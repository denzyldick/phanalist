Impossible Assertion

Reports assertions that can never hold on any feasible path.

Try in Playground All rules GitHub

Reports assertions that can never hold on any feasible path.

Why it matters

An assertion that is always false indicates contradictory logic, an incorrect assumption, or a bug in the surrounding control flow. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to detect provably impossible assertions.

Bad example

<?php
function f(int $i): void
{
    assert($i > 0 && $i < 0); // impossible
}

Good example

<?php
function f(int $i): void
{
    assert($i >= 0);
}

What it checks

  • Assertions whose condition is unsatisfiable on every feasible path
  • Assertions narrowed by earlier branches, isset(), and short-circuit conditions
  • assert() calls with modelable boolean conditions
  • Unknown assertion conditions are treated as assumptions, not failures

Model limits

E0042 shares the model limits, loop bounds, and interprocedural behavior described in E0031. It reports an assertion only when the assertion provably can never hold; it does not report an assertion merely because its condition is unknown.

How to fix

  • Revisit the assertion condition and the assumptions leading to it.
  • Fix the control flow or data assumptions that make the assertion impossible.
  • Replace overly strong assertions with conditions that reflect the actual invariant.
