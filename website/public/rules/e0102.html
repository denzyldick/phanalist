E0102 security critical

Command Injection via proc_open

Passing user input to `proc_open()` as part of a command can allow an attacker to execute arbitrary shell commands on your server.

Try in Playground All rules GitHub

Passing user input to proc_open() as part of a command can allow an attacker to execute arbitrary shell commands on your server.

Why it matters

Command injection via proc_open() can:

  • Run arbitrary system commands
  • Read or modify files and databases
  • Install malware or backdoors
  • Achieve full server compromise

Bad example

$cmd = $_GET['cmd'] ?? '';
$descriptors = [0 => ['pipe', 'r'], 1 => ['pipe', 'w'], 2 => ['pipe', 'w']];
$process = proc_open($cmd, $descriptors, $pipes);

An attacker can send ?cmd=ls; cat /etc/passwd, causing the server to execute both commands.

Good example

$cmd = $_GET['cmd'] ?? '';
$allowed = ['ls', 'whoami', 'date'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$process = proc_open(escapeshellcmd($cmd), $descriptors, $pipes);

What it checks

  • proc_open() calls where the command string contains tainted input
  • proc_open() with user-controlled command arguments without escapeshellarg()

When it does not report

  • proc_open() with literal commands or validated input
  • escapeshellarg() / escapeshellcmd() sanitization is recognized

How to fix

  1. Never pass user input directly to proc_open().
  2. Validate commands against an allowlist.
  3. Use escapeshellarg() for all user-controlled arguments.
  4. Prefer PHP-native functions over shell commands.

Configuration

E0102 is enabled by default and has no configuration options.

Taint engine

This rule is backed by the phanalist taint engine. Instead of guessing whether a variable contains user input, the engine tracks taint from sources to sinks.

  • TaintMode::Only (default): Reports only when a proven taint flow from a source (for example $_GET, $_POST, superglobals, or request parameters) reaches the sink.
  • TaintMode::Annotate: Reports all findings and adds the proven source origin.
  • TaintMode::Off: Retains legacy heuristic behavior through taint_support::looks_dynamic for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort, CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent of line numbers.
