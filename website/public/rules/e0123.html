E0123 security critical

XSS via echo

Outputting user-controlled input directly with `echo`, `print`, or similar constructs without escaping can allow cross-site scripting (XSS).

Try in Playground All rules GitHub

Outputting user-controlled input directly with echo, print, or similar constructs without escaping can allow cross-site scripting (XSS).

Why it matters

XSS vulnerabilities can:

  • Steal session cookies and authentication tokens
  • Perform actions on behalf of another user
  • Alter page content
  • Redirect users to malicious sites

Bad example

$name = $_GET['name'] ?? '';
echo "Hello, $name";
// ?name=<script>stealCookies()</script>

Good example

$name = $_GET['name'] ?? '';
echo "Hello, " . htmlspecialchars($name, ENT_QUOTES, 'UTF-8');

What it checks

  • echo, print, printf(), vprintf() with tainted input
  • <?= $var ?> short echo tags with unescaped variables

When it does not report

  • htmlspecialchars() or htmlentities() escaping is recognized
  • Output in non-HTML contexts (such as JSON or CLI) may be flagged conservatively

How to fix

  1. Escape output with htmlspecialchars() for HTML contexts.
  2. Use ENT_QUOTES | ENT_SUBSTITUTE flags.
  3. Use a templating engine with auto-escaping (such as Twig or Blade) when possible.
  4. Avoid echoing user input directly.

Configuration

E0123 is enabled by default and has no configuration options.
