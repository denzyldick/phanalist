E0065 security critical

NoSQL injection

This rule reports NoSQL query calls where user-controlled input reaches the query argument. In NoSQL systems, attacker-controlled operators or structures can change query behavior.

This rule reports NoSQL query calls where user-controlled input reaches the query argument. In NoSQL systems, attacker-controlled operators or structures can change query behavior.

Why it matters

NoSQL injection can bypass authentication, expose unintended records, or modify or delete data depending on the query and database permissions.

Bad example

$username = $_GET['user'] ?? '';
$collection->findOne(['username' => $username]);

If user input is passed through as an array or object containing query operators, the query meaning can change.

Good example

$username = (string)($_GET['user'] ?? '');
$collection->findOne(['username' => $username]);

Casting or validating input to the expected type helps ensure user data is treated as a value, not a query structure.

What it checks

  • MongoDB/PHPLIB-style method calls such as insertOne, insertMany, updateOne, updateMany, replaceOne, deleteOne, deleteMany, findOne, find, aggregate, countDocuments, distinct, and createClient
  • Functions such as mongo_insert, mongo_update, and mongo_find
  • Cases where user-controlled input reaches these calls, based on taint analysis and dynamic-expression heuristics

When it does not report

  • Queries built only from static or trusted data
  • Cases where input is sanitized, typed, or constrained in ways the model recognizes
  • Cases where the taint or heuristic model cannot prove the input reaches the call

How to fix

  • Cast or validate user input to the expected scalar type before using it in queries.
  • Avoid passing raw request arrays directly into database query filters.
  • Use query builders or APIs that safely separate query structure from user values.

Configuration

E0065 is enabled by default. The taint-aware behavior is controlled by a per-rule taint_mode setting:

rules:
  E0065:
    taint_mode: annotate
  • annotate (default) reports the finding and adds the proven source origin to the message.
  • only reports only findings reached by proven tainted data.
  • off keeps the legacy heuristic-only behavior.
