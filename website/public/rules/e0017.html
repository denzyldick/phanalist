Coupling Between Objects (CBO)

Coupling Between Objects (CBO) counts how many distinct external classes a class depends on.

Try in Playground All rules GitHub

Coupling Between Objects (CBO) counts how many distinct external classes a class depends on.

Why it matters

Highly coupled classes are more sensitive to changes elsewhere in the codebase. Reducing coupling can make classes easier to test, reuse, and modify independently.

How it works

The rule counts distinct external classes referenced by a class, including cases such as:

  1. Extending or implementing a class/interface.
  2. Using a class as a property type, parameter type, or return type.
  3. Instantiating a class with new.
  4. Calling static methods like Logger::info().
  5. Catching a class as an exception.

If the score exceeds the configured max_coupling, the rule reports a violation.

Bad example

// Depends on many external classes.
class OrderService extends BaseService implements AuditableService
{
    private UserRepository $users;
    private PaymentGateway $payments;
    private Mailer $mailer;

    public function __construct(Logger $logger, EventBus $events) {}

    public function refund(Order $order): RefundReceipt
    {
        if ($order instanceof PaidOrder) {
            StripeRefund::create($order);
        }

        try {
            return new RefundReceipt();
        } catch (GatewayException $exception) {
            throw new CannotRefundOrder();
        }
    }
}

Good example

class RefundService
{
    public function __construct(
        private PaymentGateway $payments,
        private RefundReceiptFactory $receipts,
    ) {}

    public function refund(Order $order): RefundReceipt
    {
        $this->payments->refund($order);
        return $this->receipts->createFor($order);
    }
}

How to fix

  • Split responsibilities into smaller, focused classes.
  • Depend on fewer collaborators.
  • Pass simple data where appropriate instead of introducing additional object dependencies.

Configuration
