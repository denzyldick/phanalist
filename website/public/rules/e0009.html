Cyclomatic complexity

Cyclomatic complexity measures how many independent execution paths exist through a method.

Cyclomatic complexity measures how many independent execution paths exist through a method.

Why it matters

Methods with many branches are harder to read, test, and change safely. A high score usually means the method is making too many decisions in one place.

How it is calculated

The rule starts at 1 and adds 1 for each branching construct:

  • if or elseif
  • each case in a switch
  • loops such as for, foreach, and while
  • catch blocks

If the score exceeds the configured max_complexity, the rule reports a violation.

Bad example

public function getChapter(int $number, Character $character): bool {
    if ($number > 0) {                 // +1 path
        switch ($number) {
            case 1:                    // +1 path
            case 2:                    // +1 path
                if ($character->isAlive()) { // +1 path
                    return true;
                }
                break;
        }
        if ($character->hasSword()) {  // +1 path
            if ($character->isStrong()) { // +1 path
                return true;
            }
        }
    }
    return false;
}

Good example

public function getChapter(int $number, Character $character): bool {
    if ($number <= 0) {
        return false;
    }

    if ($this->isEarlyChapter($number) && $character->isAlive()) {
        return true;
    }

    return $character->hasSword() && $character->isStrong();
}

private function isEarlyChapter(int $number): bool {
    return $number === 1 || $number === 2;
}

How to fix

  • Extract complex conditions into smaller, well-named methods.
  • Return early to reduce nesting.
  • Split large methods into smaller units with focused responsibilities.

Configuration

rules:
  E0009:
    max_complexity: 10
