Instability, Abstractness, and Distance from Main Sequence

Reports namespace-level coupling metrics when they exceed configured thresholds: Instability (I), Abstractness (A), and Distance from Main Sequence (D).

Try in Playground All rules GitHub

Reports namespace-level coupling metrics when they exceed configured thresholds: Instability (I), Abstractness (A), and Distance from Main Sequence (D).

Why it matters

These metrics help evaluate whether a namespace has a healthy balance between stability and abstraction.

  • Stable, abstract namespaces (for example, shared interfaces) are easier to depend on safely.
  • Unstable, concrete namespaces (for example, implementation details) are easier to change when few other parts depend on them.
  • Namespaces far from this balance can be hard to change or provide little practical value.

Bad example

<?php
namespace App\Service;

class PaymentService
{
    public function __construct(
        private \App\Repository\OrderRepository $orders,
        private \App\Repository\UserRepository $users,
        private \App\Gateway\StripeGateway $stripe,
    ) {}
}

Good example

<?php
namespace App\Service;

interface PaymentGateway
{
    public function charge(int $amount): void;
}

class PaymentService
{
    public function __construct(private PaymentGateway $gateway) {}
}

What it checks

For each namespace, Phanalist computes:

  • Instability (I) = Ce / (Ca + Ce)
    • Ce (efferent coupling): number of external types this namespace depends on.
    • Ca (afferent coupling): number of classes outside this namespace that depend on classes in this namespace.
    • Higher I means the namespace depends on many others relative to how many depend on it.
  • Abstractness (A) = abstract / total
    • abstract: number of abstract classes and interfaces in the namespace.
    • total: total number of classes in the namespace.
  • Distance from Main Sequence (D) = |A + I - 1|
    • Lower values are closer to the ideal balance.

The rule reports:

  • E0023:instability when I > max_instability and Ca + Ce > 0.
  • E0023:abstractness when A > max_abstractness and total > 0.
  • E0023:distance when D > max_distance and both instability and abstractness are computable.

When it does not report

  • Instability is not reported when Ca + Ce == 0 (no coupling to compute).
  • Abstractness and distance are not reported when total == 0.
  • Distance is only evaluated when coupling exists (Ca + Ce > 0) and the namespace has classes.

How to fix

  • High instability: reduce outgoing dependencies, or move volatile dependencies behind stable abstractions.
  • High abstractness: ensure abstractions have concrete implementations and real usage; avoid interfaces with no consumers.
  • High distance: rebalance the namespace. If many parts depend on it, prefer stable abstractions. If few parts depend on it, concrete implementations are usually appropriate.

Configuration

rules:
  E0023:
    max_instability: 0.8
    max_abstractness: 0.8
    max_distance: 0.5
