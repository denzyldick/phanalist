E0096 security minor

Cookie Without Secure Flag

Setting a cookie without the `Secure` flag allows it to be sent over unencrypted HTTP, where it can be intercepted by network attackers.

Try in Playground All rules GitHub

Setting a cookie without the Secure flag allows it to be sent over unencrypted HTTP, where it can be intercepted by network attackers.

Why it matters

Without the Secure flag:

  • Session cookies can be stolen via network sniffing
  • Attackers on the same network can capture cookies
  • Authentication tokens are exposed in transit

Bad example

setcookie('session_id', $value, [
    'secure' => false,   // sent over HTTP
    'httponly' => true,
]);

Good example

setcookie('session_id', $value, [
    'secure' => true,    // HTTPS only
    'httponly' => true,  // not accessible via JavaScript
    'samesite' => 'Lax',
]);

What it checks

  • setcookie() or setrawcookie() calls where secure is not set to true
  • session_set_cookie_params() with secure => false

When it does not report

  • Cookies explicitly marked secure => true
  • Server-level session.cookie_secure ini settings are not detected

How to fix

  1. Set secure => true on cookies containing sensitive data.
  2. Use session.cookie_secure = 1 in php.ini.
  3. Serve the site over HTTPS only.

Configuration

E0096 is enabled by default and has no configuration options.
