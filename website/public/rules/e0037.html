String Offset Out of Bounds

Reports string offsets that can be out of bounds.

Try in Playground All rules GitHub

Reports string offsets that can be out of bounds.

Why it matters

Accessing a string offset outside its valid range can produce warnings and unexpected values. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to detect feasible out-of-bounds string accesses.

Bad example

<?php
function lastChar(string $s): string
{
    return $s[strlen($s)]; // off by one
}

Good example

<?php
function lastChar(string $s): string
{
    if ($s === '') {
        return '';
    }

    return $s[strlen($s) - 1];
}

What it checks

  • Negative and out-of-bounds string offsets
  • Literal strings and documented non-empty-string values
  • Lengths derived from strlen(), str_repeat() with a literal repetition count, substr() using PHP's offset and length rules, str_split() using a literal chunk size, and str_pad() with a literal non-empty pad string
  • Symbolic offsets and guards in branches and short-circuit conditions
  • Offsets that cannot be modeled report unverified under unknown_policy: report

Model limits

E0037 shares the model limits, loop bounds, and interprocedural behavior described in E0031.

How to fix

  • Check string length before accessing an offset.
  • Guard offsets with isset($str[$i]) or explicit bounds checks.
  • Normalize or validate computed offsets before use.
