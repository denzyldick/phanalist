E0125 security major

Open redirect via header

Redirecting users with `header("Location: ...")` to a URL taken from user input without validation can create an open redirect vulnerability.

Redirecting users with header("Location: ...") to a URL taken from user input without validation can create an open redirect vulnerability.

Why it matters

Open redirects can be abused for:

  • Phishing, by making malicious links appear to come from a trusted domain
  • Bypassing expectations around post-login redirects
  • Redirecting users to sites that attempt to steal credentials or deliver malicious content

Bad example

$url = $_GET['url'] ?? '';
header("Location: $url");
exit;

Good example

$url = $_GET['url'] ?? '';
$allowed = ['/dashboard', '/profile', '/login'];
if (!in_array($url, $allowed, true)) {
    $url = '/dashboard';
}
header("Location: $url");
exit;

What it checks

  • header("Location: ...") with tainted input
  • header("refresh: ...;url=...") with tainted input

When it does not report

  • Whitelist validation using in_array() with strict mode is recognized
  • Relative paths starting with / may still be flagged conservatively unless whitelisted

How to fix

  1. Use an allowlist of permitted redirect destinations.
  2. Validate that redirect targets are relative and same-origin when possible.
  3. Avoid redirecting directly to user-supplied URLs.

Configuration

E0125 is enabled by default and has no configuration options.
