E0091 security major

Source code exposure via highlight_file

Using `highlight_file()`, `show_source()`, or `highlight_string()` in production code can expose PHP source code, including credentials and application logic, to anyone who can access that page.

Using highlight_file(), show_source(), or highlight_string() in production code can expose PHP source code, including credentials and application logic, to anyone who can access that page.

Why it matters

Source code disclosure can expose:

  • Database credentials and API keys
  • Business logic and application flow
  • Other vulnerabilities in the codebase
  • Third-party library versions

Bad example

if ($_GET['debug'] === '1') {
    highlight_file(__FILE__); // exposes entire file source
}
show_source('config.php'); // exposes config file including DB credentials

Good example

// Remove source-highlighting functions from production code.
// If debugging is needed, use a local development environment.

What it checks

  • highlight_file(), show_source(), and highlight_string() calls
  • Especially risky when gated by user input ($_GET['debug'])

When it does not report

  • highlight_string() with a literal safe string may be intentional but is flagged conservatively
  • The rule cannot determine whether the call is protected by authentication or authorization

How to fix

  1. Remove highlight_file() and show_source() from production code.
  2. Do not expose source code via HTTP.
  3. Use a local IDE or php -S for development debugging.

Configuration

E0091 is enabled by default and has no configuration options.
