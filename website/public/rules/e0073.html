E0073 security major

Weak cryptographic hash

Hashing passwords with weak, fast algorithms such as MD5 or SHA1 is unsafe. Use a dedicated password hashing function such as `password_hash()`.

Hashing passwords with weak, fast algorithms such as MD5 or SHA1 is unsafe. Use a dedicated password hashing function such as password_hash().

Why it matters

MD5 and SHA1 are designed for speed, not password storage. Attackers can:

  • Crack password hashes quickly using rainbow tables or GPU brute force
  • Recover common passwords in a short time
  • Compromise many user accounts if hashes are exposed

Bad example

$hash = md5($password);   // weak and fast
$hash = sha1($password);  // weak and fast

Good example

$hash = password_hash($password, PASSWORD_DEFAULT);
// Uses bcrypt or argon2 with automatic salting and cost factor
if (password_verify($password, $hash)) {
    // valid
}

What it checks

  • md5(), sha1(), hash('md5', ...), and hash('sha1', ...) applied to password-like variables
  • crypt() without a proper salt or cost parameter

When it does not report

  • password_hash() and password_verify() are recognized as safe
  • Hashing non-password data (such as file checksums or data integrity checks) may be flagged conservatively

How to fix

  1. Use password_hash() with PASSWORD_DEFAULT for password storage.
  2. Verify passwords with password_verify().
  3. Do not use MD5, SHA1, or plain hash() for password storage.

Configuration

E0073 is enabled by default and has no configuration options.
