Unchecked json_decode result

`json_decode()` returns `null` when the JSON is invalid. If the result is immediately accessed as an object or array, PHP may produce a warning, exception, or "property on null" error.

json_decode() returns null when the JSON is invalid. If the result is immediately accessed as an object or array, PHP may produce a warning, exception, or "property on null" error.

Why it matters

Malformed input from a request body, file, or external API can cause a runtime failure instead of a clear validation or error-handling path.

Bad example

return json_decode($json)->name;
return json_decode($json, true)[0];

Good example

$data = json_decode($json, true, flags: JSON_THROW_ON_ERROR);

return $data['name'];

JSON_THROW_ON_ERROR makes invalid JSON throw a JsonException that you can catch. If you prefer not to use exceptions, check the result before reading it:

$data = json_decode($json, true);
if (!is_array($data)) {
    return null;
}

return $data['name'] ?? null;

What it checks

  • json_decode($json)->property
  • json_decode($json)->method()
  • json_decode($json)[$key]

It also accepts direct accesses guarded by ??, isset(), or empty(), and calls that use JSON_THROW_ON_ERROR in a positional or named flags argument.

When it does not report

  • The access is guarded by ??, isset(), or empty().
  • The call uses JSON_THROW_ON_ERROR.
  • The decoded value is assigned to a variable first. The rule only checks direct access, so it does not report this even when the variable is not checked.
  • The null check happens inside a helper function or custom wrapper.

How to fix

  • Use JSON_THROW_ON_ERROR and catch JsonException.
  • Check is_array() or is_object() before reading the result.
  • Use ?? or isset() for optional keys.
  • Consider decoding into a typed DTO or validating the structure before using it.

Configuration

E0052 has no configuration options and is enabled by default.
