E0079 security major

Dynamic method call

Invoking a method using a method name that comes from user input can allow an attacker to call unintended methods on your objects.

Try in Playground All rules GitHub

Invoking a method using a method name that comes from user input can allow an attacker to call unintended methods on your objects.

Why it matters

Dynamic method invocation can:

  • Reach unintended business logic or internal methods
  • Bypass access controls on sensitive operations
  • Execute dangerous methods with attacker-controlled arguments

Bad example

$method = $_GET['method'] ?? '';
$obj->$method();

An attacker can send ?method=deleteAllData, causing the application to call that method.

Good example

$method = $_GET['method'] ?? '';
$allowed = ['getData', 'save', 'view'];
if (!in_array($method, $allowed, true)) {
    http_response_code(400);
    exit;
}
$obj->$method();

What it checks

  • $obj->$method() where $method is a variable from user input
  • $obj->{$method}() with a tainted method name
  • call_user_func([$obj, $method]) with a tainted method name

When it does not report

  • Cases where the method name is validated against a whitelist before invocation
  • Static method calls are not flagged

How to fix

  1. Use a whitelist of allowed method names.
  2. Use a command or action pattern instead of dynamic dispatch.
  3. Do not pass user input directly as a method name.

Configuration

E0079 is enabled by default and has no configuration options.
