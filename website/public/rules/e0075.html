E0075 security major

Session security

Calling `session_start()` without secure cookie settings can leave session IDs vulnerable to interception and theft.

Try in Playground All rules GitHub

Calling session_start() without secure cookie settings can leave session IDs vulnerable to interception and theft.

Why it matters

Insecure session configuration can allow attackers to:

  • Steal session cookies over unencrypted HTTP
  • Access session data via JavaScript in an XSS attack
  • Fixate session IDs before authentication
  • Hijack authenticated user sessions

Bad example

session_set_cookie_params([
    'secure' => false,    // sent over HTTP
    'httponly' => false,  // accessible via JavaScript
]);
session_start();

Good example

session_set_cookie_params([
    'lifetime' => 3600,
    'path' => '/',
    'secure' => true,      // HTTPS only
    'httponly' => true,    // not accessible via JavaScript
    'samesite' => 'Lax',   // prevent cross-site leakage
]);
ini_set('session.use_strict_mode', '1');
session_start();

What it checks

  • session_start() without prior session_set_cookie_params() setting secure => true and httponly => true
  • ini_set('session.cookie_secure', '0') or ini_set('session.cookie_httponly', '0')
  • session.use_trans_sid = 1 (session ID in URL)

When it does not report

  • CLI scripts where session cookies do not apply
  • Secure cookie parameters set via .htaccess or web server configuration (not detectable statically)

How to fix

  1. Set session.cookie_secure = 1 so cookies are sent only over HTTPS.
  2. Set session.cookie_httponly = 1 so cookies are not accessible via JavaScript.
  3. Set session.cookie_samesite = Lax or Strict.
  4. Set session.use_only_cookies = 1 so session IDs are not placed in URLs.
  5. Set session.use_strict_mode = 1 to reject uninitialized session IDs.

Configuration

E0075 is enabled by default and has no configuration options.
