Unreachable Code

Reports statements that cannot be reached.

Try in Playground All rules GitHub

Reports statements that cannot be reached.

Why it matters

Unreachable code often indicates a logic error, dead branch, or leftover code after a control-flow change. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to identify statements that cannot be executed on feasible paths.

Bad example

<?php
function f(): int
{
    return 1;
    echo "never"; // unreachable
}

Good example

<?php
function f(): int
{
    echo "before return";
    return 1;
}

What it checks

  • Statements after return, break, continue, throw, or exit
  • Numbered break and continue levels
  • continue inside switch
  • Unreachable statements after never-returning calls
  • Conditional throws and exits that only make one branch unreachable
  • Statements after exhaustive switch or match constructs

Model limits

E0041 shares the model limits, loop bounds, and interprocedural behavior described in E0031. A branch that merely throws is not treated as making the whole following statement unreachable.

How to fix

  • Remove dead code, or move it before the terminating statement if it should run.
  • Rework control flow when a condition makes a branch unintentionally unreachable.
  • Check never-returning calls and exhaustive match/switch logic for unintended early exits.

Configuration

rules:
  E0041:
    php_version: "8.4"
    check_unreachable: true

See E0031 for the shared model limits, unknown_policy behavior, and per-code configuration.
