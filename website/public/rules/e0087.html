E0087 security critical

Command execution with backticks

Passing user input to the backtick (shell execution) operator can allow an attacker to run arbitrary shell commands on the server.

Passing user input to the backtick (shell execution) operator can allow an attacker to run arbitrary shell commands on the server.

Why it matters

Command injection can lead to:

  • Reading sensitive files (such as /etc/passwd, source code, or credentials)
  • Modifying or deleting data
  • Installing malware or backdoors
  • Full server compromise

Bad example

$ip = $_GET['ip'] ?? '';
$output = `ping -c 4 $ip`;

An attacker can send ?ip=8.8.8.8; cat /etc/passwd, causing the server to execute both commands.

Good example

$ip = $_GET['ip'] ?? '';
if (!filter_var($ip, FILTER_VALIDATE_IP)) {
    http_response_code(400);
    exit;
}
$output = shell_exec('ping -c 4 ' . escapeshellarg($ip));

What it checks

  • Backtick operator (`$cmd`) with tainted input
  • shell_exec(), exec(), system(), and passthru() with tainted input (also covered by E0127-E0131)

When it does not report

  • Backticks with literal strings or trusted internal variables
  • escapeshellarg() or escapeshellcmd() sanitization is recognized

How to fix

  1. Do not pass user input to shell execution functions.
  2. Validate input strictly (for example, FILTER_VALIDATE_IP for IP addresses).
  3. Use escapeshellarg() for any user-controlled arguments.
  4. Prefer PHP-native functions over shell commands when possible.

Configuration

E0087 is enabled by default and has no configuration options.
