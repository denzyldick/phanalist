E0060 security critical

SQL injection

This rule reports SQL query calls where user-controlled input is included in the query string. An attacker may be able to change the meaning of the query by supplying crafted input.

This rule reports SQL query calls where user-controlled input is included in the query string. An attacker may be able to change the meaning of the query by supplying crafted input.

Why it matters

SQL injection can expose, modify, or delete data, bypass authentication, or lead to broader system compromise depending on database permissions and application behavior.

Bad example

$id = $_GET['id'] ?? '';
$result = mysqli_query($conn, "SELECT * FROM users WHERE id = $id");

An attacker can visit ?id=1 OR 1=1, which changes the query to:

SELECT * FROM users WHERE id = 1 OR 1=1

Good example

$id = $_GET['id'] ?? '';
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
$user = $stmt->fetch();

Prepared statements keep user input as data instead of executable SQL.

What it checks

  • SQL execution calls such as mysqli_query(), mysqli_real_query(), mysqli_multi_query(), mysql_query(), pg_query(), pg_exec(), pg_send_query(), sqlite_query(), and sqlite_exec()
  • Method calls named query, exec, real_query, or multi_query
  • Cases where user-controlled input reaches the SQL argument, based on taint analysis and dynamic-expression heuristics

When it does not report

  • Prepared statements with bound parameters, such as $pdo->prepare("... WHERE id = ?")
  • Static SQL queries with no user-controlled input
  • Cases where the taint or heuristic model cannot prove the input reaches the query

How to fix

  • Use prepared statements with bound parameters instead of concatenating input into SQL strings.
  • Validate or cast input as an additional safeguard when a specific type is expected.
  • Keep SQL structure fixed and pass user values as parameters.
// Bad
$query = "SELECT * FROM users WHERE id = " . $_GET['id'];

// Good
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$_GET['id']]);

Configuration

E0060 is enabled by default. The taint-aware behavior is controlled by a per-rule taint_mode setting:

rules:
  E0060:
    taint_mode: annotate
  • annotate (default) reports the finding and adds the proven source origin to the message.
  • only reports only findings reached by proven tainted data.
  • off keeps the legacy heuristic-only behavior.
