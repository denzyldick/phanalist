E0117 security critical

SQL injection via query string

Building SQL queries by concatenating query string input (`$_GET`) can allow SQL injection.

Building SQL queries by concatenating query string input ($_GET) can allow SQL injection.

Why it matters

SQL injection through query string parameters is risky because:

  • Query parameters are easy to modify and share in URLs
  • Attacks can be automated with simple URL manipulation
  • Search and filter endpoints are common targets

Bad example

$id = $_GET['id'] ?? '';
$result = mysqli_query($conn, "SELECT * FROM users WHERE id = $id");

An attacker can visit ?id=1 OR 1=1, causing the query to return more rows than intended.

Good example

$id = $_GET['id'] ?? '';
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
$user = $stmt->fetch();

What it checks

  • mysqli_query(), PDO::query(), pg_query() with SQL strings containing $_GET variables
  • SQL queries built by string concatenation with query string input

When it does not report

  • Prepared statements using ? or :name placeholders
  • Input cast to safe types (for example, (int)$_GET['id'])
  • Query string parameters validated against a whitelist

How to fix

  1. Do not concatenate $_GET values into SQL strings.
  2. Use prepared statements with parameter binding.
  3. Cast query string input to the expected type when appropriate (for example, (int) for IDs).

Configuration

E0117 is enabled by default and has no configuration options.
