Cognitive complexity

Cognitive complexity estimates how difficult code is to understand by accounting for control flow, nesting, and logical operators.

Cognitive complexity estimates how difficult code is to understand by accounting for control flow, nesting, and logical operators.

Why it matters

Code that is deeply nested or contains many branching conditions takes more effort to read and maintain. Reducing cognitive complexity usually makes behavior easier to follow and safer to modify.

How it is calculated

  • Each decision point adds to the score, such as if, while, for, and foreach.
  • Nesting increases the cost of nested decisions.
  • Logical operators such as && and || add additional complexity.

If the score exceeds the configured max_complexity, the rule reports a violation.

Bad example (high complexity)

public function checkAccess($user, $job) {
    if ($user->isLoggedIn()) {          // +1
        if ($user->hasPermission()) {   // +2 (nested)
            if ($job->isActive()) {     // +3 (deeply nested)
                return true;
            }
        }
    }
    return false;
}

Good example (lower complexity)

public function checkAccess($user, $job) {
    if (!$user->isLoggedIn()) return false;    // +1
    if (!$user->hasPermission()) return false; // +1 (not nested)
    if (!$job->isActive()) return false;       // +1 (not nested)

    return true;
}

How to fix

  • Use early returns to reduce nesting.
  • Extract complex conditions into well-named helper methods.
  • Simplify boolean expressions where possible.
