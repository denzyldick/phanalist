E0078 security major

Variable variables

Using `extract()` on user-controlled arrays or using variable variables (`$$x`) with tainted names can allow an attacker to overwrite internal variables.

Using extract() on user-controlled arrays or using variable variables ($$x) with tainted names can allow an attacker to overwrite internal variables.

Why it matters

Variable variables and extract() can:

  • Overwrite internal variables such as $is_admin, $auth, or $user
  • Bypass access controls by injecting unexpected variables
  • Lead to remote code execution when combined with dynamic function calls

Bad example

extract($_GET); // attacker sends ?is_admin=1
if ($is_admin) {
    grantAdminAccess();
}

Good example

// Access request data explicitly through superglobals
$username = $_GET['username'] ?? null;
$is_admin = checkUserRole($username); // server-side check, never from request

What it checks

  • extract() with $_GET, $_POST, $_REQUEST, $_COOKIE, or other tainted arrays
  • $$var variable variables where $var originates from user input

When it does not report

  • extract($trustedArray, EXTR_SKIP) with a non-user-controlled array
  • EXTR_PREFIX_ALL or EXTR_PREFIX_IF_EXISTS flags are used (they add a prefix, reducing collision risk)

How to fix

  1. Do not call extract() on user-controlled input.
  2. Access $_GET, $_POST, $_REQUEST, and $_COOKIE explicitly.
  3. Use filter_input() for validated input retrieval where appropriate.

Configuration

E0078 is enabled by default and has no configuration options.
