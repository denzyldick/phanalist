E0113 security major

Session Regeneration Missing

Calling `session_start()` and writing session data after authentication without calling `session_regenerate_id()` can leave the application vulnerable to session fixation attacks.

Calling session_start() and writing session data after authentication without calling session_regenerate_id() can leave the application vulnerable to session fixation attacks.

Why it matters

Session fixation allows an attacker to:

  • Authenticate using a session ID they chose
  • Hijack the session after the victim logs in
  • Access the victim's authenticated account

Bad example

session_start();
// Verify credentials...
$_SESSION['user_id'] = $user->id;
// No session_regenerate_id() after login

An attacker can send the victim a link with a pre-set session ID. When the victim logs in, the attacker uses that same session ID to access the account.

Good example

session_start();
// Verify credentials...
$_SESSION['user_id'] = $user->id;
session_regenerate_id(true); // Fixation protection

What it checks

  • session_start() followed by $_SESSION writes without a subsequent session_regenerate_id()
  • Login/auth endpoints that set session data without regenerating the ID

When it does not report

  • Session state cannot be tracked across multiple files (heuristic limitation)
  • session_regenerate_id() called before session_start() may not be detected

How to fix

  1. Call session_regenerate_id(true) immediately after authentication succeeds.
  2. Set session.use_strict_mode = 1 in php.ini.
  3. Regenerate the session ID on privilege changes (for example user to admin).

Configuration

E0113 is enabled by default and has no configuration options.
