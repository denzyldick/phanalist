E0077 security minor

Display errors enabled

Enabling `display_errors` via `ini_set()` or similar causes PHP errors to be rendered in the browser, which can expose stack traces, file paths, and variable values.

Enabling display_errors via ini_set() or similar causes PHP errors to be rendered in the browser, which can expose stack traces, file paths, and variable values.

Why it matters

Error messages shown to users can expose:

  • File paths and directory structure
  • Database structure and SQL queries
  • Sensitive variable contents
  • Information that helps attackers understand the application

Bad example

ini_set('display_errors', '1');
ini_set('error_reporting', 'E_ALL');

Good example

ini_set('display_errors', '0');
ini_set('log_errors', '1');
ini_set('error_log', '/var/log/app_errors.log');
// In production: display_errors = Off, log_errors = On

What it checks

  • ini_set('display_errors', '1') or ini_set('display_errors', 'true')
  • error_reporting(E_ALL) without display_errors = Off
  • .htaccess or .user.ini directives enabling display_errors

When it does not report

  • php.ini or .htaccess settings cannot be fully read from static analysis; the rule only detects inline ini_set() patterns it can see
  • display_errors = 1 behind if (getenv('APP_ENV') === 'development') may still be flagged

How to fix

  1. Set display_errors = Off in production.
  2. Set log_errors = On and write logs to a secure path outside the web root.
  3. Review errors in log files rather than browser output.

Configuration

E0077 is enabled by default and has no configuration options.
