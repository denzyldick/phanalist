E0080 security critical

Weak cryptographic function

Using `crypt()` for password hashing, or using it with weak parameters, is unsafe. Use a modern password hashing function such as `password_hash()`.

Using crypt() for password hashing, or using it with weak parameters, is unsafe. Use a modern password hashing function such as password_hash().

Why it matters

crypt() with weak parameters (such as DES-based crypt) is vulnerable to:

  • Fast brute-force attacks due to limited key space
  • Rainbow table attacks when no salt or a weak salt is used
  • Outdated behavior compared to bcrypt or Argon2 used by password_hash()

Bad example

$hash = crypt($password, '$1$saltsalt$'); // MD5-based crypt, weak
$hash = crypt($password);                   // uses system default, may be weak

Good example

$hash = password_hash($password, PASSWORD_DEFAULT);
// Uses bcrypt or argon2 with automatic salt and cost factor
if (password_verify($password, $hash)) {
    // valid
}

What it checks

  • crypt() calls used for password hashing
  • crypt() without a proper salt parameter

When it does not report

  • password_hash() and password_verify() are recognized as safe
  • crypt() used for non-password purposes (such as file integrity) may be flagged conservatively

How to fix

  1. Replace crypt() with password_hash() for password storage.
  2. Use password_verify() for password verification.
  3. Do not implement a custom password hashing scheme.

Configuration

E0080 is enabled by default and has no configuration options.
