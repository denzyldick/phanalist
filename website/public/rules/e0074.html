E0074 security major

Weak random number generator

Generating security-sensitive values (such as tokens, keys, salts, or CSRF tokens) with `rand()` or `mt_rand()` is unsafe because these functions are not cryptographically secure.

Generating security-sensitive values (such as tokens, keys, salts, or CSRF tokens) with rand() or mt_rand() is unsafe because these functions are not cryptographically secure.

Why it matters

rand() and mt_rand() use weak pseudorandom number generators. Attackers may be able to:

  • Predict future random values from prior outputs
  • Guess session tokens, CSRF tokens, or password reset tokens
  • Bypass authentication or authorization

Bad example

$token = bin2hex(mt_rand(100000, 999999)); // predictable
$key = rand(1000, 9999);                    // easily brute-forced

Good example

$token = bin2hex(random_bytes(16));  // cryptographically secure
$key = random_int(1000, 9999);       // cryptographically secure

What it checks

  • rand(), mt_rand(), and uniqid() used for security-sensitive purposes (tokens, keys, salts)
  • mt_rand() without seeding from a secure source

When it does not report

  • random_bytes() and random_int() are recognized as safe
  • rand() used for non-security purposes (such as game logic or display shuffling) may be flagged conservatively

How to fix

  1. Use random_bytes() for tokens and keys.
  2. Use random_int() for numeric security values.
  3. Do not use rand(), mt_rand(), or uniqid() for security purposes.

Configuration

E0074 is enabled by default and has no configuration options.
