# E0067: Mail Injection

**In plain English:** Your code takes input from a user and puts it into the `mail()` function's headers or subject line without sanitization. An attacker can inject extra email headers (BCC, CC, From) to turn your contact form into a spam relay.

**Why it matters:** Mail injection:
- Turns your contact form into a spam relay
- Allows email spoofing (appears to come from your domain)
- Can get your server's IP blacklisted for spam
- Can expose your internal network structure

## Bad

```php
$email = $_GET['email'] ?? '';
mail('admin@example.com', 'Contact', $body, "From: $email");
```

If an attacker sends: `?email=attacker@evil.com%0d%0aBcc: victim@example.com`, your mail sends with an extra BCC header.

## Good

```php
$email = filter_var($_GET['email'] ?? '', FILTER_VALIDATE_EMAIL);
if ($email === false) {
    http_response_code(400);
    exit;
}
mail('admin@example.com', 'Contact', $body, "From: $email");
```

## What the rule checks

- `mail()` with `$additional_headers` or `$subject` built from tainted input
- `mb_send_mail()` with tainted headers

## When it does not report

- `filter_var($email, FILTER_VALIDATE_EMAIL)` is recognized as sanitization
- `str_replace(["\r", "\n"], "", $input)` is recognized

## How to fix

1. Validate email addresses with `filter_var($email, FILTER_VALIDATE_EMAIL)`
2. Strip newlines from header values: `str_replace(["\r", "\n"], "", $input)`
3. Use a mail library (SwiftMailer, PHPMailer) that sanitizes headers automatically

## Configuration

E0067 is enabled by default and has no configuration options.

Very common in contact forms. Easy to demonstrate and fix.
