# E0087: String-to-Number Comparison

**In plain English:** Comparing a string to a number with loose comparison triggers PHP's string-to-number coercion. `"1e2" == 100` is true because PHP interprets `"1e2"` as scientific notation (1 × 10² = 100). `"0admin" == 0` is also true because PHP converts the string starting with digits to the number 0.

**Why it matters:** Attackers can craft strings that coerce to unexpected numeric values, bypassing checks like `if ($version == 2)`.

## Bad

```php
if ($_GET['version'] == 2) { // "2e0" == 2 is true; "2admin" == 2 is true
    enableFeature();
}
if ($status == 200) { // "200ok" == 200 is true
    proceed();
}
```

## Good

```php
if ((string)$_GET['version'] === '2') {
    enableFeature();
}
if (is_int($status) && $status === 200) {
    proceed();
}
```

## What the rule checks

- `==` comparisons between a string-tainted variable and an integer/float literal
- `switch($string)` with integer cases (also covered by E0089)

## When it does not report

- Related to E0086 (loose comparison) — E0087 focuses specifically on string-to-number coercion
- `(int)` / `(float)` casts before comparison are recognized as safe

## How to fix

1. Cast to string before comparing: `(string)$input === '2'`
2. Use strict type checks: `is_int($input) && $input === 2`
3. Use `filter_var()` with validation filters

## Configuration

E0087 is enabled by default and has no configuration options.
