# E0087: Command execution with backticks

**In plain English:** User input is passed to the backtick (shell execution) operator, allowing an attacker to run arbitrary shell commands on your server.

**Why it matters:** Command injection can lead to:
- Reading sensitive files (`/etc/passwd`, source code, credentials)
- Modifying or deleting data
- Installing malware or backdoors
- Full server compromise

## Bad

```php
$ip = $_GET['ip'] ?? '';
$output = `ping -c 4 $ip`;
```

An attacker sends: `?ip=8.8.8.8; cat /etc/passwd` and your server executes both commands.

## Good

```php
$ip = $_GET['ip'] ?? '';
if (!filter_var($ip, FILTER_VALIDATE_IP)) {
    http_response_code(400);
    exit;
}
$output = shell_exec('ping -c 4 ' . escapeshellarg($ip));
```

## What the rule checks

- Backtick operator (`` `$cmd` ``) with tainted input
- `shell_exec()`, `exec()`, `system()`, `passthru()` with tainted input (also covered by E0127-E0131)

## When it does not report

- Backticks with literal strings or trusted internal variables
- `escapeshellarg()` or `escapeshellcmd()` sanitization is recognized

## How to fix

1. Never pass user input to shell execution functions
2. Validate input strictly (e.g., `FILTER_VALIDATE_IP` for IP addresses)
3. Use `escapeshellarg()` for any user-controlled arguments
4. Prefer PHP-native functions over shell commands

## Configuration

E0087 is enabled by default and has no configuration options.
