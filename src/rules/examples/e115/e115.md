# E0115: XXE via libxml

**In plain English:** Iterating over all `$_GET` / `$_POST` / `$_REQUEST` keys without limit allows an attacker to send thousands of parameters, causing CPU/memory exhaustion.

**Why it matters:** An attacker can send 10,000+ GET parameters to force the application to process all of them, consuming resources.

## Bad

```php
foreach ($_GET as $key => $value) {
    process($key, $value); // attacker sends 10000+ parameters
}
// or
foreach ($_POST as $key => $value) {
    $db->insert('logs', ['key' => $key, 'value' => $value]);
}
```

## Good

```php
$allowed = ['page', 'limit', 'sort'];
foreach ($_GET as $key => $value) {
    if (!in_array($key, $allowed, true)) {
        continue;
    }
    process($key, $value);
}
// or limit count:
if (count($_GET) > 50) {
    http_response_code(400);
    exit;
}
```

## What the rule checks

- `foreach ($_GET as ...)`, `foreach ($_POST as ...)`, `foreach ($_REQUEST as ...)` without whitelist or count limit
- `array_keys($_GET)`, `array_values($_GET)` used in loops

## When it does not report

- `foreach ($_GET as $k => $v)` with `count()` check before loop is recognized
- Whitelist validation inside loop is recognized

## How to fix

1. Whitelist allowed keys before iterating
2. Add `count($_GET) > MAX` guard
3. Process only expected parameters

## Configuration

E0115 is enabled by default. Configuration options:

```yaml
rules:
  E0115:
    max_params: 50
    superglobals:
      - _GET
      - _POST
      - _REQUEST
      - _COOKIE
```
