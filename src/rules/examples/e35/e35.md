# E0035: Missing Array Key

Reports reads of keys that are missing from tracked literal arrays.

## Why it matters

Accessing a missing array key can produce warnings/notices and lead to unexpected `null` values. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to find feasible paths where a key read is missing.

## Bad example

```php
<?php
/** @param array{name: string} $user */
function greet(array $user): string
{
    return $user['email']; // key may be missing
}
```

## Good example

```php
<?php
/** @param array{name: string, email?: string} $user */
function greet(array $user): string
{
    $email = $user['email'] ?? 'unknown';

    return $email;
}
```

## What it checks

- Missing string and integer keys in tracked literal arrays
- Keys returned by `array_key_first()` and `array_key_last()` for tracked literal arrays, preserving PHP insertion order
- Nested literal array shapes
- Reads guarded by `isset()` and `??`
- Arrays forgotten after writes through untracked paths or by-reference calls
- Keys checked through bounded branches and short-circuit conditions

## Model limits

E0035 shares the model limits, loop bounds, and interprocedural behavior described in [E0031](../e31/e31.md). It reports missing keys, not list bounds; use [E0036](../e36/e36.md) for out-of-bounds list indexes.

## How to fix

- Ensure the key exists before reading it, or use `isset()`, `array_key_exists()`, or `??`.
- Initialize required keys when constructing the array.
- Refactor code so array shape is explicit and consistent on all paths.

## Configuration

```yaml
rules:
  E0035:
    php_version: "8.4"
    check_array_index: true
```

See [E0031](../e31/e31.md) for the shared model limits, `unknown_policy` behavior, and per-code configuration.
