# E0080: Predictable Temp Files

**In plain English:** Your code creates temporary files with predictable names using `tempnam()`. An attacker can guess the filename and create a symlink at that location before your code does, leading to a symlink attack.

**Why it matters:** Predictable temp files allow:
- Symlink attacks (attacker creates symlink at predictable path)
- TOCTOU vulnerabilities (time-of-check-time-of-use)
- Overwriting files the attacker shouldn't have access to

## Bad

```php
$tmp = tempnam('/tmp', 'upload_');
// /tmp/upload_XXXX is guessable
file_put_contents($tmp, $_FILES['file']['tmp_name']);
```

## Good

```php
$tmp = tempnam(sys_get_temp_dir(), bin2hex(random_bytes(8)));
// unpredictable name
file_put_contents($tmp, $_FILES['file']['tmp_name']);
chmod($tmp, 0600);
```

## What the rule checks

- `tempnam()` calls with predictable prefixes or in predictable directories (`/tmp`, `/var/tmp`)
- `tmpfile()` is generally safe (unnamed, auto-deleted)

## When it does not report

- `random_bytes()` or `uniqid('', true)` in prefix is recognized as better
- Cannot verify actual filesystem permissions

## How to fix

1. Use unpredictable prefixes:
   ```php
   $prefix = bin2hex(random_bytes(8));
   $tmp = tempnam(sys_get_temp_dir(), $prefix);
   ```
2. Set restrictive permissions: `chmod($tmp, 0600)`
3. Consider `tmpfile()` for auto-cleanup

## Configuration

E0080 is enabled by default and has no configuration options.

## Related CVE / blog angle

TOCTOU / symlink race. Advanced topic for security blogs.
