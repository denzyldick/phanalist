# E0080: Weak cryptographic function

**In plain English:** Passwords are hashed using `crypt()` instead of a modern password hashing function, or `crypt()` is used with weak parameters.

**Why it matters:** `crypt()` with weak parameters (like DES-based crypt) is vulnerable to:
- Fast brute-force attacks due to limited key space
- Rainbow table attacks if no salt or weak salt is used
- Being outdated compared to bcrypt/argon2 used by `password_hash()`

## Bad

```php
$hash = crypt($password, '$1$saltsalt$'); // MD5-based crypt, weak
$hash = crypt($password);                   // uses system default, may be weak
```

## Good

```php
$hash = password_hash($password, PASSWORD_DEFAULT);
// Uses bcrypt or argon2 with automatic salt and cost factor
if (password_verify($password, $hash)) {
    // valid
}
```

## What the rule checks

- `crypt()` calls used for password hashing
- `crypt()` without a proper salt parameter

## When it does not report

- `password_hash()` / `password_verify()` are recognized as safe
- `crypt()` used for non-password purposes (file integrity, etc.) may be flagged conservatively

## How to fix

1. Replace `crypt()` with `password_hash()` for password storage
2. Use `password_verify()` for verification
3. Never roll your own password hashing scheme

## Configuration

E0080 is enabled by default and has no configuration options.
