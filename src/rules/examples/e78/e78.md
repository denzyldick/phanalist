# E0078: Variable variables

**In plain English:** `extract()` imports variables from user-controlled arrays into the symbol table, or variable variables (`$$x`) are used with tainted names, allowing an attacker to overwrite internal variables.

**Why it matters:** Variable variables and `extract()` can:
- Overwrite internal variables like `$is_admin`, `$auth`, or `$user`
- Bypass access controls by injecting unexpected variables
- Lead to remote code execution if combined with dynamic function calls

## Bad

```php
extract($_GET); // attacker sends ?is_admin=1
if ($is_admin) {
    grantAdminAccess();
}
```

## Good

```php
// Access request data explicitly through superglobals
$username = $_GET['username'] ?? null;
$is_admin = checkUserRole($username); // server-side check, never from request
```

## What the rule checks

- `extract()` with `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, or other tainted arrays
- `$$var` variable variables where `$var` originates from user input

## When it does not report

- `extract($trustedArray, EXTR_SKIP)` with a non-user-controlled array
- `EXTR_PREFIX_ALL` or `EXTR_PREFIX_IF_EXISTS` flags used (adds prefix, reducing collision risk)

## How to fix

1. Never call `extract()` on user-controlled input
2. Access `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE` explicitly
3. Use `filter_input()` for validated input retrieval

## Configuration

E0078 is enabled by default and has no configuration options.
