# E0078: Variable variables

**In plain English:** Your code passes user input to PHP stream functions like `file_get_contents()` or `fopen()` without restricting what kind of URL scheme can be used. PHP supports stream wrappers like `data://`, `zip://`, `expect://`, `phar://` that can do more than just read files.

**Why it matters:** Stream wrappers can turn innocent file reads into:
- Code execution (`data://` with base64-encoded PHP)
- Reading unexpected resources (`php://input`, `php://filter`)
- Accessing compressed files (`zip://`)

## Bad

```php
$data = $_GET['data'] ?? '';
$result = file_get_contents($data);
```

An attacker sends: `?data=data://text/base64,PD9waHAgcGhwaW5mbygpOz8+` which decodes to `<?php phpinfo(); ?>`.

## Good

```php
$url = filter_var($data, FILTER_VALIDATE_URL);
if ($url === false || !in_array(parse_url($url, PHP_URL_SCHEME), ['http', 'https'], true)) {
    http_response_code(400);
    exit;
}
$result = file_get_contents($url);
```

## What the rule checks

- `file_get_contents()`, `file()`, `fopen()`, `readfile()`, `copy()` with tainted input that may contain stream wrapper schemes (`data://`, `zip://`, `expect://`, `phar://`, `glob://`, `ftp://`)

## When it does not report

- `filter_var()` with `FILTER_VALIDATE_URL` is recognized as sanitization
- Whitelist of allowed schemes is recognized

## How to fix

1. Validate URLs with `filter_var(FILTER_VALIDATE_URL)`
2. Restrict to `http://` and `https://` schemes
3. Never pass raw user input to stream functions

## Configuration

E0078 is enabled by default. Configuration options:

```yaml
rules:
  E0078:
    allowed_schemes:
      - http
      - https
    block_schemes:
      - data
      - zip
      - expect
      - phar
      - glob
      - ftp
```
