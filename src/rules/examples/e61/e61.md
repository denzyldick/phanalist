# E0061: Cross-Site Scripting (XSS)

This rule reports output of user-controlled data to HTML without appropriate escaping. If an attacker can inject markup or script content, it may execute in another user's browser.

## Why it matters

XSS can expose session data, perform actions as the affected user, redirect users, or modify page content.

## Bad example

```php
echo "Welcome, " . $_GET['name'];
```

If an attacker visits `?name=<script>alert('hacked')</script>`, the page outputs:

```html
Welcome, <script>alert('hacked')</script>
```

The browser treats that as executable script.

## Good example

```php
echo "Welcome, " . htmlspecialchars($_GET['name'] ?? '', ENT_QUOTES, 'UTF-8');
```

`htmlspecialchars()` converts special characters so the browser treats the value as text, not markup or script.

## What it checks

- `echo` statements and short echo tags
- `print()`, `printf()`, and `vprintf()` calls
- Cases where user-controlled input reaches HTML output, based on taint analysis and dynamic-expression heuristics

## When it does not report

- Output that has been escaped with `htmlspecialchars()`, `htmlentities()`, or equivalent sanitization recognized by the analysis
- Static text with no user-controlled input
- Cases where the taint or heuristic model cannot prove the input reaches output

## How to fix

- Escape data at output time for the target context. For HTML, use `htmlspecialchars()` with `ENT_QUOTES` and `'UTF-8'`.
- Prefer template engines with auto-escaping where appropriate.
- Avoid building HTML by concatenating untrusted input.

```php
echo htmlspecialchars($userInput, ENT_QUOTES, 'UTF-8');
```

## Configuration

E0061 is enabled by default. The taint-aware behavior is controlled by a per-rule `taint_mode` setting:

```yaml
rules:
  E0061:
    taint_mode: annotate
```

- `annotate` (default) reports the finding and adds the proven source origin to the message.
- `only` reports only findings reached by proven tainted data.
- `off` keeps the legacy heuristic-only behavior.
