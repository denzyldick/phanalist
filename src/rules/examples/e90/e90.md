# E0090: File write to user-controlled path

**In plain English:** User input is used to determine a file path for writing, allowing an attacker to write files to arbitrary locations on your server.

**Why it matters:** Arbitrary file write can:
- Overwrite critical system or application files
- Drop a web shell for remote code execution
- Modify configuration files to weaken security

## Bad

```php
$filename = $_GET['file'] ?? '';
$content = $_GET['content'] ?? '';
file_put_contents("/var/www/files/$filename", $content);
```

An attacker sends `?file=../../../var/www/shell.php&content=<?php system($_GET['cmd']); ?>` and gains code execution.

## Good

```php
$filename = $_GET['file'] ?? '';
$allowed = ['profile.txt', 'settings.txt'];
if (!in_array($filename, $allowed, true)) {
    http_response_code(400);
    exit;
}
file_put_contents("/var/www/files/$filename", $content);
```

## What the rule checks

- `file_put_contents()`, `file()`, `fopen()` with `'w'`, `'w+'`, `'a'`, `'a+'` modes where the path is built from user-controlled input
- `file_get_contents()` used with write contexts (stream contexts)

## When it does not report

- Whitelist validation of filenames before writing
- Paths resolved to a fixed directory with `realpath()` verification

## How to fix

1. Never write to paths based directly on user input
2. Use a whitelist of allowed filenames
3. Store user-writable files in a dedicated directory outside the web root
4. Validate and sanitize all path components

## Configuration

E0090 is enabled by default and has no configuration options.
