# E0094: Dynamic Method Call

**In plain English:** Your code calls a method on an object using a method name from user input. An attacker can invoke arbitrary methods on objects, potentially reaching dangerous business logic or internal methods.

**Why it matters:** Dynamic method calls can:
- Reach unintended business logic
- Invoke dangerous internal methods
- Bypass access controls

## Bad

```php
$method = $_GET['method'] ?? '';
$obj->$method();
```

## Good

```php
$method = $_GET['method'] ?? '';
$allowed = ['getData', 'save', 'delete'];
if (!in_array($method, $allowed, true)) {
    http_response_code(400);
    exit;
}
$obj->$method();
```

## What the rule checks

- `$obj->$method()` where `$method` is a variable
- `$obj->{$method}()` where `$method` is a variable
- `call_user_func([$obj, $method])` with tainted method name

## When it does not report

- Whitelist validation is recognized
- Static method calls are not flagged

## How to fix

1. Use a whitelist of allowed methods
2. Use a command/action pattern instead of dynamic dispatch

## Configuration

E0094 is enabled by default and has no configuration options.
