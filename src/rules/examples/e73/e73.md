# E0073: Weak cryptographic hash

**In plain English:** Your PHP session settings are insecure. Session cookies might be sent over unencrypted HTTP, accessible to JavaScript, or sent in URLs. Weak hash functions make session IDs predictable.

**Why it matters:** Weak session config enables:
- Session hijacking (stealing session IDs via network sniffing or JavaScript)
- Session fixation
- Session ID leakage via URLs in Referer headers

## Bad

```php
session_set_cookie_params([
    'secure' => false,  // sent over HTTP
    'httponly' => false, // accessible via JavaScript
]);
ini_set('session.hash_function', 'md5'); // weak hash
```

## Good

```php
session_set_cookie_params([
    'lifetime' => 3600,
    'path' => '/',
    'domain' => 'example.com',
    'secure' => true,
    'httponly' => true,
    'samesite' => 'Lax',
]);
ini_set('session.use_strict_mode', '1');
ini_set('session.hash_function', 'sha256');
```

## What the rule checks

- `session_set_cookie_params()` with `secure => false` or `httponly => false`
- `ini_set('session.use_only_cookies', '0')`
- `session.hash_function = md5` or `sha1`
- `session.use_trans_sid = 1` (session ID in URL)
- `session.cookie_domain` set to broad domains (`.example.com`)

## When it does not report

- Cannot detect web server-level session config (only inline `ini_set()` calls)

## How to fix

1. `session.cookie_secure = 1` (only send over HTTPS)
2. `session.cookie_httponly = 1` (not accessible via JavaScript)
3. `session.use_only_cookies = 1` (don't put session ID in URLs)
4. `session.use_strict_mode = 1` (reject uninitialized session IDs)
5. `session.cookie_samesite = Lax` (prevent cross-site request leakage)
6. `session.hash_function = sha256` (stronger hash)

## Configuration

E0073 is enabled by default and has no configuration options.
