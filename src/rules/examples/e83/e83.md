# E0083: Open redirect

**In plain English:** Your code uses outdated or broken symmetric ciphers like DES, 3DES, RC4, or Blowfish for encryption. These ciphers have known practical attacks and should not be used.

**Why it matters:** Weak ciphers can be broken by attackers:
- DES: Broken in hours with modern hardware
- RC4: Numerous biases allow plaintext recovery
- 3DES: Vulnerable to meet-in-the-middle attacks
- Blowfish: Vulnerable to birthday attacks on small blocks

## Bad

```php
$encrypted = openssl_encrypt($data, 'des-ecb', $key);
$encrypted = openssl_encrypt($data, 'rc4', $key);
$encrypted = mcrypt_encrypt(MCRYPT_3DES, $key, $data, MCRYPT_MODE_CBC);
```

## Good

```php
$encrypted = openssl_encrypt($data, 'aes-256-gcm', $key, 0, $iv);
```

## What the rule checks

- `openssl_encrypt()` / `openssl_decrypt()` with cipher names containing `des`, `3des`, `tripledes`, `rc4`, `blowfish`, `bf-`
- `mcrypt_encrypt()` with `MCRYPT_DES`, `MCRYPT_3DES`, `MCRYPT_RC4`, `MCRYPT_BLOWFISH`

## When it does not report

- Only checks symmetric ciphers — asymmetric (RSA, etc.) not covered here
- AES-128 is not flagged (still considered acceptable in many contexts)

## How to fix

1. Use AES-256-GCM or AES-256-CBC with HMAC
2. For password hashing, use `password_hash()` (bcrypt/argon2), not encryption

## Configuration

E0083 is enabled by default. Configuration options:

```yaml
rules:
  E0083:
    weak_ciphers:
      - des
      - 3des
      - tripledes
      - rc4
      - blowfish
      - bf-
```
