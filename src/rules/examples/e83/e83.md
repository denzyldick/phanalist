# E0083: Open redirect

Redirecting users to a URL supplied in the request without validating where it goes can allow attackers to craft phishing links that appear to come from your domain.

## Why it matters

Open redirect vulnerabilities are commonly used in:

- **Phishing campaigns**: users trust your domain and click the link
- **Bypassing SSO protections**: redirecting after login to a malicious site
- **Credential harvesting**: the malicious site mimics a trusted page

## Bad example

```php
$url = $_GET['redirect'] ?? '';
header("Location: $url");
exit;
```

An attacker can create a link like `https://yoursite.com/redirect.php?url=http://evil.com/login`. Users may trust your domain but be redirected to `evil.com`.

## Good example

```php
$url = $_GET['redirect'] ?? '';
$allowed = ['/dashboard', '/profile', '/login'];
if (!in_array($url, $allowed, true)) {
    $url = '/dashboard';
}
header("Location: $url");
exit;
```

## What it checks

- `header("Location: ...")` with tainted input
- `header("refresh: ...;url=...")` with tainted input

## When it does not report

- Whitelist validation using `in_array()` with strict mode is recognized
- Relative paths starting with `/` may be flagged conservatively unless whitelisted

## How to fix

1. Use a whitelist of allowed redirect paths.
2. Validate that URLs are relative and same-origin.
3. Do not redirect to user-supplied URLs directly.

## Configuration

E0083 is enabled by default and has no configuration options.
