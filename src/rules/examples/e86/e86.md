# E0086: Deprecated session function

**In plain English:** PHP's `==` and `!=` operators perform type juggling before comparing values. This can lead to surprising matches such as `"0e1234" == 0` being true, or `"admin" == 0` being true when the left side is a string starting with digits.

**Why it matters:** Loose comparison is a classic PHP authentication bypass vector. Attackers can craft input that passes type-juggled equality checks, gaining unauthorized access.

## Bad

```php
if ($_GET['role'] == 'admin') {
    grantAdminAccess();
}
if ($token == $expected_token) {
    allowAccess();
}
if ($status != 200) {
    showError();
}
```

## Good

```php
if ($_GET['role'] === 'admin') {
    grantAdminAccess();
}
if (hash_equals($token, $expected_token)) {
    allowAccess();
}
if ($status !== 200) {
    showError();
}
```

## What the rule checks

- `==` and `!=` binary comparison expressions anywhere in the code
- Both operands of loose comparisons

## When it does not report

- `===` and `!==` strict comparisons
- Comparisons of literal values with no type-juggling risk

## How to fix

1. Replace `==` with `===` and `!=` with `!==`
2. Use `hash_equals()` for comparing secrets (tokens, passwords, signatures)
3. Use `str_contains()`, `str_starts_with()`, `str_ends_with()` for string checks

## Configuration

E0086 is enabled by default and has no configuration options.
