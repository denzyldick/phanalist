# E0131: Command execution via proc_open

Passing untrusted input to `proc_open()` as part of a command can allow an attacker to execute arbitrary shell commands on the server.

## Why it matters

Command injection through `proc_open()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Lead to full server compromise

## Bad example

```php
$cmd = $_GET['cmd'] ?? '';
$descriptors = [0 => ['pipe', 'r'], 1 => ['pipe', 'w'], 2 => ['pipe', 'w']];
$process = proc_open($cmd, $descriptors, $pipes);
```

An attacker can send `?cmd=ls; cat /etc/passwd`, causing the server to execute both commands.

## Good example

```php
// Avoid proc_open() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['ls', 'whoami', 'date'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$process = proc_open(escapeshellcmd($cmd), $descriptors, $pipes);
```

## What it checks

- `proc_open()` calls where the command string contains tainted input
- `proc_open()` calls with user-controlled command arguments without `escapeshellarg()` or `escapeshellcmd()`

## When it does not report

- `proc_open()` with literal commands or validated input
- Cases where `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Do not pass user input directly to `proc_open()`.
2. Prefer PHP-native functions instead of shell commands.
3. If a shell command is required, validate it against an allowlist and escape all arguments.

## Configuration

E0131 is enabled by default and has no configuration options.
