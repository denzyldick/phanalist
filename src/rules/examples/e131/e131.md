# E0131: Command execution via proc_open

**In plain English:** `ORDER BY` and `LIMIT` clauses are hard to parameterize with prepared statements, so they are often concatenated directly. An attacker can inject SQL here.

**Why it matters:** Even when other queries use prepared statements, `ORDER BY` and `LIMIT` are common injection points.

## Bad

```php
$order = $_GET['order'] ?? '';
$result = $pdo->query("SELECT * FROM products ORDER BY $order");
$limit = $_GET['limit'] ?? '';
$result = $pdo->query("SELECT * FROM products LIMIT $limit");
```

## Good

```php
$order = $_GET['order'] ?? '';
$allowed = ['price', 'name', 'date'];
if (!in_array($order, $allowed, true)) {
    $order = 'price';
}
$result = $pdo->query("SELECT * FROM products ORDER BY $order");

$limit = (int)($_GET['limit'] ?? 10);
$result = $pdo->query("SELECT * FROM products LIMIT $limit");
```

## What the rule checks

- SQL strings with `ORDER BY` or `LIMIT` followed by tainted variable interpolation
- Whitelist validation is recognized

## When it does not report

- Prepared statement placeholders for ORDER BY/LIMIT are not supported by PDO/MySQLi — whitelist or casting is required

## How to fix

1. Whitelist allowed column names for ORDER BY
2. Cast LIMIT to `(int)`
3. Use a query builder that handles these safely

## Configuration

E0131 is enabled by default and has no configuration options.
