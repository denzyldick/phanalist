# E0131: Command execution via proc_open

**In plain English:** User input is passed to `proc_open()` as part of a command, allowing an attacker to execute arbitrary shell commands on your server.

**Why it matters:** Command injection via `proc_open()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Achieve full server compromise

## Bad

```php
$cmd = $_GET['cmd'] ?? '';
$descriptors = [0 => ['pipe', 'r'], 1 => ['pipe', 'w'], 2 => ['pipe', 'w']];
$process = proc_open($cmd, $descriptors, $pipes);
```

An attacker sends: `?cmd=ls; cat /etc/passwd` and your server executes both commands.

## Good

```php
// Avoid proc_open() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['ls', 'whoami', 'date'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$process = proc_open(escapeshellcmd($cmd), $descriptors, $pipes);
```

## What the rule checks

- `proc_open()` calls where the command string contains tainted input
- `proc_open()` with user-controlled command arguments without `escapeshellarg()` or `escapeshellcmd()`

## When it does not report

- `proc_open()` with literal commands or validated input
- `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Never pass user input directly to `proc_open()`
2. Use PHP-native functions instead of shell commands
3. If you must run a command, validate against a whitelist and escape all arguments

## Configuration

E0131 is enabled by default and has no configuration options.
