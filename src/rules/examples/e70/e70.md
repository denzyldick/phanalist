# E0070: IDOR (Insecure Direct Object Reference)

**In plain English:** Your application lets users access database records by supplying an ID (like `/profile?id=123`), but doesn't check if the user actually owns that record. An attacker can change the ID number to see or edit someone else's data.

**Why it matters:** IDOR lets users:
- View other users' private data (profiles, messages, orders)
- Modify other users' data
- Delete other users' records

## Bad

```php
$userId = $_GET['id'] ?? '';
$profile = $db->query("SELECT * FROM profiles WHERE user_id = $userId")->fetch();
echo $profile->email;
```

An attacker changes `?id=123` to `?id=124` and sees someone else's profile.

## Good

```php
$userId = $_GET['id'] ?? '';
$profile = $db->query("SELECT * FROM profiles WHERE user_id = ? AND owner_id = ?", [$userId, $currentUser->id])->fetch();
if (!$profile) {
    http_response_code(403);
    exit;
}
echo $profile->email;
```

## What the rule checks

- Database queries where a user-supplied ID is used directly without ownership verification
- `find($id)` or `findOrFail($id)` (Eloquent) without scope/ownership check

## When it does not report

- Queries that scope by current user (`WHERE owner_id = ? AND id = ?`)
- UUIDs instead of sequential IDs (harder to guess)

## How to fix

1. Always scope queries by the current user:
   ```php
   WHERE owner_id = ? AND id = ?
   ```
2. Use UUIDs instead of sequential IDs to prevent guessing
3. Check authorization at the service layer, not just the controller

## Configuration

E0070 is enabled by default and has no configuration options.
