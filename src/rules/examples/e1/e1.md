# E0001: Opening Tag Position

**In plain English:** The PHP opening tag (`<?php`) should always be placed on the very first line of the file, starting at column 1.

**Why it matters:** If there is any whitespace, blank lines, or HTML output before `<?php`, PHP will immediately send headers and output to the browser. This can cause unexpected whitespace in JSON/API responses, "Headers already sent" warnings, or break redirects and cookies.

## ❌ The Bad Example
```php

<?php
// There is an empty blank line before the opening tag!
echo "Hello World";
```

## ✅ The Good Example
```php
<?php
declare(strict_types=1);

namespace App;

echo "Hello World";
```
*(Note: Shebang lines like `#!/usr/bin/env php` for CLI scripts are allowed on the very first line before `<?php`).*

## What the rule checks
- Ensures `<?php` or `<?=` is on line 1 of the file.
- Ensures the opening tag starts at column 1 (no leading indentation/spaces).
- Automatically allows Unix shebang (`#!...`) lines in CLI scripts on line 1.

## When it does not report
- When the opening tag is on line 1, column 1.
- When a valid shebang line is on line 1 and the opening tag follows on line 2.

## How to fix
- Remove any leading blank lines, spaces, or BOM characters before the `<?php` tag.

## Configuration
E0001 has no configuration options and is enabled by default.
