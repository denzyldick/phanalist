# E0001: Opening tag position

The PHP opening tag (`<?php` or `<?=`) should be on the first line of the file, starting at column 1.

## Why it matters

If there is any whitespace, blank lines, or output before `<?php`, PHP may send headers and output to the browser earlier than expected. This can cause unexpected whitespace in JSON or API responses, "Headers already sent" warnings, or broken redirects and cookies.

## Bad example

```php

<?php
// There is an empty blank line before the opening tag.
echo "Hello World";
```

## Good example

```php
<?php
declare(strict_types=1);

namespace App;

echo "Hello World";
```

Shebang lines like `#!/usr/bin/env php` are allowed on the first line in CLI scripts, with the PHP opening tag on the next line.

## What it checks

- The PHP opening tag is on line 1.
- The opening tag starts at column 1 (no leading indentation or spaces).
- CLI scripts may use a Unix shebang (`#!...`) on line 1 before the opening tag.

## When it does not report

- When the opening tag is on line 1, column 1.
- When a valid shebang line is on line 1 and the opening tag follows on line 2.

## How to fix

Remove any leading blank lines, spaces, or BOM characters before the `<?php` tag.

## Configuration

E0001 has no configuration options and is enabled by default.
