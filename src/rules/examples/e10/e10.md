# E0010: NPath complexity

NPath complexity counts the number of distinct execution paths through a method. Unlike cyclomatic complexity, consecutive branches multiply the number of possible paths.

## Why it matters

When branches stack on top of each other, the number of possible execution paths can grow quickly. A high NPath score makes a method difficult to reason about and thoroughly test.

## How it is calculated

The rule counts distinct paths through a method. For example, four independent `if/else` statements in sequence produce `2 × 2 × 2 × 2 = 16` possible paths.

If the score exceeds the configured `max_paths`, the rule reports a violation.

## Bad example

```php
public function labyrinth(string $weather, bool $hasUmbrella, bool $isTired): string {
    $plan = '';

    // 2 paths
    if ($weather === 'rain') {
        $plan .= 'wear coat; ';
    } else {
        $plan .= 'wear t-shirt; ';
    }

    // 2 paths (total so far: 2 x 2 = 4)
    if ($hasUmbrella) {
        $plan .= 'take umbrella; ';
    } else {
        $plan .= 'run fast; ';
    }

    // 2 paths (total: 4 x 2 = 8)
    if ($isTired) {
        $plan .= 'walk slowly; ';
    } else {
        $plan .= 'skip; ';
    }

    return $plan;
}
```

## Good example

```php
public function getPlan(string $weather, bool $hasUmbrella, bool $isTired): string {
    return sprintf(
        '%s; %s; %s;',
        $this->getClothing($weather),
        $this->getRainGear($hasUmbrella),
        $this->getPace($isTired)
    );
}
// Each helper method has a smaller NPath, reducing total complexity.
```

## How to fix

- Extract stacked conditionals into smaller helper methods.
- Use lookups, maps, or polymorphism where they fit the problem.
- Keep each method focused on a single decision.

## Configuration

```yaml
rules:
  E0010:
    max_paths: 200
```
