# E0093: Dynamic Class Instantiation

**In plain English:** Your code instantiates a class using a name from user input. An attacker can instantiate any autoloadable class, which combined with gadget chains can lead to object injection and remote code execution.

**Why it matters:** Combined with gadget chains, dynamic class instantiation can:
- Instantiate any autoloadable class
- Trigger object injection via magic methods
- Lead to remote code execution

## Bad

```php
$class = $_GET['class'] ?? '';
$obj = new $class();
```

## Good

```php
$class = $_GET['class'] ?? '';
$allowed = ['User', 'Product', 'Order'];
if (!in_array($class, $allowed, true)) {
    http_response_code(400);
    exit;
}
$obj = new $class();
```

## What the rule checks

- `new $class()` where `$class` comes from superglobal array access
- `ReflectionClass::newInstanceArgs()` with tainted class name

## When it does not report

- Whitelist-validated class names
- Static class names

## How to fix

1. Use a whitelist of allowed class names
2. Use a factory pattern instead of dynamic instantiation

## Configuration

E0093 is enabled by default and has no configuration options.
