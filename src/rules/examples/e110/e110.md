# E0110: Raw SQL query execution

**In plain English:** Raw SQL queries are executed without using prepared statements or parameter binding, making the application vulnerable to SQL injection.

**Why it matters:** Raw SQL execution with user input can lead to:
- Data theft (emails, passwords, credit cards)
- Authentication bypass
- Data modification or deletion
- Full server compromise

## Bad

```php
$id = $_GET['id'] ?? '';
$result = $pdo->query("SELECT * FROM users WHERE id = $id");
```

## Good

```php
$id = $_GET['id'] ?? '';
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
$user = $stmt->fetch();
```

## What the rule checks

- `PDO::query()`, `mysqli_query()`, `pg_query()` with SQL strings containing interpolated variables
- SQL queries built by string concatenation with user input

## When it does not report

- `PDO::prepare()` with `?` or `:name` placeholders
- Static SQL queries with no user input
- Input validated against a whitelist or cast to safe types

## How to fix

1. Always use prepared statements with parameter binding
2. Never concatenate variables into SQL strings
3. Validate and sanitize input as a second line of defense

## Configuration

E0110 is enabled by default and has no configuration options.
