# E0110: XML Bomb / Billion Laughs

**In plain English:** XML parsers expand entity references recursively. An attacker can define 10 entities that each expand 10x, consuming gigabytes of memory (billion laughs attack).

**Why it matters:** XML bombs cause denial of service through:
- Memory exhaustion
- CPU consumption
- Server crash

## Bad

```php
$xml = $_GET['xml'] ?? '';
$doc = new DOMDocument();
$doc->loadXML($xml); // no entity expansion limit
// <!DOCTYPE lolz [ <!ENTITY lol "lol"> ... ]>
```

## Good

```php
libxml_disable_entity_loader(true);
$doc = new DOMDocument();
$doc->loadXML($xml);
```

## What the rule checks

- XML parsing functions (`simplexml_load_string`, `DOMDocument::loadXML`, `xml_parse()`) with tainted input and no entity loader disabled
- No entity expansion limit configured

## When it does not report

- `libxml_disable_entity_loader(true)` is recognized as mitigation
- Cannot determine actual entity expansion behavior without parsing

## How to fix

1. Call `libxml_disable_entity_loader(true)` before parsing
2. Set memory limits (`memory_limit`) as a backstop
3. Use JSON instead of XML for user-supplied data
4. Validate XML size before parsing

## Configuration

E0110 is enabled by default and has no configuration options.

## Related CVE / blog angle

XML DoS. Good for showing denial-of-service vectors in data parsing.
