# E0039: Property Access on Null

Reports property reads on values that can be null.

## Why it matters

Reading a property on `null` causes a fatal runtime error. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to detect feasible paths where the receiver can be null.

## Bad example

```php
<?php
function id(?User $user): int
{
    return $user->id; // $user may be null
}
```

## Good example

```php
<?php
function id(?User $user): int
{
    if ($user === null) {
        return 0;
    }

    return $user->id;
}
```

## What it checks

- Property reads on null and nullable values
- Nullness narrowed by `if`, `switch`, `match`, `isset()`, and short-circuit conditions
- Nullsafe property access (`?->`) is treated as safe
- PHPDoc parameter, `@var`, and return contracts
- Constant-return, identity, and method summaries

## Model limits

E0039 shares the model limits, loop bounds, and interprocedural behavior described in [E0031](../e31/e31.md).

## How to fix

- Check for null before accessing properties.
- Use nullsafe operator `?->` when a null result is acceptable.
- Refactor code so nullable values are handled explicitly at boundaries.

## Configuration

```yaml
rules:
  E0039:
    php_version: "8.4"
    check_nullability: true
```

See [E0031](../e31/e31.md) for the shared model limits, `unknown_policy` behavior, and per-code configuration.
