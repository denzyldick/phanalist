# E0076: Information disclosure

**In plain English:** Your application stores uploaded files in a directory that the web server serves (like `public/uploads/` or `www/uploads/`). Even if you check file extensions, an uploaded file in the web root can be accessed directly via URL or executed if the check is bypassed.

**Why it matters:** An uploaded file in the web root can be:
- Accessed directly via URL
- Executed by the web server if it's a PHP file
- Used to pivot to further attacks

## Bad

```php
move_uploaded_file($tmp, '/var/www/html/uploads/' . $filename);
// accessible at https://yoursite.com/uploads/shell.php
```

## Good

```php
move_uploaded_file($tmp, '/var/www/protected_uploads/' . $filename);
// not accessible via URL; serve via PHP readfile() with auth check
```

## What the rule checks

- `move_uploaded_file()` or `file_put_contents()` paths containing `public/`, `www/`, `html/`, `web/`, `public_html/`, `document_root`
- Upload destinations under known web server document roots

## When it does not report

- Heuristic path matching — may miss custom directory structures
- Cannot determine actual server document root statically

## How to fix

1. Store uploads outside the web root
2. Serve files through a PHP script that checks authentication:
   ```php
   header('Content-Disposition: attachment');
   readfile('/protected/uploads/' . $filename);
   ```
3. Serve `Content-Disposition: attachment` to prevent browser execution

## Configuration

E0076 is enabled by default. Configuration options:

```yaml
rules:
  E0076:
    web_accessible_paths:
      - public
      - www
      - html
      - web
      - public_html
      - document_root
      - htdocs
```
