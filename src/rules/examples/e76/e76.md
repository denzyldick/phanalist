# E0076: Information disclosure

Leaving `phpinfo()` in committed production code exposes detailed PHP configuration, version, extensions, and environment variables to anyone who can access that page.

## Why it matters

Attackers can use `phpinfo()` output to:

- Fingerprint the server (PHP version, loaded extensions)
- Identify version-specific vulnerabilities
- Read environment variables and configuration values
- Plan targeted attacks against the infrastructure

## Bad example

```php
<?php phpinfo(); ?>
```

## Good example

```php
// Remove phpinfo() entirely from production code.
// Use it only in local development and do not commit it.
```

## What it checks

- `phpinfo()` function calls anywhere in committed source code
- `phpinfo(INFO_ALL)`, `phpinfo(INFO_GENERAL)`, and other `phpinfo()` variants

## When it does not report

- No safe usage in committed code. `phpinfo()` is always flagged.

## How to fix

1. Remove `phpinfo()` from production code.
2. Use it only in local development and do not commit it.
3. If you need it temporarily, protect it with an IP allowlist and authentication, then delete it after use.

## Configuration

E0076 is enabled by default and has no configuration options.
