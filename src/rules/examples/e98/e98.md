# E0098: Session ID in URL

**In plain English:** Session IDs are embedded in URLs via `session.use_trans_sid`, exposing them in Referer headers, browser history, and server logs.

**Why it matters:** Session IDs in URLs can:
- Be leaked via Referer headers when users click external links
- Be stored in browser history
- Be logged by web servers and proxies
- Be used for session hijacking

## Bad

```php
ini_set('session.use_trans_sid', '1');
session_start();
// Session ID appears in URLs: /page.php?PHPSESSID=abc123
```

## Good

```php
ini_set('session.use_only_cookies', '1');
ini_set('session.use_trans_sid', '0');
session_set_cookie_params([
    'secure' => true,
    'httponly' => true,
]);
session_start();
```

## What the rule checks

- `session.use_trans_sid = 1` or `ini_set('session.use_trans_sid', '1')`
- Links containing `PHPSESSID` or similar session ID parameters

## When it does not report

- `session.use_only_cookies = 1` is recognized as the safe alternative
- Cannot detect php.ini-level configuration directly

## How to fix

1. Set `session.use_only_cookies = 1` in php.ini
2. Set `session.use_trans_sid = 0`
3. Never include session IDs in URLs manually

## Configuration

E0098 is enabled by default and has no configuration options.
