# E0085: Unkeyed Hash for Integrity

**In plain English:** Your code uses `md5()` or `sha1()` (unkeyed hash) to verify data integrity without an HMAC. Without a secret key, an attacker can modify both the data and the hash, making the integrity check useless.

**Why it matters:** Without a secret key:
- Attacker modifies data and recomputes the hash
- Integrity checks are bypassed
- Data tampering goes undetected

## Bad

```php
$hash = md5($data); // attacker can modify $data and recompute md5
if (md5($received_data) === $received_hash) { // forged hash accepted
    // ...
}
```

## Good

```php
$expected = hash_hmac('sha256', $data, $secret_key);
if (hash_equals(hash_hmac('sha256', $received_data, $secret_key), $expected)) {
    // ...
}
```

## What the rule checks

- `md5()`, `sha1()`, `hash('md5', ...)`, `hash('sha1', ...)` used for integrity verification
- Comparison of unkeyed hash results where one side may be attacker-controlled

## When it does not report

- `hash_hmac()` is recognized as safe
- `password_hash()` / `password_verify()` are not flagged (they're for passwords, not integrity)
- Cannot distinguish "file checksum" from "integrity check" semantically — may flag legitimate checksums

## How to fix

1. Use `hash_hmac()` with a secret key for integrity verification
2. Use `hash_equals()` to compare the HMAC results
3. For file integrity, sign with a digital signature (RSA/ECDSA) rather than just hashing

## Configuration

E0085 is enabled by default and has no configuration options.

## Related CVE / blog angle

HMAC vs plain hash. Good for showing the difference between checksums and authenticated integrity.
