# E0085: Inline PHP execution short tags

Short echo tags (`<?= ?>`) and short open tags (`<?`) can cause portability issues. In environments where `short_open_tag` is disabled, code may break or be served as plain text.

## Why it matters

Short tags can cause:

- PHP source code to be served as plain text if `short_open_tag` is disabled
- Portability issues across different server configurations
- Confusion with XML declarations (`<?xml ... ?>`)

## Bad example

```php
<?= $userInput ?>
<?= $variable ?>
```

## Good example

```php
<?php echo $userInput; ?>
<?php echo htmlspecialchars($variable, ENT_QUOTES, 'UTF-8'); ?>
```

## What it checks

- `<?= ... ?>` short echo tags in PHP files
- `<?` short open tags (without `php`)

## When it does not report

- Files known to run on servers with `short_open_tag = On` are not distinguished by static analysis
- Server-level `php.ini` configuration cannot be detected

## How to fix

1. Replace `<?= ... ?>` with `<?php echo ...; ?>`.
2. Escape output with `htmlspecialchars()` for HTML contexts when appropriate.
3. Set `short_open_tag = Off` in `php.ini` and use full PHP tags.

## Configuration

E0085 is enabled by default and has no configuration options.
