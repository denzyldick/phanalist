# E0101: Object injection via unserialize

**In plain English:** Untrusted data is passed to `unserialize()`, which can instantiate arbitrary PHP objects and trigger magic methods, leading to object injection and potential remote code execution.

**Why it matters:** PHP object injection is a critical vulnerability. Attackers can craft serialized objects that:
- Trigger `__wakeup()`, `__destruct()`, or other magic methods
- Execute arbitrary code through gadget chains
- Read, modify, or delete files
- Achieve full server compromise

## Bad

```php
$data = $_GET['data'] ?? '';
$result = unserialize($data);
```

## Good

```php
// Use JSON instead of PHP serialization for untrusted data
$data = $_GET['json'] ?? '';
$result = json_decode($data, true);
if (json_last_error() !== JSON_ERROR_NONE) {
    http_response_code(400);
    exit;
}
```

## What the rule checks

- `unserialize()` calls where the argument may originate from `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, `php://input`
- `session_decode()` with user-controlled data

## When it does not report

- `unserialize()` on literal strings or trusted internal variables
- `unserialize()` with `['allowed_classes' => false]` to prevent object instantiation

## How to fix

1. Never pass user-controlled data to `unserialize()`
2. Use JSON (`json_decode()` / `json_encode()`) instead
3. If you must use `unserialize()`, pass `['allowed_classes' => false]`

## Configuration

E0101 is enabled by default and has no configuration options.

## Taint Engine Backed

This rule is now powered by the phanalist taint engine. Instead of guessing whether
a variable contains user input (`has_user_input` / `looks_dynamic` heuristics), the
engine performs source-to-sink taint tracking. The rule queries `SinkKind` from the
engine:

- **`TaintMode::Only`** (default): Only reports when a proven taint flow from a source
  (e.g. `$_GET`, `$_POST`, superglobals, request parameters) reaches the sink.
- **`TaintMode::Annotate`**: Reports all findings and adds the proven source origin.
- **`TaintMode::Off`**: Retains the legacy heuristic behaviour through
  `taint_support::looks_dynamic` for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort,
CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent
of line numbers.
