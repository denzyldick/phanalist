# E0034: intdiv() Overflow

Reports `intdiv()` calls that can overflow for `PHP_INT_MIN / -1`.

## Why it matters

`intdiv(PHP_INT_MIN, -1)` overflows integer arithmetic in PHP and causes a runtime error. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to detect feasible paths that reach this case.

## Bad example

```php
<?php
function overflow(): int
{
    return intdiv(PHP_INT_MIN, -1); // overflow
}
```

## Good example

```php
<?php
function safeIntDiv(int $a, int $b): int
{
    if ($b === 0) {
        throw new InvalidArgumentException('Division by zero');
    }
    if ($a === PHP_INT_MIN && $b === -1) {
        throw new InvalidArgumentException('Overflow');
    }

    return intdiv($a, $b);
}
```

## What it checks

- `intdiv(PHP_INT_MIN, -1)` and equivalent constant expressions
- Symbolic dividends and divisors whose feasible values reach the overflow case
- Guarded calls and bounded integer ranges
- Constant-return, identity, and PHPDoc method/function summaries

## Model limits

E0034 shares the model limits, loop bounds, and interprocedural behavior described in [E0031](../e31/e31.md).

## How to fix

- Guard against the `PHP_INT_MIN` and `-1` combination before calling `intdiv()`.
- Validate or constrain inputs so the overflow case is unreachable.
- Handle the overflow case explicitly when values come from external input.
