# E0104: HTTP response splitting

**In plain English:** User input is written to HTTP headers without sanitizing CRLF sequences (`\r\n`), allowing an attacker to inject additional headers or split the HTTP response.

**Why it matters:** HTTP response splitting can:
- Inject malicious headers (Set-Cookie, Location, etc.)
- Perform cache poisoning
- Perform cross-site scripting (XSS)
- Bypass security controls

## Bad

```php
$redirect = $_GET['redirect'] ?? '';
header("Location: $redirect");
// ?redirect=http://evil.com%0d%0aSet-Cookie: session=evil
```

## Good

```php
$redirect = $_GET['redirect'] ?? '';
$redirect = str_replace(["\r", "\n"], '', $redirect);
$allowed = ['/dashboard', '/profile'];
if (!in_array($redirect, $allowed, true)) {
    $redirect = '/dashboard';
}
header("Location: $redirect");
```

## What the rule checks

- `header()` calls with tainted input that may contain CRLF sequences
- `setcookie()` with tainted values that may contain newlines

## When it does not report

- `str_replace(["\r", "\n"], '', $input)` is recognized as sanitization
- Whitelist validation of header values

## How to fix

1. Strip `\r` and `\n` from all user input before writing to headers
2. Use whitelist validation for header values
3. Never include raw user input in `header()`, `setcookie()`, or `http_response_code()` messages

## Configuration

E0104 is enabled by default and has no configuration options.

## Taint Engine Backed

This rule is now powered by the phanalist taint engine. Instead of guessing whether
a variable contains user input (`has_user_input` / `looks_dynamic` heuristics), the
engine performs source-to-sink taint tracking. The rule queries `SinkKind` from the
engine:

- **`TaintMode::Only`** (default): Only reports when a proven taint flow from a source
  (e.g. `$_GET`, `$_POST`, superglobals, request parameters) reaches the sink.
- **`TaintMode::Annotate`**: Reports all findings and adds the proven source origin.
- **`TaintMode::Off`**: Retains the legacy heuristic behaviour through
  `taint_support::looks_dynamic` for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort,
CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent
of line numbers.
