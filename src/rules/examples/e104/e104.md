# E0104: Log File in Web Root

**In plain English:** Log files written to directories served by the web server can be downloaded directly via URL. If an attacker can guess the log file path, they can read all logged data.

**Why it matters:** Log file exposure can reveal:
- Passwords and tokens in logged data
- IP addresses and user information
- Internal application structure
- Error messages and stack traces

## Bad

```php
error_log($message, 3, '/var/www/html/app.log'); // accessible at https://example.com/app.log
file_put_contents(__DIR__ . '/../public/debug.log', $data);
```

## Good

```php
error_log($message, 3, '/var/log/app/app.log'); // outside web root
// Or: use syslog, or a logging service
```

## What the rule checks

- `error_log(..., 3, $path)` where `$path` contains `public/`, `www/`, `html/`, `web/`, `public_html/`
- `file_put_contents()` / `fopen()` with paths under web-accessible directories for log-like files

## When it does not report

- Heuristic path matching — may miss custom directory structures
- Cannot determine actual server document root

## How to fix

1. Write logs outside the web root (`/var/log/`, `/tmp/`, syslog)
2. Use a logging service (CloudWatch, Datadog, ELK)
3. Set file permissions to `0640` or stricter

## Configuration

E0104 is enabled by default. Configuration options:

```yaml
rules:
  E0104:
    web_accessible_paths:
      - public
      - www
      - html
      - web
      - public_html
      - document_root
      - htdocs
    log_keywords:
      - log
      - debug
      - access
      - error
      - audit
```
