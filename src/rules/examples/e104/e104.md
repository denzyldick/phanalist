# E0104: HTTP Response Splitting

Writing user input to HTTP headers without sanitizing CRLF sequences (`\r\n`) can allow an attacker to inject additional headers or split the HTTP response.

## Why it matters

HTTP response splitting can:

- Inject malicious headers (for example `Set-Cookie` or `Location`)
- Enable cache poisoning
- Enable cross-site scripting (XSS) in some contexts
- Bypass security controls

## Bad example

```php
$redirect = $_GET['redirect'] ?? '';
header("Location: $redirect");
// ?redirect=http://evil.com%0d%0aSet-Cookie: session=evil
```

## Good example

```php
$redirect = $_GET['redirect'] ?? '';
$redirect = str_replace(["\r", "\n"], '', $redirect);
$allowed = ['/dashboard', '/profile'];
if (!in_array($redirect, $allowed, true)) {
    $redirect = '/dashboard';
}
header("Location: $redirect");
```

## What it checks

- `header()` calls with tainted input that may contain CRLF sequences
- `setcookie()` with tainted values that may contain newlines

## When it does not report

- `str_replace(["\r", "\n"], '', $input)` is recognized as sanitization
- Allowlist validation of header values is recognized

## How to fix

1. Strip `\r` and `\n` from all user input before writing to headers.
2. Use allowlist validation for header values.
3. Never include raw user input in `header()`, `setcookie()`, or `http_response_code()` messages.

## Configuration

E0104 is enabled by default and has no configuration options.

## Taint engine

This rule is backed by the phanalist taint engine. Instead of guessing whether a variable contains user input, the engine tracks taint from sources to sinks.

- **`TaintMode::Only`** (default): Reports only when a proven taint flow from a source (for example `$_GET`, `$_POST`, superglobals, or request parameters) reaches the sink.
- **`TaintMode::Annotate`**: Reports all findings and adds the proven source origin.
- **`TaintMode::Off`**: Retains legacy heuristic behavior through `taint_support::looks_dynamic` for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort, CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent of line numbers.
