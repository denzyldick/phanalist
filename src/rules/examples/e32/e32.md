# E0032: Modulo by Zero

Reports modulo operations where the right operand can be zero.

## Why it matters

Modulo by zero causes runtime errors. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to find feasible paths where the divisor can be zero and provide a solver-backed counterexample.

## Bad example

```php
<?php
function bucket(int $id, int $size): int
{
    return $id % $size; // $size can be 0
}
```

## Good example

```php
<?php
function bucket(int $id, int $size): int
{
    if ($size === 0) {
        throw new InvalidArgumentException('Size must be non-zero');
    }

    return $id % $size;
}
```

## What it checks

- `%` and `%=` where the divisor can be zero
- Literal zero, symbolic zero, and zero reached through tracked arrays or expressions
- Guarded modulo, including `if`, `switch`, `match`, short-circuit `&&`, and `try`/`catch`/`finally` paths
- Loop exit values merged with the feasible zero-iteration path
- Constant-return, identity, and PHPDoc method/function summaries

## Model limits

E0032 shares the model limits, loop bounds, and interprocedural behavior described in [E0031](../e31/e31.md). A clean result is relative to that model, not a proof of every possible PHP execution.

## How to fix

- Guard the divisor before using `%` or `%=` when it can be zero.
- Use assertions or explicit checks to make the non-zero assumption clear on feasible paths.
- When the divisor comes from input or computation, handle the zero case explicitly.

## Configuration

Each verification code has its own settings block. The relevant check is:

```yaml
rules:
  E0032:
    php_version: "8.4"
    check_modulo: true
```

`check_modulo` controls the modulo-by-zero check for E0032. Other checks are configured under their own codes.
