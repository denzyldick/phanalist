# E0074: Weak random number generator

**In plain English:** Security-sensitive values (tokens, keys, salts, CSRF tokens) are generated using `rand()` or `mt_rand()`, which are predictable and not cryptographically secure.

**Why it matters:** `rand()` and `mt_rand()` use weak PRNG algorithms. Attackers can:
- Predict future random values from prior outputs
- Guess session tokens, CSRF tokens, or password reset tokens
- Bypass authentication and authorization

## Bad

```php
$token = bin2hex(mt_rand(100000, 999999)); // predictable
$key = rand(1000, 9999);                    // easily brute-forced
```

## Good

```php
$token = bin2hex(random_bytes(16));  // cryptographically secure
$key = random_int(1000, 9999);       // cryptographically secure
```

## What the rule checks

- `rand()`, `mt_rand()`, `uniqid()` used for security-sensitive purposes (tokens, keys, salts)
- `mt_rand()` without seeding from a secure source

## When it does not report

- `random_bytes()` and `random_int()` are recognized as safe
- `rand()` used for non-security purposes (e.g., game logic, display shuffling) may be flagged conservatively

## How to fix

1. Use `random_bytes()` for tokens and keys
2. Use `random_int()` for numeric security values
3. Never use `rand()`, `mt_rand()`, or `uniqid()` for security purposes

## Configuration

E0074 is enabled by default and has no configuration options.
