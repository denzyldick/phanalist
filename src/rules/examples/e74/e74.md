# E0074: Weak random number generator

**In plain English:** Your code writes passwords, tokens, or other credentials to log files. Log files are often less protected than source code and may be backed up, shipped to third parties, or accessible to support staff.

**Why it matters:** Credential leakage through logs:
- Anyone with log access can see passwords
- Log backups may be stored insecurely
- Third-party log services may have access
- Support staff can read credentials

## Bad

```php
error_log("Login attempt for user $username with password $password");
print_r($_POST); // logs passwords if in POST
syslog(LOG_INFO, "User $user logged in with $password");
```

## Good

```php
error_log("Login attempt for user $username"); // no password
$safe = ['username' => $username, 'ip' => $_SERVER['REMOTE_ADDR']];
error_log(json_encode($safe));
```

## What the rule checks

- `error_log()`, `syslog()`, `trigger_error()` with variables named `password`, `pass`, `pwd`, `secret`, `token`, `key`, `credential`
- `print_r($_POST)`, `var_dump($_REQUEST)`, `var_export($_POST)` — logging entire request arrays

## When it does not report

- Cannot analyze custom logging wrappers
- Heuristic based on variable names — may miss custom naming

## How to fix

1. Never log passwords, tokens, or secrets
2. Log only safe fields (username, IP, timestamp, action)
3. Use `filter_input()` and field allowlisting before logging

## Configuration

E0074 is enabled by default. Configuration options:

```yaml
rules:
  E0074:
    sensitive_names:
      - password
      - pass
      - pwd
      - secret
      - token
      - key
      - credential
      - api_key
      - auth
    sensitive_superglobals:
      - _POST
      - _REQUEST
      - _COOKIE
```

Credential leakage. Good for showing operational security issues beyond code bugs.
