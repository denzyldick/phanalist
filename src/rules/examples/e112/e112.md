# E0112: File upload without validation

**In plain English:** `move_uploaded_file()` is called without validating the uploaded file's extension, MIME type, or destination, allowing an attacker to upload malicious files.

**Why it matters:** Unrestricted file upload can lead to:
- Remote code execution via uploaded PHP scripts
- Server compromise
- Distribution of malware through your server

## Bad

```php
move_uploaded_file($_FILES['file']['tmp_name'], '/uploads/' . $_FILES['file']['name']);
```

An attacker uploads `shell.php` and accesses it at `https://yoursite.com/uploads/shell.php`.

## Good

```php
$allowed = ['jpg', 'jpeg', 'png', 'gif', 'pdf'];
$ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
if (!in_array($ext, $allowed, true)) {
    http_response_code(400);
    exit;
}
$finfo = new finfo(FILEINFO_MIME_TYPE);
$mime = $finfo->file($_FILES['file']['tmp_name']);
if (!in_array($mime, ['image/jpeg', 'image/png', 'image/gif', 'application/pdf'], true)) {
    http_response_code(400);
    exit;
}
$filename = bin2hex(random_bytes(16)) . '.' . $ext;
move_uploaded_file($_FILES['file']['tmp_name'], '/var/www/protected_uploads/' . $filename);
```

## What the rule checks

- `move_uploaded_file()` without prior extension/MIME validation
- `file_put_contents()` with `$_FILES` data
- `$_FILES['name']` used directly in file paths

## When it does not report

- Whitelist validation of extension and MIME type before move
- Uploads stored outside the web root with randomized filenames

## How to fix

1. Validate file extension against an allowlist
2. Verify MIME type with `finfo_file()`
3. Rename uploaded files to random names
4. Store uploads outside the web root

## Configuration

E0112 is enabled by default. Configuration options:

```yaml
rules:
  E0112:
    allowed_extensions:
      - jpg
      - jpeg
      - png
      - gif
      - pdf
      - txt
    check_mime: true
    store_outside_webroot: true
```
