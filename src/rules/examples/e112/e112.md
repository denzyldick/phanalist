# E0112: Fork Bomb

**In plain English:** `pcntl_fork()` called in a loop without limit can spawn unlimited processes, exhausting system resources.

**Why it matters:** A fork bomb can crash the entire server, not just the PHP application.

## Bad

```php
while (true) {
    pcntl_fork(); // unlimited process creation
}
// or
foreach ($items as $item) {
    pcntl_fork(); // one fork per item, no cap
}
```

## Good

```php
$max_workers = 10;
$active = 0;
foreach ($items as $item) {
    if ($active >= $max_workers) {
        pcntl_wait($status);
        $active--;
    }
    $pid = pcntl_fork();
    if ($pid === 0) {
        // child
        exit(0);
    }
    $active++;
}
```

## What the rule checks

- `pcntl_fork()` inside `while`, `for`, `foreach`, or `do-while` loops without an exit condition or worker cap
- `pcntl_fork()` without `pcntl_wait()` to reap children

## When it does not report

- Cannot determine loop bounds statically — flagged conservatively
- `pcntl_fork()` outside loops is not flagged

## How to fix

1. Use a worker pool with a maximum concurrency limit
2. Call `pcntl_wait()` to reap child processes
3. Use a job queue (Redis, RabbitMQ) instead of direct forking

## Configuration

E0112 is enabled by default and has no configuration options.

## Related CVE / blog angle

Fork bomb. Server-level DoS. Shows understanding of PHP process control.
