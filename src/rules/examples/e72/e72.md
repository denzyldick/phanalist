# E0072: Missing CSRF Protection

**In plain English:** Your application has forms or endpoints that change data (POST, PUT, DELETE) but doesn't verify that the request actually came from your own site. An attacker can trick a logged-in user's browser into making requests to your site without their knowledge.

**Why it matters:** CSRF allows attackers to:
- Change a user's email or password
- Delete a user's account
- Make purchases or transfers
- Perform any action the user is authorized to do

## Bad

```html
<form method="POST" action="/update-email">
    <input name="email" value="attacker@example.com">
    <button>Update</button>
</form>
```

An attacker can host this form on their site. If a logged-in user visits it, their email gets changed without their knowledge.

## Good

```html
<form method="POST" action="/update-email">
    <input type="hidden" name="_token" value="<?php echo csrf_token(); ?>">
    <input name="email">
    <button>Update</button>
</form>
```

## What the rule checks

- HTML `<form method="POST">` without a CSRF token field
- PHP endpoints handling `$_POST` state changes without CSRF validation

## When it does not report

- Cannot detect AJAX endpoints with custom CSRF headers
- Cannot validate that token is actually checked server-side
- Does not analyze SameSite cookie attributes as CSRF mitigation

## How to fix

1. Add CSRF tokens to all state-changing forms
2. Validate tokens on the server for every POST/PUT/DELETE
3. Use framework CSRF middleware (Laravel `VerifyCsrfToken`, Symfony `csrf_protection`)
4. Set `SameSite=Lax` or `Strict` on session cookies

## Configuration

E0072 is enabled by default. Configuration options:

```yaml
rules:
  E0072:
    csrf_token_names:
      - _token
      - csrf_token
      - token
      - csrfmiddlewaretoken
    state_changing_methods:
      - POST
      - PUT
      - PATCH
      - DELETE
```
