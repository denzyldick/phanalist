# E0072: Path traversal

**In plain English:** User-controlled input is used to build a file path without sanitizing `../` sequences, allowing an attacker to read or write files outside the intended directory.

**Why it matters:** Path traversal can:
- Read sensitive files like `/etc/passwd`, source code, and credentials
- Write arbitrary files to the server
- Lead to remote code execution if combined with file upload

## Bad

```php
$page = $_GET['page'] ?? '';
include __DIR__ . '/pages/' . $page . '.php';
```

If an attacker sends `?page=../../../etc/passwd`, your server reads `/etc/passwd`.

## Good

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include __DIR__ . '/pages/' . $page . '.php';
```

## What the rule checks

- `include`, `require`, `file_get_contents()`, `file_put_contents()`, `fopen()` with paths built from tainted input
- `../` or null byte (`%00`) sequences in user-controlled paths

## When it does not report

- Whitelist validation of path components
- `realpath()` verification that the resolved path starts with the expected directory

## How to fix

1. Use a whitelist of allowed paths/files
2. Use `realpath()` and verify the result starts with the expected directory prefix
3. Strip `../` and null bytes from user input

## Configuration

E0072 is enabled by default and has no configuration options.
