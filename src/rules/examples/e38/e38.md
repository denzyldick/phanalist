# E0038: Method Call on Null

Reports method calls on values that can be null.

## Why it matters

Calling a method on `null` causes a fatal runtime error. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to detect feasible paths where the receiver can be null.

## Bad example

```php
<?php
function name(?User $user): string
{
    return $user->getName(); // $user may be null
}
```

## Good example

```php
<?php
function name(?User $user): string
{
    if ($user === null) {
        return 'guest';
    }

    return $user->getName();
}
```

## What it checks

- Method calls on null and nullable values
- Nullness narrowed by `if`, `switch`, `match`, `isset()`, and short-circuit conditions
- Nullsafe calls (`?->`) are treated as safe
- PHPDoc parameter, `@var`, and return contracts
- Constant-return, identity, and method summaries

## Model limits

E0038 shares the model limits, loop bounds, and interprocedural behavior described in [E0031](../e31/e31.md).

## How to fix

- Guard nullable values before calling methods.
- Use nullsafe operator `?->` when a null result is acceptable.
- Make nullability explicit in types/contracts and handle the null case intentionally.

## Configuration

```yaml
rules:
  E0038:
    php_version: "8.4"
    check_nullability: true
```

See [E0031](../e31/e31.md) for the shared model limits, `unknown_policy` behavior, and per-code configuration.
