# E0134: Mail injection via mail

**In plain English:** User input is passed to the `mail()` function's headers or subject parameters without sanitization, allowing an attacker to inject additional email headers (BCC, CC, From) and turn your contact form into a spam relay.

**Why it matters:** Mail injection can:
- Turn your contact form into a spam relay
- Send emails to arbitrary recipients with forged headers
- Bypass email filtering and security controls
- Damage your domain's email reputation

## Bad

```php
$email = $_GET['email'] ?? '';
mail('admin@example.com', 'Contact Form', $message, "From: $email");
// ?email=attacker@example.com%0d%0aBCC: victim@example.com
```

## Good

```php
$email = $_GET['email'] ?? '';
if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    http_response_code(400);
    exit;
}
$headers = ["From: webform@example.com", "Reply-To: $email"];
mail('admin@example.com', 'Contact Form', $message, implode("\r\n", $headers));
```

## What the rule checks

- `mail()` calls where user input is passed to the `$additional_headers` parameter
- `mail()` calls where user input is passed to the `$subject` parameter
- CRLF sequences (`\r\n`) in mail headers or subject

## When it does not report

- `filter_var($email, FILTER_VALIDATE_EMAIL)` is recognized as validation
- `str_replace(["\r", "\n"], '', $input)` is recognized as sanitization
- Static email addresses are not flagged

## How to fix

1. Validate email addresses with `filter_var(FILTER_VALIDATE_EMAIL)`
2. Strip `\r` and `\n` from all user input passed to `mail()`
3. Use a fixed `From:` address and put user input in `Reply-To:` instead
4. Use a dedicated mail library (SwiftMailer, PHPMailer, Symfony Mailer)

## Configuration

E0134 is enabled by default and has no configuration options.
