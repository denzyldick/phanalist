# E0134: Mail injection via mail

**In plain English:** An autoloader includes class files based on user-controlled class names. An attacker can trigger inclusion of arbitrary files (LFI/RFI).

**Why it matters:** Autoload injection can lead to local/remote file inclusion and object injection.

## Bad

```php
spl_autoload_register(function($class) {
    include "/classes/$class.php";
});
// Triggered by: new $_GET['class']()
```

## Good

```php
spl_autoload_register(function($class) {
    $allowed = ['User', 'Product', 'Order'];
    if (!in_array($class, $allowed, true)) {
        return;
    }
    include "/classes/$class.php";
});
```

## What the rule checks

- `spl_autoload_register()` closures that build include/require paths from the `$class` parameter without validation
- `__autoload()` function (legacy) with unvalidated class name

## When it does not report

- Whitelist validation inside autoloader is recognized
- PSR-4 autoloaders with fixed namespace prefixes are generally safe

## How to fix

1. Validate class names against a whitelist in autoloaders
2. Use Composer's autoloader instead of custom autoloaders
3. Never include files based directly on user input

## Configuration

E0134 is enabled by default and has no configuration options.

Autoload injection. Related to E0055 dynamic include and E0093 dynamic instantiation.
