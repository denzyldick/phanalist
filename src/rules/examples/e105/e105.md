# E0105: Local File Inclusion

Including or reading a local file based on user-controlled input can allow an attacker to read arbitrary files on your server or execute code.

## Why it matters

Local file inclusion (LFI) can:

- Read sensitive files (`/etc/passwd`, source code, credentials, config files)
- Include uploaded files containing malicious PHP code
- Lead to remote code execution when combined with file upload

## Bad example

```php
$page = $_GET['page'] ?? '';
include __DIR__ . '/pages/' . $page . '.php';
```

If an attacker sends `?page=../../../etc/passwd`, the server may read `/etc/passwd`.

## Good example

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include __DIR__ . '/pages/' . $page . '.php';
```

## What it checks

- `include`, `require`, `include_once`, and `require_once` with paths built from tainted input
- `file_get_contents()`, `file()`, `readfile()`, and `fopen()` with tainted paths
- `../` or null byte (`%00`) sequences in user-controlled paths

## When it does not report

- Allowlist validation is recognized
- `realpath()` verification that the resolved path starts with the expected directory is recognized

## How to fix

1. Use an allowlist of permitted pages or files.
2. Use `realpath()` and verify the result starts with the expected directory prefix.
3. Strip `../` and null bytes from user input.

## Configuration

E0105 is enabled by default and has no configuration options.

## Taint engine

This rule is backed by the phanalist taint engine. Instead of guessing whether a variable contains user input, the engine tracks taint from sources to sinks.

- **`TaintMode::Only`** (default): Reports only when a proven taint flow from a source (for example `$_GET`, `$_POST`, superglobals, or request parameters) reaches the sink.
- **`TaintMode::Annotate`**: Reports all findings and adds the proven source origin.
- **`TaintMode::Off`**: Retains legacy heuristic behavior through `taint_support::looks_dynamic` for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort, CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent of line numbers.
