# E0105: SSTI (Server-Side Template Injection)

**In plain English:** User input is passed directly into a template rendering engine (Twig, Smarty, Blade) without sanitization. An attacker can inject template expressions that execute arbitrary code on the server.

**Why it matters:** SSTI can lead to:
- Remote code execution
- File read (reading sensitive files like `/etc/passwd`)
- Full server compromise

## Bad

```php
$template = $_GET['template'] ?? '';
echo $twig->render($template, ['name' => $user->name]);
```

An attacker sends `?template={{7*7}}` or `{{self.__init__.__globals__}}` to execute code.

## Good

```php
$template = $_GET['template'] ?? '';
$allowed = ['welcome', 'goodbye', 'reminder'];
if (!in_array($template, $allowed, true)) {
    $template = 'welcome';
}
echo $twig->render($template, ['name' => $user->name]);
```

## What the rule checks

- `Twig::render()`, `$twig->render()`, `$smarty->display()`, `$blade->render()` with tainted template names/sources

## When it does not report

- Whitelist validation on template names is recognized
- Cannot analyze template file contents for inline expression injection
- Does not cover JavaScript template engines (Vue, React) — those are client-side

## How to fix

1. Use a whitelist of allowed template names
2. Never pass user input as the template source
3. Use template engine sandbox modes if available

## Configuration

E0105 is enabled by default. Configuration options:

```yaml
rules:
  E0105:
    template_engines:
      - twig
      - smarty
      - blade
      - latte
    render_methods:
      - render
      - display
      - fetch
      - make
```
