# E0105: Local file inclusion

**In plain English:** A local file is included or read based on user-controlled input, allowing an attacker to read arbitrary files on your server or execute code.

**Why it matters:** Local file inclusion (LFI) can:
- Read sensitive files (`/etc/passwd`, source code, credentials, config files)
- Include uploaded files containing malicious PHP code
- Lead to remote code execution when combined with file upload

## Bad

```php
$page = $_GET['page'] ?? '';
include __DIR__ . '/pages/' . $page . '.php';
```

If an attacker sends `?page=../../../etc/passwd`, your server reads `/etc/passwd`.

## Good

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include __DIR__ . '/pages/' . $page . '.php';
```

## What the rule checks

- `include`, `require`, `include_once`, `require_once` with paths built from tainted input
- `file_get_contents()`, `file()`, `readfile()`, `fopen()` with tainted paths
- `../` or null byte (`%00`) sequences in user-controlled paths

## When it does not report

- Whitelist validation is recognized
- `realpath()` verification that the resolved path starts with the expected directory

## How to fix

1. Use a whitelist of allowed pages/files
2. Use `realpath()` and verify the result starts with the expected directory prefix
3. Strip `../` and null bytes from user input

## Configuration

E0105 is enabled by default and has no configuration options.
