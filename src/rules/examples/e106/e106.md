# E0106: Deserialization of untrusted data

**In plain English:** Untrusted data is deserialized using `unserialize()` or `wddx_deserialize()`, which can instantiate arbitrary PHP objects and trigger magic methods, leading to object injection.

**Why it matters:** Deserialization of untrusted data is a critical vulnerability. Attackers can:
- Instantiate arbitrary PHP classes
- Trigger magic methods (`__wakeup()`, `__destruct()`)
- Execute arbitrary code through gadget chains
- Achieve remote code execution

## Bad

```php
$data = $_GET['data'] ?? '';
$result = unserialize($data);
// or
$result = wddx_deserialize($data);
```

## Good

```php
// Use JSON instead of PHP serialization or WDDX for untrusted data
$data = $_GET['json'] ?? '';
$result = json_decode($data, true);
if (json_last_error() !== JSON_ERROR_NONE) {
    http_response_code(400);
    exit;
}
```

## What the rule checks

- `unserialize()` calls with tainted input from superglobals
- `wddx_deserialize()` calls with any argument (inherently dangerous)
- `session_decode()` with user-controlled data

## When it does not report

- `unserialize()` with `['allowed_classes' => false]` to prevent object instantiation
- `json_decode()` is recognized as safe

## How to fix

1. Never pass user-controlled data to `unserialize()` or `wddx_deserialize()`
2. Use JSON (`json_decode()` / `json_encode()`) instead
3. If you must use `unserialize()`, pass `['allowed_classes' => false]`

## Configuration

E0106 is enabled by default and has no configuration options.
