# E0106: Deserialization of untrusted data

**In plain English:** Template variables are output without escaping (`{{ var }}` in Twig without autoescape, `{!! var !!}` in Blade raw echo). An attacker can inject HTML/JavaScript that runs in other users' browsers.

**Why it matters:** Unescaped template output is XSS. Even with auto-escaping on globally, raw output tags bypass it.

## Bad

```twig
{# Twig with autoescape off #}
{{ user_input }}

{!! $user_input !!}  {# Blade raw echo #}
```

## Good

```twig
{# Twig autoescape on (default) #}
{{ user_input | escape }}
{{ user_input }}

{!! $user_input !!}  {# only if $user_input is known-safe HTML #}
```

## What the rule checks

- Twig `{{ var }}` where `var` may be tainted and autoescape is off
- Blade `{!! !!}` raw echo with tainted variables
- Smarty `{$var}` without `|escape` modifier

## When it does not report

- Cannot statically determine if Twig autoescape is on/off — flagged conservatively
- Cannot trace taint through template context arrays
- Blade `{{ $var }}` (escaped) is not flagged

## How to fix

1. Enable Twig autoescape globally (`autoescape: true`)
2. Use `{{ var | escape }}` explicitly when unsure
3. Avoid `{!! !!}` in Blade unless the content is sanitized HTML

## Configuration

E0106 is enabled by default. Configuration options:

```yaml
rules:
  E0106:
    raw_output_tags:
      - '{!! !!}'  # Blade raw
      - '{$var|raw}'  # Smarty raw
    autoescape_off_indicators:
      - 'autoescape: false'
      - 'autoescape: off'
```

Template XSS. Good for showing that template engines don't automatically make you safe.
