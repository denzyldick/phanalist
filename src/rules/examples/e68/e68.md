# E0068: Open Redirect

**In plain English:** Your application takes a URL from a user and redirects them to it without checking where it goes. An attacker can craft a link that looks like it's from your site but actually sends users to a malicious site.

**Why it matters:** Open redirect is used in:
- **Phishing campaigns**: Users trust your domain, so they click the link
- **Bypassing SSO protections**: Redirecting after login to a malicious site
- **Credential harvesting**: The malicious site looks like yours to steal credentials

## Bad

```php
$url = $_GET['redirect'] ?? '';
header("Location: $url");
exit;
```

If an attacker sends a link like: `https://yoursite.com/redirect.php?url=http://evil.com/login`, users click thinking it's safe, but get sent to `evil.com/login` which looks like your login page.

## Good

```php
$url = $_GET['redirect'] ?? '';
$allowed = ['/dashboard', '/profile', '/login'];
if (!in_array($url, $allowed, true)) {
    $url = '/dashboard';
}
header("Location: $url");
```

## What the rule checks

- `header("Location: ...")` with tainted input
- `header("refresh: ...;url=...")` with tainted input
- `header("uri: ...")` with tainted input

## When it does not report

- Whitelist validation (`in_array()` with strict mode) is recognized
- Relative paths starting with `/` may be flagged conservatively unless whitelisted

## How to fix

1. Use a whitelist of allowed redirect paths:
   ```php
   $allowed = ['/dashboard', '/profile', '/login'];
   ```
2. Validate that URLs are relative and same-origin
3. Never redirect to user-supplied URLs directly

## Configuration

E0068 is enabled by default and has no configuration options.
