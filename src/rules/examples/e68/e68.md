# E0068: Eval injection

**In plain English:** User-supplied input is passed to `eval()` or similar code execution sinks, allowing an attacker to run arbitrary PHP code on your server.

**Why it matters:** `eval()` is one of the most dangerous functions in PHP. If an attacker controls any part of the evaluated string, they can:
- Execute arbitrary system commands
- Read or modify files
- Steal data or credentials
- Take full control of the server

## Bad

```php
$code = $_GET['code'] ?? '';
eval($code);
```

An attacker sends: `?code=system('id');` and your server runs it.

## Good

```php
// Never eval user input. Use a whitelist of allowed operations instead.
$action = $_GET['action'] ?? '';
$allowed = ['list', 'view', 'search'];
if (!in_array($action, $allowed, true)) {
    http_response_code(400);
    exit;
}
// Handle each allowed action explicitly
switch ($action) {
    case 'list':
        listItems();
        break;
    // ...
}
```

## What the rule checks

- `eval()` calls with tainted input
- `assert()` with a string argument containing user input
- `create_function()` (removed in PHP 8) with user input

## When it does not report

- `eval()` on literal strings or trusted internal variables
- `assert()` with a boolean expression (not a string)

## How to fix

1. Never pass user input to `eval()`
2. Replace dynamic code execution with a whitelist-based dispatch
3. Use `assert()` only with boolean expressions, never strings

## Configuration

E0068 is enabled by default and has no configuration options.
