# E0102: Command injection via proc_open

**In plain English:** User input is passed to `proc_open()` as part of a command, allowing an attacker to execute arbitrary shell commands on your server.

**Why it matters:** Command injection via `proc_open()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Achieve full server compromise

## Bad

```php
$cmd = $_GET['cmd'] ?? '';
$descriptors = [0 => ['pipe', 'r'], 1 => ['pipe', 'w'], 2 => ['pipe', 'w']];
$process = proc_open($cmd, $descriptors, $pipes);
```

An attacker sends: `?cmd=ls; cat /etc/passwd` and your server executes both commands.

## Good

```php
$cmd = $_GET['cmd'] ?? '';
$allowed = ['ls', 'whoami', 'date'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$process = proc_open(escapeshellcmd($cmd), $descriptors, $pipes);
```

## What the rule checks

- `proc_open()` calls where the command string contains tainted input
- `proc_open()` with user-controlled command arguments without `escapeshellarg()`

## When it does not report

- `proc_open()` with literal commands or validated input
- `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Never pass user input directly to `proc_open()`
2. Validate commands against a whitelist
3. Use `escapeshellarg()` for all user-controlled arguments
4. Prefer PHP-native functions over shell commands

## Configuration

E0102 is enabled by default and has no configuration options.

## Taint Engine Backed

This rule is now powered by the phanalist taint engine. Instead of guessing whether
a variable contains user input (`has_user_input` / `looks_dynamic` heuristics), the
engine performs source-to-sink taint tracking. The rule queries `SinkKind` from the
engine:

- **`TaintMode::Only`** (default): Only reports when a proven taint flow from a source
  (e.g. `$_GET`, `$_POST`, superglobals, request parameters) reaches the sink.
- **`TaintMode::Annotate`**: Reports all findings and adds the proven source origin.
- **`TaintMode::Off`**: Retains the legacy heuristic behaviour through
  `taint_support::looks_dynamic` for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort,
CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent
of line numbers.
