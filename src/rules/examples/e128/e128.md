# E0128: Missing Subresource Integrity

**In plain English:** External JavaScript/CSS loaded without `integrity` attribute can be modified by a compromised CDN, executing attacker-controlled code on your site.

**Why it matters:** If a CDN is compromised, all sites loading its scripts without SRI will execute the malicious code.

## Bad

```html
<script src="https://cdn.example.com/library.js"></script>
<link rel="stylesheet" href="https://cdn.example.com/style.css">
```

## Good

```html
<script src="https://cdn.example.com/library.js" integrity="sha384-..." crossorigin="anonymous"></script>
<link rel="stylesheet" href="https://cdn.example.com/style.css" integrity="sha384-..." crossorigin="anonymous">
```

## What the rule checks

- PHP scripts outputting `<script src="...">` or `<link rel="stylesheet" href="...">` to external domains without `integrity` attribute
- Cannot detect HTML in template files without parsing

## When it does not report

- Cannot detect SRI set by frontend build tools (webpack, vite)
- Cannot detect HTML in `.phtml`, `.blade.php`, `.twig` templates without template parsing

## How to fix

1. Add `integrity` attributes with SHA-384 hashes to all external scripts/styles
2. Use `crossorigin="anonymous"` with SRI
3. Subresource Integrity generator: https://www.srihash.org/

## Configuration

E0128 is enabled by default. Configuration options:

```yaml
rules:
  E0128:
    external_domains:
      - cdn.example.com
      - code.jquery.com
      - stackpath.bootstrapcdn.com
```
