# E0033: intdiv() by Zero

Reports `intdiv()` calls where the divisor can be zero.

## Why it matters

`intdiv()` throws a `DivisionByZeroError` when its divisor is zero. This rule uses Phanalist's bounded formal verification engine (Z3-backed) to find feasible paths where that can happen.

## Bad example

```php
<?php
function split(int $total, int $parts): int
{
    return intdiv($total, $parts); // $parts can be 0
}
```

## Good example

```php
<?php
function split(int $total, int $parts): int
{
    if ($parts === 0) {
        throw new InvalidArgumentException('Parts must be non-zero');
    }

    return intdiv($total, $parts);
}
```

## What it checks

- `intdiv($value, 0)` and `intdiv($value, $divisor)` where `$divisor` can be zero
- Symbolic divisors, tracked array elements, and bounded integer ranges
- Guarded calls, including `if`, `switch`, `match`, short-circuit `&&`, and `try`/`catch`/`finally` paths
- Constant-return, identity, and PHPDoc method/function summaries

## Model limits

E0033 shares the model limits, loop bounds, and interprocedural behavior described in [E0031](../e31/e31.md).

## How to fix

- Check that the divisor is non-zero before calling `intdiv()`.
- Add guards or assertions that make the non-zero condition explicit on feasible paths.
- Handle the zero case separately when the divisor is derived from input or computation.

## Configuration

```yaml
rules:
  E0033:
    php_version: "8.4"
    check_intdiv: true
```

See [E0031](../e31/e31.md) for the shared model limits, `unknown_policy` behavior, and per-code configuration.
