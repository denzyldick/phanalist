# E0084: SQL query string concatenation

**In plain English:** User input is concatenated directly into SQL query strings, allowing attackers to inject arbitrary SQL and read, modify, or delete your database.

**Why it matters:** SQL injection is one of the most dangerous web vulnerabilities. It can lead to:
- Stealing user data (emails, passwords, credit card numbers)
- Bypassing login screens entirely
- Deleting or modifying your database
- Taking full control of your server

## Bad

```php
$id = $_GET['id'] ?? '';
$result = mysqli_query($conn, "SELECT * FROM users WHERE id = $id");
```

An attacker can visit: `?id=1 OR 1=1` and your query becomes:
```sql
SELECT * FROM users WHERE id = 1 OR 1=1
```
This returns **all** users instead of just one.

## Good

```php
$id = $_GET['id'] ?? '';
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
$user = $stmt->fetch();
```

With prepared statements, the database treats `$id` as data only—never as executable code.

## What the rule checks

- `mysqli_query()`, `mysqli::query()`, `pg_query()`, `pg_exec()`, `PDO::query()`, `PDO::exec()` calls
- Where user input (`$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, etc.) is concatenated directly into the SQL string

## When it does not report

- Prepared statements with `?` or `:name` placeholders (e.g., `$pdo->prepare("... WHERE id = ?")`)
- Static SQL queries with no user input
- Input that has been validated against a whitelist

## How to fix

1. **Never trust user input.** Always assume `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE` contain attacker-controlled data.
2. **Use prepared statements** with PDO or MySQLi. Never concatenate variables into SQL strings.
3. **Validate input** as a second line of defense (e.g., cast to `int` if you expect a number).

```php
// Bad
$query = "SELECT * FROM users WHERE id = " . $_GET['id'];

// Good
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$_GET['id']]);
```

## Configuration

E0084 is enabled by default and has no configuration options.
