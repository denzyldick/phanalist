# E0107: Raw Output in Templates (`{!! !!}`)

**In plain English:** Blade's `{!! !!}` syntax outputs raw, unescaped HTML. If the content comes from user input, it's XSS.

**Why it matters:** `{!! !!}` is an explicit escape hatch — using it with user input defeats Laravel's XSS protection.

## Bad

```blade
{!! $user_bio !!}  // user bio could contain <script>
{!! $comment->content !!}  // comment could contain XSS payload
```

## Good

```blade
{{ $user_bio }}  // auto-escaped by Laravel
{!! $sanitized_html !!}  // only if content passed through HTML purifier
```

## What the rule checks

- `{!! !!}` Blade directives with variables that may originate from `$_GET`, `$_POST`, database, or user-generated content
- `@{{ }}` (escaped) is not flagged

## When it does not report

- Cannot trace whether a database field contains user-generated content — flagged conservatively
- HTML-purified content may still be flagged

## How to fix

1. Use `{{ $var }}` (escaped) by default
2. If raw HTML is required, pass through `HTMLPurifier` first
3. Never use `{!! !!}` with direct request input

## Configuration

E0107 is enabled by default and has no configuration options.
