# E0107: Weak Random for Security Tokens

Generating security-sensitive tokens (session tokens, CSRF tokens, password reset tokens, API keys) with weak random number generators like `rand()`, `mt_rand()`, or `uniqid()` can make them predictable.

## Why it matters

Weak random values are predictable. Attackers can:

- Guess session tokens and hijack user sessions
- Predict CSRF tokens and bypass CSRF protection
- Guess password reset tokens and take over accounts
- Recover API keys and access protected resources

## Bad example

```php
$token = bin2hex(mt_rand(100000, 999999)); // predictable
$resetToken = uniqid();                    // guessable
```

## Good example

```php
$token = bin2hex(random_bytes(16));   // cryptographically secure
$resetToken = random_int(100000, 999999); // cryptographically secure
```

## What it checks

- `rand()`, `mt_rand()`, or `uniqid()` used for security-sensitive purposes (tokens, keys, salts)
- `mt_rand()` or `rand()` assigned to variables named `token`, `key`, `secret`, `salt`, `nonce`, or `csrf`

## When it does not report

- `random_bytes()` and `random_int()` are recognized as safe
- `rand()` used for non-security purposes (for example game logic or display shuffling) may be flagged conservatively

## How to fix

1. Use `random_bytes()` for tokens and keys.
2. Use `random_int()` for numeric security values.
3. Never use `rand()`, `mt_rand()`, or `uniqid()` for security purposes.

## Configuration

E0107 is enabled by default.

```yaml
rules:
  E0107:
    token_variable_names:
      - token
      - key
      - secret
      - salt
      - nonce
      - csrf_token
      - reset_token
      - session_id
    weak_functions:
      - rand
      - mt_rand
      - uniqid
```
