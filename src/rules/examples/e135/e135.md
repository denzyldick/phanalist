# E0135: Reachable Unchecked `json_decode()` Result

**In plain English:** `json_decode()` can return `null` on invalid JSON. Using the result without checking for `null` causes errors or null dereferences.

**Why it matters:** Null dereference can crash the application or expose debug information.

## Bad

```php
$data = json_decode($_GET['json'] ?? '');
echo $data->name; // Fatal error if $data is null
```

## Good

```php
$data = json_decode($_GET['json'] ?? '');
if ($data === null) {
    http_response_code(400);
    exit;
}
echo $data->name;
```

## What the rule checks

- `json_decode()` results used without `is_null()` or `=== null` check
- Property access (`->`), method calls, or array access on `json_decode()` results without null guard

## When it does not report

- `json_decode($input, true)` returning array — same null check applies
- `json_last_error()` checks are recognized as validation

## How to fix

1. Always check `json_decode()` result for `null`
2. Use `json_decode($input, true, 512, JSON_THROW_ON_ERROR)` for exception-based handling

## Configuration

E0135 is enabled by default and has no configuration options.

## Related CVE / blog angle

Reliability + security. Null dereference can lead to information disclosure via error messages.
