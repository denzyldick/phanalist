# E0071: Unsafe file upload

Storing uploaded files without validating their type, extension, or destination can allow an attacker to upload executable code to the server.

## Why it matters

An attacker who can upload a `.php` file and access it through the web server may be able to:

- Execute arbitrary code
- Gain control of the server
- Use the uploaded file as a foothold for further attacks

## Bad example

```php
move_uploaded_file($_FILES['file']['tmp_name'], '/uploads/' . $_FILES['file']['name']);
```

An attacker can upload `shell.php` and access it at `https://yoursite.com/uploads/shell.php`.

## Good example

```php
$allowed = ['jpg', 'jpeg', 'png', 'gif', 'pdf'];
$ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
if (!in_array($ext, $allowed, true)) {
    http_response_code(400);
    exit;
}
$finfo = new finfo(FILEINFO_MIME_TYPE);
$mime = $finfo->file($_FILES['file']['tmp_name']);
if (!in_array($mime, ['image/jpeg', 'image/png', 'image/gif', 'application/pdf'], true)) {
    http_response_code(400);
    exit;
}
$filename = bin2hex(random_bytes(16)) . '.' . $ext;
move_uploaded_file($_FILES['file']['tmp_name'], '/var/www/protected_uploads/' . $filename);
```

## What it checks

- `move_uploaded_file()` without prior extension or MIME validation
- `file_put_contents()` with `$_FILES` data
- `$_FILES['name']` used directly in file paths without sanitization

## When it does not report

- Cases where extension and MIME type are validated against a whitelist before moving the file
- Uploads stored outside the web root with randomized filenames

## How to fix

1. Validate the file extension against an allowlist.
2. Verify the MIME type with `finfo_file()`.
3. Rename uploaded files to random names.
4. Store uploads outside the web root and serve them through a PHP script.

## Configuration

E0071 is enabled by default. Configuration options:

```yaml
rules:
  E0071:
    allowed_extensions:
      - jpg
      - jpeg
      - png
      - gif
      - pdf
      - txt
    check_mime: true
    store_outside_webroot: true
```
