# E0071: Unsafe file upload

**In plain English:** Your application starts a session and stores login information in it, but doesn't change the session ID after login. An attacker can set a session ID before the user logs in, then use that same session ID to hijack the authenticated session.

**Why it matters:** Session fixation allows an attacker to:
- Authenticate using a session ID they chose
- Hijack the session after the victim logs in
- Access the victim's authenticated account

## Bad

```php
session_start();
$_SESSION['user_id'] = $user->id;
// No session_regenerate_id() after login
```

An attacker sends the victim a link with a pre-set session ID. When the victim logs in, the attacker uses that same session ID to access the account.

## Good

```php
session_start();
// Verify credentials...
$_SESSION['user_id'] = $user->id;
session_regenerate_id(true); // Fixation protection
```

## What the rule checks

- `session_start()` followed by `$_SESSION` writes without a subsequent `session_regenerate_id()`
- Login/auth endpoints that set session data without regenerating the ID

## When it does not report

- Cannot track session state across multiple files (heuristic limitation)

## How to fix

1. Call `session_regenerate_id(true)` immediately after authentication succeeds
2. Set `session.use_strict_mode = 1` in php.ini
3. Regenerate on privilege changes (user → admin)

## Configuration

E0071 is enabled by default and has no configuration options.
