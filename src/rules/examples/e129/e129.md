# E0129: Command execution via shell_exec

Passing untrusted input to `shell_exec()` can allow an attacker to execute arbitrary shell commands on the server.

## Why it matters

Command injection through `shell_exec()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Lead to full server compromise

## Bad example

```php
$cmd = $_GET['cmd'] ?? '';
$output = shell_exec($cmd);
echo $output;
```

An attacker can send `?cmd=cat /etc/passwd`, causing the server to execute the command.

## Good example

```php
// Avoid shell_exec() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['whoami', 'date', 'uptime'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$output = shell_exec(escapeshellcmd($cmd));
```

## What it checks

- `shell_exec()` calls where the command string contains tainted input
- `shell_exec()` calls with user-controlled command arguments without escaping

## When it does not report

- `shell_exec()` with literal commands or validated input
- Cases where `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Do not pass user input directly to `shell_exec()`.
2. Prefer PHP-native functions instead of shell commands.
3. If a shell command is required, validate it against an allowlist and escape all arguments.

## Configuration

E0129 is enabled by default and has no configuration options.
