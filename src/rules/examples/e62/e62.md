# E0062: Command injection

**In plain English:** Your code takes input from a user and passes it to a shell command (like `system()`, `exec()`, `shell_exec()`). An attacker can inject their own shell commands that run on your server.

**Why it matters:** Command injection leads to **full server compromise**. An attacker can:
- Read any file on your server
- Install malware or backdoors
- Delete your data
- Use your server to attack other systems

## Bad

```php
$file = $_GET['file'] ?? '';
system("cat $file");
```

If an attacker visits: `?file=; rm -rf /var/www/html`, your server runs:
```
cat ; rm -rf /var/www/html
```

## Good

```php
// Avoid shell execution entirely
$content = file_get_contents($file);

// If you must use shell, validate and escape
$allowed = ['file1.txt', 'file2.txt'];
if (!in_array($file, $allowed, true)) {
    http_response_code(400);
    exit;
}
$file = escapeshellarg($file);
system("cat $file");
```

## What the rule checks

- `system()`, `exec()`, `shell_exec()`, `passthru()`, `popen()`, `proc_exec()` calls
- Where user input is passed directly or concatenated into the command string

## When it does not report

- Commands with literal string arguments only
- Commands using `escapeshellarg()` on user input
- Commands with whitelist-validated input

## How to fix

1. **Avoid shell execution entirely.** Use PHP built-in functions instead (`file_get_contents()`, `scandir()`, `glob()`, etc.)
2. If shell is unavoidable, validate input against a whitelist first
3. Use `escapeshellarg()` on every user-controlled argument

## Configuration

E0062 is enabled by default and has no configuration options.
