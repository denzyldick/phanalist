# E0130: Command execution via passthru

Passing untrusted input to `passthru()` can allow an attacker to execute arbitrary shell commands on the server.

## Why it matters

Command injection through `passthru()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Lead to full server compromise

## Bad example

```php
$cmd = $_GET['cmd'] ?? '';
passthru($cmd);
```

An attacker can send `?cmd=cat /etc/passwd`, causing the server to execute the command.

## Good example

```php
// Avoid passthru() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['whoami', 'date', 'uptime'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
passthru(escapeshellcmd($cmd));
```

## What it checks

- `passthru()` calls where the command string contains tainted input
- `passthru()` calls with user-controlled command arguments without escaping

## When it does not report

- `passthru()` with literal commands or validated input
- Cases where `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Do not pass user input directly to `passthru()`.
2. Prefer PHP-native functions instead of shell commands.
3. If a shell command is required, validate it against an allowlist and escape all arguments.

## Configuration

E0130 is enabled by default and has no configuration options.
