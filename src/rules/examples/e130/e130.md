# E0130: Command execution via passthru

**In plain English:** User input is passed to `passthru()`, allowing an attacker to execute arbitrary shell commands on your server.

**Why it matters:** Command injection via `passthru()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Achieve full server compromise

## Bad

```php
$cmd = $_GET['cmd'] ?? '';
passthru($cmd);
```

An attacker sends: `?cmd=cat /etc/passwd` and your server returns the contents.

## Good

```php
// Avoid passthru() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['whoami', 'date', 'uptime'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
passthru(escapeshellcmd($cmd));
```

## What the rule checks

- `passthru()` calls where the command string contains tainted input
- `passthru()` with user-controlled command arguments without escaping

## When it does not report

- `passthru()` with literal commands or validated input
- `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Never pass user input directly to `passthru()`
2. Use PHP-native functions instead of shell commands
3. If you must run a command, validate against a whitelist and escape all arguments

## Configuration

E0130 is enabled by default and has no configuration options.
