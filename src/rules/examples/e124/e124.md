# E0124: Weak hash for passwords

**In plain English:** Passwords are hashed using weak algorithms like MD5, SHA1, or `crypt()` instead of a proper password hashing function like `password_hash()`.

**Why it matters:** Weak password hashing allows attackers to:
- Crack password hashes quickly using rainbow tables or GPU brute-force
- Reverse common passwords in seconds
- Compromise user accounts en masse if the database is leaked

## Bad

```php
$hash = md5($password);       // weak, fast, unsalted
$hash = sha1($password);      // weak, fast, unsalted
$hash = crypt($password);     // weak, may use DES-based crypt
```

## Good

```php
$hash = password_hash($password, PASSWORD_DEFAULT);
// Uses bcrypt or argon2 with automatic salting and cost factor
if (password_verify($password, $hash)) {
    // valid
}
```

## What the rule checks

- `md5()`, `sha1()`, `hash('md5', ...)`, `hash('sha1', ...)` applied to password-like variables
- `crypt()` used for password hashing

## When it does not report

- `password_hash()` and `password_verify()` are recognized as safe
- Hashing non-password data (file checksums, data integrity) may be flagged conservatively

## How to fix

1. Use `password_hash()` with `PASSWORD_DEFAULT` (bcrypt/argon2)
2. Verify with `password_verify()`
3. Never use MD5, SHA1, or `crypt()` for password storage

## Configuration

E0124 is enabled by default and has no configuration options.
