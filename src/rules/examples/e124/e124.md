# E0124: Weak hash for passwords

Hashing passwords with weak algorithms such as MD5, SHA1, or `crypt()` does not provide adequate protection for password storage. Use a dedicated password hashing function instead.

## Why it matters

Weak password hashing makes it easier for attackers to:
- Crack password hashes quickly using rainbow tables or brute-force attacks
- Recover common passwords in a short time
- Compromise many accounts if a password database is exposed

## Bad example

```php
$hash = md5($password);       // weak, fast, unsalted
$hash = sha1($password);      // weak, fast, unsalted
$hash = crypt($password);     // weak, may use DES-based crypt
```

## Good example

```php
$hash = password_hash($password, PASSWORD_DEFAULT);
// Uses bcrypt or argon2 with automatic salting and cost factor
if (password_verify($password, $hash)) {
    // valid
}
```

## What it checks

- `md5()`, `sha1()`, `hash('md5', ...)`, `hash('sha1', ...)` applied to password-like variables
- `crypt()` used for password hashing

## When it does not report

- `password_hash()` and `password_verify()` are recognized as safe
- Hashing non-password data (such as file checksums or data integrity) may be flagged conservatively

## How to fix

1. Use `password_hash()` with `PASSWORD_DEFAULT` (bcrypt or Argon2, depending on platform support).
2. Verify passwords with `password_verify()`.
3. Do not use MD5, SHA1, or `crypt()` for password storage.

## Configuration

E0124 is enabled by default and has no configuration options.
