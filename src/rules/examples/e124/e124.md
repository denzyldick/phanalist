# E0124: Missing `Referrer-Policy`

**In plain English:** No `Referrer-Policy` header, causing the browser to send full URLs (including query strings with sensitive data) to third-party sites.

**Why it matters:** Referrer headers leak:
- Internal URLs
- Session tokens in URLs
- Sensitive query parameters to external sites

## Bad

```php
// No Referrer-Policy header
header("Content-Type: text/html");
echo $page;
```

## Good

```php
header("Referrer-Policy: strict-origin-when-cross-origin");
header("Content-Type: text/html");
echo $page;
```

## What the rule checks

- PHP scripts sending HTML without `Referrer-Policy` header

## When it does not report

- Cannot detect Referrer-Policy set at web server level or via `<meta>` tag

## How to fix

1. Send `Referrer-Policy: strict-origin-when-cross-origin` or `no-referrer`
2. For maximum privacy: `no-referrer`

## Configuration

E0124 is enabled by default. Configuration options:

```yaml
rules:
  E0124:
    exclude_paths:
      - api/
```

Referrer leakage. Privacy-focused header. Easy to implement.
