# E0122: Missing Content-Security-Policy

**In plain English:** No `Content-Security-Policy` header is sent, allowing inline scripts and untrusted resource loading — enabling XSS and data exfiltration.

**Why it matters:** CSP is a strong second line of defense against XSS. Without it, any XSS vulnerability can load external scripts or exfiltrate data.

## Bad

```php
header("Content-Type: text/html");
echo $page;
// No CSP header
```

## Good

```php
header("Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com;");
header("Content-Type: text/html");
echo $page;
```

## What the rule checks

- PHP scripts sending HTML without `Content-Security-Policy` header
- Cannot detect CSP set via `<meta http-equiv="Content-Security-Policy">` in HTML

## When it does not report

- Cannot detect CSP set via web server CSP headers
- API/JSON endpoints don't need CSP

## How to fix

1. Send a restrictive `Content-Security-Policy` header on HTML responses
2. Start with `default-src 'self'` and add trusted sources as needed
3. Use `report-uri` or `report-to` for monitoring violations

## Configuration

E0122 is enabled by default. Configuration options:

```yaml
rules:
  E0122:
    exclude_paths:
      - api/
      - webhooks/
```
