# E0008: Return type signature

**In plain English:** Methods should declare explicit return type signatures (e.g., `: int`, `: string`, `: void`, `: ?User`).

**Why it matters:** Without return type signatures, other developers (and static analysis tools) have to read through the entire method body to figure out what it returns. Type declarations make code self-documenting and let PHP catch type mismatches at runtime.

## ❌ The Bad Example
```php
class UserService {
    // Missing return type signature
    public function getUser($id) {
        return $this->repository->find($id);
    }
}
```

## ✅ The Good Example
```php
class UserService {
    // Explicit return type signature
    public function getUser(int $id): ?User {
        return $this->repository->find($id);
    }
}
```

## What the rule checks
- Scans method declarations for missing return type signatures.

## When it does not report
- When methods declare an explicit return type (including `: void`, `: mixed`, or union types).

## How to fix
- Add a return type colon and typehint to your method signatures.

## Configuration
E0008 has no configuration options and is enabled by default.

### Junior Engineer's Rule of Thumb:
Always specify parameter types and return types on your methods. It turns your code into living documentation!
