# E0116: Remote command execution via popen

**In plain English:** User input is passed to `popen()`, allowing an attacker to execute arbitrary shell commands on your server through a pipe.

**Why it matters:** Command injection via `popen()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Achieve full server compromise

## Bad

```php
$cmd = $_GET['cmd'] ?? '';
$handle = popen($cmd, 'r');
echo fread($handle, 4096);
pclose($handle);
```

An attacker sends: `?cmd=cat /etc/passwd` and your server returns the contents.

## Good

```php
// Avoid popen() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['whoami', 'date', 'uptime'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$handle = popen(escapeshellcmd($cmd), 'r');
```

## What the rule checks

- `popen()` calls where the command string contains tainted input from superglobals
- `popen()` with user-controlled command arguments without `escapeshellcmd()` or `escapeshellarg()`

## When it does not report

- `popen()` with literal commands or validated input
- `escapeshellcmd()` / `escapeshellarg()` sanitization is recognized

## How to fix

1. Never pass user input directly to `popen()`
2. Use PHP-native functions instead of shell commands
3. If you must run a command, validate against a whitelist and escape all arguments

## Configuration

E0116 is enabled by default and has no configuration options.
