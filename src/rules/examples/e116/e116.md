# E0116: Remote command execution via popen

Passing untrusted input to `popen()` can allow an attacker to execute arbitrary shell commands on the server.

## Why it matters

Command injection through `popen()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Lead to full server compromise

## Bad example

```php
$cmd = $_GET['cmd'] ?? '';
$handle = popen($cmd, 'r');
echo fread($handle, 4096);
pclose($handle);
```

An attacker can send `?cmd=cat /etc/passwd`, causing the server to return sensitive file contents.

## Good example

```php
// Avoid popen() entirely. Use PHP-native functions instead.
// If you must run a command, validate strictly and escape:
$cmd = $_GET['cmd'] ?? '';
$allowed = ['whoami', 'date', 'uptime'];
$base = explode(' ', $cmd)[0] ?? '';
if (!in_array($base, $allowed, true)) {
    http_response_code(400);
    exit;
}
$handle = popen(escapeshellcmd($cmd), 'r');
```

## What it checks

- `popen()` calls where the command string contains tainted input from superglobals
- `popen()` calls with user-controlled command arguments without `escapeshellcmd()` or `escapeshellarg()`

## When it does not report

- `popen()` with literal commands or validated input
- Cases where `escapeshellcmd()` / `escapeshellarg()` sanitization is recognized

## How to fix

1. Do not pass user input directly to `popen()`.
2. Prefer PHP-native functions instead of shell commands.
3. If a shell command is required, validate the command against an allowlist and escape all arguments.

## Configuration

E0116 is enabled by default and has no configuration options.
