# E0118: `disable_functions` Not Set

**In plain English:** `disable_functions` can disable dangerous PHP functions (`exec`, `system`, `passthru`, `eval`, etc.). Without it, all functions are available if an attacker achieves code execution.

**Why it matters:** Disabling functions reduces the attack surface — even if an attacker injects code, they can't easily run shell commands.

## Bad

```php
// php.ini: disable_functions not set
// or
ini_set('disable_functions', ''); // cannot be changed at runtime anyway (PHP_INI_SYSTEM)
```

## Good

```php
// php.ini: disable_functions = exec,system,passthru,shell_exec,popen,proc_open,eval,create_function
```

## What the rule checks

- Cannot read php.ini directly
- `ini_set('disable_functions', ...)` is a PHP_INI_SYSTEM setting — cannot be changed at runtime

## When it does not report

- `disable_functions` is PHP_INI_SYSTEM — cannot be set via `ini_set()` at runtime
- This rule is primarily informational/documentation

## How to fix

1. Set `disable_functions` in php.ini with dangerous functions
2. Combine with `open_basedir` and `allow_url_fopen = Off` for defense in depth

## Configuration

E0118 is enabled by default. Configuration options:

```yaml
rules:
  E0118:
    recommended_disabled:
      - exec
      - system
      - passthru
      - shell_exec
      - popen
      - proc_open
      - eval
      - create_function
      - mail
```
