# E0114: `ignore_user_abort(true)`

**In plain English:** `ignore_user_abort(true)` makes PHP continue running after the client disconnects. An attacker can trigger work that persists even after they cancel the request.

**Why it matters:** Combined with long-running operations, this allows resource exhaustion — the server keeps working even though the client has gone away.

## Bad

```php
ignore_user_abort(true);
set_time_limit(0);
// process large file upload — client cancels, server keeps processing
```

## Good

```php
// Default behavior (ignore_user_abort = false) — script stops when client disconnects
// Use a job queue for work that must complete regardless of client connection
```

## What the rule checks

- `ignore_user_abort(true)` calls
- `ini_set('ignore_user_abort', '1')` / `ini_set('ignore_user_abort', 'true')`

## When it does not report

- CLI scripts and background workers may intentionally use this — flagged conservatively
- Cannot determine web vs CLI context

## How to fix

1. Remove `ignore_user_abort(true)` from web request handlers
2. Use a job queue (Redis, RabbitMQ, Symfony Messenger) for work that must complete
3. Check `connection_aborted()` in long loops to exit early

## Configuration

E0114 is enabled by default. Configuration options:

```yaml
rules:
  E0114:
    exclude_paths:
      - scripts/
      - workers/
      - commands/
```
