# E0091: Source code exposure via highlight_file

**In plain English:** `highlight_file()`, `show_source()`, or `highlight_string()` are used in production code, exposing your PHP source code—including credentials and logic—to anyone who can access that page.

**Why it matters:** Source code disclosure exposes:
- Database credentials and API keys
- Business logic and application flow
- Other vulnerabilities in the codebase
- Third-party library versions

## Bad

```php
if ($_GET['debug'] === '1') {
    highlight_file(__FILE__); // exposes entire file source
}
show_source('config.php'); // exposes config file including DB credentials
```

## Good

```php
// Remove entirely — never expose source code to users
// If debugging is needed, use a local development environment only
```

## What the rule checks

- `highlight_file()`, `show_source()`, `highlight_string()` calls
- Especially dangerous when gated by user input (`$_GET['debug']`)

## When it does not report

- `highlight_string()` with a literal safe string may be intentional — flagged conservatively
- Cannot determine if behind authentication/authorization

## How to fix

1. Remove `highlight_file()` / `show_source()` from production code
2. Never expose source code via HTTP
3. Use a local IDE or `php -S` for development debugging

## Configuration

E0091 is enabled by default and has no configuration options.
