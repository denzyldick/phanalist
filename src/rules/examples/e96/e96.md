# E0096: Cookie without secure flag

**In plain English:** A cookie is set without the `Secure` flag, meaning it can be sent over unencrypted HTTP and intercepted by network attackers.

**Why it matters:** Without the `Secure` flag:
- Session cookies can be stolen via network sniffing
- Attackers on the same WiFi can capture cookies
- Authentication tokens are exposed in transit

## Bad

```php
setcookie('session_id', $value, [
    'secure' => false,   // sent over HTTP
    'httponly' => true,
]);
```

## Good

```php
setcookie('session_id', $value, [
    'secure' => true,    // HTTPS only
    'httponly' => true,  // not accessible via JavaScript
    'samesite' => 'Lax',
]);
```

## What the rule checks

- `setcookie()` or `setrawcookie()` calls where `secure` is not set to `true`
- `session_set_cookie_params()` with `secure => false`

## When it does not report

- Cookies explicitly marked `secure => true`
- Cannot detect server-level `session.cookie_secure` ini setting

## How to fix

1. Always set `secure => true` on cookies containing sensitive data
2. Use `session.cookie_secure = 1` in php.ini
3. Serve your site over HTTPS only

## Configuration

E0096 is enabled by default and has no configuration options.
