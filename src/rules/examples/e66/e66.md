# E0066: Header Injection / HTTP Response Splitting

**In plain English:** Your code takes input from a user and writes it into HTTP headers (like `Location:` for redirects or `Set-Cookie`). An attacker can inject newlines (`\r\n`) to add extra headers or split the HTTP response into two parts.

**Why it matters:** HTTP response splitting enables:
- Session fixation (forcing a user to use a specific session ID)
- Cache poisoning (getting malicious content cached)
- Cross-Site Scripting (XSS) via header injection
- Redirecting users to malicious sites

## Bad

```php
$url = $_GET['url'] ?? '';
header("Location: $url");
```

If an attacker sends: `?url=http://evil.com%0d%0aSet-Cookie: session=evil`, your server sends:
```
Location: http://evil.com
Set-Cookie: session=evil
```

## Good

```php
$url = $_GET['url'] ?? '';
$url = str_replace(["\r", "\n"], "", $url);
header("Location: $url");
```

Stripping newlines prevents the attacker from injecting additional headers.

## What the rule checks

- `header()`, `header_remove()` with tainted input
- `setcookie()`, `setrawcookie()` with tainted name/value

## When it does not report

- `str_replace(["\r", "\n"], "", $input)` is recognized as sanitization
- `filter_var($url, FILTER_VALIDATE_URL)` is recognized

## How to fix

1. Strip `\r` and `\n` from all header values:
   ```php
   $value = str_replace(["\r", "\n"], "", $userInput);
   ```
2. Validate URLs with `filter_var($url, FILTER_VALIDATE_URL)`
3. Never put raw user input in HTTP headers

## Configuration

E0066 is enabled by default and has no configuration options.
