# E0066: Header injection

This rule reports HTTP header-related calls where user-controlled input reaches the header value. Crafted input containing CR/LF characters can be used to inject additional headers or manipulate the response.

## Why it matters

Header injection can lead to response splitting, cache poisoning, unsafe redirects, session-related issues, or other header manipulation vulnerabilities depending on the context.

## Bad example

```php
$url = $_GET['url'] ?? '';
header("Location: $url");
```

If an attacker can inject newline characters, additional headers may be added to the response.

## Good example

```php
$url = $_GET['url'] ?? '';
$url = str_replace(["\r", "\n"], "", $url);
header("Location: $url");
```

Removing CR and LF characters prevents newline-based header injection. For URLs, also validate the expected format.

## What it checks

- `header()`, `header_remove()`, `setcookie()`, and `setrawcookie()` calls
- Cases where user-controlled input reaches these calls, based on taint analysis and dynamic-expression heuristics

## When it does not report

- Header values built only from static or trusted data
- Cases where sanitization or data flow prevents the taint/heuristic model from reporting the sink
- Cases where the model cannot prove the input reaches the call

## How to fix

- Strip `\r` and `\n` from header values before passing them to header functions.
- Validate URLs with `filter_var($url, FILTER_VALIDATE_URL)` when setting redirect targets.
- Avoid placing raw user input in HTTP headers.

## Configuration

E0066 is enabled by default. The taint-aware behavior is controlled by a per-rule `taint_mode` setting:

```yaml
rules:
  E0066:
    taint_mode: annotate
```

- `annotate` (default) reports the finding and adds the proven source origin to the message.
- `only` reports only findings reached by proven tainted data.
- `off` keeps the legacy heuristic-only behavior.
