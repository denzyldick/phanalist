# E0088: `in_array()` Without `strict=true`

**In plain English:** `in_array()` and `array_search()` use loose comparison (`==`) by default. This means `"1admin" == 1` is true, allowing attackers to bypass allowlists by passing strings that loosely match allowed values.

**Why it matters:** Type-juggled `in_array()` checks are a common PHP authorization bypass. An attacker can pass a string that loosely equals an allowed value, gaining access to restricted functionality.

## Bad

```php
$role = $_GET['role'] ?? '';
if (in_array($role, ['admin', 'moderator'])) {
    grantAccess();
}
$key = array_search($id, $ids); // no strict flag
```

If an attacker sends `?role=1admin`, PHP converts `"1admin"` to `1`, which may match `1` in the array if present.

## Good

```php
$role = $_GET['role'] ?? '';
if (in_array($role, ['admin', 'moderator'], true)) {
    grantAccess();
}
$key = array_search($id, $ids, true);
```

## What the rule checks

- `in_array()` calls without a third `strict` argument
- `array_search()` calls without a third `strict` argument

## When it does not report

- `in_array($needle, $haystack, true)` with strict mode enabled
- `array_search($needle, $haystack, true)` with strict mode enabled

## How to fix

1. Always pass `true` as the third argument:
   ```php
   in_array($needle, $haystack, true)
   ```
2. Use `array_flip()` + `isset()` for string lookups (strict by nature and faster)

## Configuration

E0088 is enabled by default and has no configuration options.
