# E0097: `import_request_variables()`

**In plain English:** `import_request_variables()` imports GET/POST/Cookie variables into the global scope. This can override existing variables and is deprecated/removed in PHP 5.4+. An attacker can override internal variables by sending specially named request parameters.

**Why it matters:** `import_request_variables()` can lead to:
- Variable override vulnerabilities
- Overwriting internal variables with attacker-controlled values
- Bypassing access controls

## Bad

```php
import_request_variables('G', 'my_');
// $my_foo is now $_GET['foo'] — attacker can override internal variables
```

## Good

```php
// Use $_GET, $_POST, $_REQUEST superglobals directly
$foo = $_GET['foo'] ?? null;
```

## What the rule checks

- `import_request_variables()` calls with any argument (function is inherently dangerous)

## When it does not report

- No safe usage — always flagged
- Removed in PHP 5.4+, but present in legacy code

## How to fix

1. Use superglobals directly (`$_GET`, `$_POST`, `$_REQUEST`)
2. Filter input with `filter_input()`

## Configuration

E0097 is enabled by default and has no configuration options.
