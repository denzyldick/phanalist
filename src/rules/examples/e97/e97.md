# E0097: Cookie without HttpOnly flag

**In plain English:** A cookie is set without the `HttpOnly` flag, meaning it can be accessed by JavaScript and stolen via XSS attacks.

**Why it matters:** Without the `HttpOnly` flag:
- Session cookies can be stolen by malicious JavaScript
- XSS attacks can exfiltrate authentication tokens
- Attackers can hijack user sessions

## Bad

```php
setcookie('session_id', $value, [
    'secure' => true,
    'httponly' => false,   // accessible via JavaScript
]);
```

## Good

```php
setcookie('session_id', $value, [
    'secure' => true,
    'httponly' => true,    // not accessible via JavaScript
    'samesite' => 'Lax',
]);
```

## What the rule checks

- `setcookie()` or `setrawcookie()` calls where `httponly` is not set to `true`
- `session_set_cookie_params()` with `httponly => false`

## When it does not report

- Cookies explicitly marked `httponly => true`
- Cannot detect server-level `session.cookie_httponly` ini setting

## How to fix

1. Always set `httponly => true` on cookies containing sensitive data
2. Use `session.cookie_httponly = 1` in php.ini
3. Only store non-sensitive data in JavaScript-accessible cookies

## Configuration

E0097 is enabled by default and has no configuration options.
