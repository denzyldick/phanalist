# E0063: LDAP Injection

**In plain English:** Your code takes input from a user and inserts it into an LDAP search query without escaping special characters. An attacker can craft input that changes what the LDAP search does—bypassing login, reading directory data, or modifying directory entries.

**Why it matters:** LDAP injection affects applications using LDAP/Active Directory for authentication or directory lookups. It can:
- Bypass authentication (log in without a password)
- Read sensitive directory information (employee records, credentials)
- Modify directory entries

## Bad

```php
$username = $_GET['user'] ?? '';
$filter = "(uid=$username)";
$result = ldap_search($conn, $dn, $filter);
```

If an attacker sends: `?user=*)(|(uid=*))`, the LDAP filter becomes:
```
(uid=*)(|(uid=*)))
```
This can return **all** directory entries instead of just one user.

## Good

```php
$username = $_GET['user'] ?? '';
$filter = "(" . ldap_escape($username, '', LDAP_ESCAPE_FILTER) . ")";
$result = ldap_search($conn, $dn, $filter);
```

`ldap_escape()` with `LDAP_ESCAPE_FILTER` escapes special LDAP characters so they're treated as literal text, not LDAP syntax.

## What the rule checks

- `ldap_search()`, `ldap_list()`, `ldap_read()` calls where the filter contains user input without `ldap_escape()`

## When it does not report

- `ldap_escape()` with `LDAP_ESCAPE_FILTER` is recognized as safe sanitization
- Static LDAP filters with no user input

## How to fix

1. Use `ldap_escape($input, '', LDAP_ESCAPE_FILTER)` for any user input in LDAP filters
2. Use parameterized LDAP queries where your LDAP library supports them

## Configuration

E0063 is enabled by default and has no configuration options.
