# E0002: Empty catch

A `catch` block should not be left empty. Caught exceptions should be handled, logged, or rethrown.

## Why it matters

Catching an exception and doing nothing with it hides failures such as bugs, failed database queries, or invalid input. When something goes wrong, the application may fail silently or behave unpredictably without leaving useful trace information.

## Bad example

```php
try {
    $this->saveUser($data);
} catch (Exception $e) {
    // Empty catch block: the error is swallowed silently.
}
```

## Good example

```php
try {
    $this->saveUser($data);
} catch (DatabaseException $e) {
    // Log the error and rethrow or handle it appropriately.
    Log::error("Failed to save user: " . $e->getMessage());
    throw new UserSaveFailedException("Could not save user.", 0, $e);
}
```

## What it checks

- `try...catch` blocks where the catch body contains no statements.

## When it does not report

- When the catch block contains logging, error handling, or rethrows the exception.

## How to fix

- Log the exception using your application's logging mechanism.
- Handle the failure gracefully, or rethrow a more specific exception when appropriate.

## Configuration

E0002 has no configuration options and is enabled by default.
