# E0022: Afferent and Efferent Coupling (Ca/Ce)

Afferent coupling (Ca) and efferent coupling (Ce) measure how much a namespace depends on other namespaces and how much other namespaces depend on it.

## Why it matters

- **Ca (incoming coupling):** How many external classes depend on classes in this namespace. High Ca means changes here can affect many other parts of the system.
- **Ce (outgoing coupling):** How many external classes this namespace depends on. High Ce means this namespace is more sensitive to changes elsewhere.

High coupling in either direction can make code harder to change safely.

## How it works

The rule evaluates namespaces and counts:

1. **Ca:** External classes that use classes from the namespace.
2. **Ce:** External classes used by classes in the namespace.

If either value exceeds its configured threshold, the rule reports a violation.

## Bad example (high Ce)

```php
namespace App\Services\Reporting;

use App\Infrastructure\Database\Connection;
use App\Infrastructure\Mail\SmtpMailer;
use App\Vendors\PdfGenerator;
use App\Vendors\ExcelWriter;
use App\Infrastructure\Storage\S3Bucket;
use App\Infrastructure\Logging\Syslog;

class ReportGenerator {
    // Depends directly on many external infrastructure classes.
}
```

## Good example (lower Ce)

```php
namespace App\Services\Reporting;

interface MailerInterface {}
interface StorageInterface {}

class ReportGenerator {
    public function __construct(MailerInterface $mailer, StorageInterface $storage) {}
}
```

## How to fix

- Introduce interfaces or abstractions to reduce direct dependencies on external implementations.
- Move infrastructure concerns behind boundaries owned by the consuming namespace.
- Split namespaces that have accumulated too many responsibilities or dependencies.

## Configuration

```yaml
rules:
  E0022:
    max_ca: 20
    max_ce: 20
```
