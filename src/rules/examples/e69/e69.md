# E0069: Broken Access Control

**In plain English:** Your application has admin or sensitive functions that don't check whether the current user is actually allowed to use them. A regular user can access admin features they shouldn't see.

**Why it matters:** Broken access control lets regular users:
- Delete other users' accounts
- Access admin panels
- Modify other users' data
- Escalate their privileges to admin

## Bad

```php
if ($_GET['action'] === 'delete_user') {
    $db->delete($_GET['user_id']);
}
```

Anyone who knows the URL can delete any user—no admin check required.

## Good

```php
if (!$user->isAdmin()) {
    http_response_code(403);
    exit;
}
if ($_GET['action'] === 'delete_user') {
    $db->delete($_GET['user_id']);
}
```

## What the rule checks

- Functions/methods with admin-related names (`admin`, `delete`, `remove`, `ban`, `promote`) without authorization checks
- Missing `$user->can()`, `$user->isAdmin()`, `$this->authorize()`, or similar checks

## When it does not report

- Functions with explicit authorization checks (`isAdmin()`, `hasRole()`, `can()`, `authorize()`)

## How to fix

1. Add explicit authorization checks before sensitive actions:
   ```php
   if (!$user->isAdmin()) {
       http_response_code(403);
       exit;
   }
   ```
2. Use framework middleware (Laravel `can`, Symfony `access_control`)
3. Centralize authorization in a service or base controller

## Configuration

E0069 is enabled by default. Configuration options:

```yaml
rules:
  E0069:
    admin_keywords:
      - admin
      - delete
      - remove
      - ban
      - promote
    auth_functions:
      - isAdmin
      - hasRole
      - can
      - authorize
      - isGranted
```
