# E0069: Unsafe deserialization

**In plain English:** Untrusted data is passed to `unserialize()` or similar deserialization functions, which can instantiate arbitrary PHP objects and trigger magic methods like `__wakeup()` and `__destruct()`.

**Why it matters:** PHP object injection is a critical vulnerability. Attackers can craft serialized objects that:
- Trigger magic methods when unserialized
- Execute arbitrary code through gadget chains
- Read, modify, or delete files
- Achieve remote code execution

## Bad

```php
$data = $_GET['data'] ?? '';
$result = unserialize($data);
```

An attacker sends a malicious serialized payload that triggers `__wakeup()` or `__destruct()` in a loaded class.

## Good

```php
// Use JSON instead of PHP serialization for untrusted data
$data = $_GET['json'] ?? '';
$result = json_decode($data, true);
if (json_last_error() !== JSON_ERROR_NONE) {
    http_response_code(400);
    exit;
}
```

## What the rule checks

- `unserialize()` calls with tainted input from `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, or `php://input`
- `session_decode()` with user-controlled data

## When it does not report

- `unserialize()` on literal strings or trusted internal variables
- `unserialize()` with `allowed_classes` option set to `false` or a restrictive array

## How to fix

1. Never pass user-controlled data to `unserialize()`
2. Use JSON (`json_decode()` / `json_encode()`) instead of PHP serialization
3. If you must use `unserialize()`, pass `['allowed_classes' => false]` to prevent object instantiation

## Configuration

E0069 is enabled by default and has no configuration options.
