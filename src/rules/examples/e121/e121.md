# E0121: Missing `X-Frame-Options`

**In plain English:** The application doesn't send `X-Frame-Options` header, allowing the site to be embedded in iframes on malicious sites (clickjacking).

**Why it matters:** Clickjacking tricks users into clicking hidden UI elements on your site, performing unintended actions.

## Bad

```php
header("Content-Type: text/html");
echo $page;
```

## Good

```php
header("X-Frame-Options: DENY"); // or SAMEORIGIN
header("Content-Security-Policy: frame-ancestors 'none'"); // modern alternative
```

## What the rule checks

- PHP scripts that send HTML responses without `X-Frame-Options` or `Content-Security-Policy: frame-ancestors` headers
- Cannot detect framework-level middleware (Laravel, Symfony) — flagged conservatively

## When it does not report

- Cannot detect headers set by web server (Apache/Nginx config) or framework middleware
- CLI/API endpoints returning JSON may not need this header

## How to fix

1. Send `X-Frame-Options: DENY` or `SAMEORIGIN` on HTML responses
2. Or use `Content-Security-Policy: frame-ancestors 'none'`
3. Configure web server to add the header globally

## Configuration

E0121 is enabled by default. Configuration options:

```yaml
rules:
  E0121:
    exclude_paths:
      - api/
      - webhooks/
```
