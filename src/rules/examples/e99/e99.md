# E0099: Disable Functions Bypass

If `disable_functions` is not configured in `php.ini`, dangerous PHP functions remain available after code execution is achieved.

## Why it matters

`disable_functions` reduces the attack surface. Even if an attacker injects code, disabling dangerous functions can make it harder to run shell commands or perform other high-risk operations.

## Bad example

```php
// php.ini: disable_functions not set (empty)
// All functions remain available
```

## Good example

```php
// php.ini: disable_functions = exec,system,passthru,shell_exec,popen,proc_open,eval,create_function
```

## What it checks

- This rule is primarily informational/documentation
- `php.ini` cannot be read directly by the rule
- `ini_set('disable_functions', ...)` is `PHP_INI_SYSTEM` and cannot be changed at runtime

## When it does not report

- `disable_functions` is `PHP_INI_SYSTEM`; it cannot be set via `ini_set()` at runtime
- The rule does not verify actual `php.ini` contents

## How to fix

1. Set `disable_functions` in `php.ini` to include dangerous functions.
2. Combine with `open_basedir` and `allow_url_fopen = Off` for defense in depth.

## Configuration

E0099 is enabled by default.

```yaml
rules:
  E0099:
    recommended_disabled:
      - exec
      - system
      - passthru
      - shell_exec
      - popen
      - proc_open
      - eval
      - create_function
      - mail
```
