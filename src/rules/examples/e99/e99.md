# E0099: Disable functions bypass

**In plain English:** `disable_functions` is not configured in php.ini, leaving dangerous PHP functions available if an attacker achieves code execution.

**Why it matters:** `disable_functions` reduces the attack surface — even if an attacker injects code, they can't easily run shell commands or execute dangerous operations.

## Bad

```php
// php.ini: disable_functions not set (empty)
// All functions remain available
```

## Good

```php
// php.ini: disable_functions = exec,system,passthru,shell_exec,popen,proc_open,eval,create_function
```

## What the rule checks

- Cannot read php.ini directly — documents the risk
- `ini_set('disable_functions', ...)` is PHP_INI_SYSTEM and cannot be changed at runtime

## When it does not report

- `disable_functions` is PHP_INI_SYSTEM — cannot be set via `ini_set()` at runtime
- This rule is primarily informational/documentation

## How to fix

1. Set `disable_functions` in php.ini with dangerous functions
2. Combine with `open_basedir` and `allow_url_fopen = Off` for defense in depth

## Configuration

E0099 is enabled by default. Configuration options:

```yaml
rules:
  E0099:
    recommended_disabled:
      - exec
      - system
      - passthru
      - shell_exec
      - popen
      - proc_open
      - eval
      - create_function
      - mail
```
