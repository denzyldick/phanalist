# E0081: Deprecated regex function

**In plain English:** Your code encrypts data using ECB (Electronic Codebook) mode. ECB encrypts identical plaintext blocks into identical ciphertext blocks, which reveals patterns in the data.

**Why it matters:** ECB mode is insecure for most purposes:
- Reveals structure in the plaintext (patterns are visible in ciphertext)
- Vulnerable to replay attacks (attacker can replay encrypted blocks)
- Vulnerable to block-swapping attacks

## Bad

```php
$encrypted = openssl_encrypt($data, 'aes-256-ecb', $key);
```

## Good

```php
$iv = random_bytes(openssl_cipher_iv_length('aes-256-cbc'));
$encrypted = openssl_encrypt($data, 'aes-256-cbc', $key, 0, $iv);
// Or better: use authenticated encryption (AES-256-GCM)
```

## What the rule checks

- `openssl_encrypt()` and `openssl_decrypt()` calls where the cipher method contains "ecb"
- `mcrypt_encrypt()` with `MCRYPT_MODE_ECB` (legacy)

## When it does not report

- CBC, GCM, CTR, and other non-ECB modes
- Cipher methods specified as variables (cannot be analyzed statically)

## How to fix

1. Use AES-256-GCM (authenticated encryption) or AES-256-CBC with HMAC (encrypt-then-MAC)
2. Always use a random IV/nonce for each encryption operation
3. Never reuse the same IV with the same key

## Configuration

E0081 is enabled by default and has no configuration options.

Weak cryptography. Good for showing how encryption mode choice affects security.
