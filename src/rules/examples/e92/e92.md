# E0092: Variable Function Invocation

**In plain English:** Your code calls a function using a variable name that comes from user input. An attacker can control which function gets called, potentially calling dangerous functions like `system()`, `exec()`, or `shell_exec()`.

**Why it matters:** Variable functions allow dynamic code execution if the function name is controllable by an attacker:
- Call arbitrary PHP functions
- Call dangerous system functions
- Bypass access controls

## Bad

```php
$func = $_GET['func'] ?? '';
$func();
call_user_func($func, $arg);
```

## Good

```php
$func = $_GET['func'] ?? '';
$allowed = ['strlen', 'md5', 'sha1'];
if (!in_array($func, $allowed, true)) {
    http_response_code(400);
    exit;
}
$func($input);
```

## What the rule checks

- `$func()` where `$func` is assigned from tainted superglobals
- `call_user_func($func, ...)` where `$func` is tainted
- `call_user_func_array($func, ...)` where `$func` is tainted

## When it does not report

- Whitelist validation is recognized
- Static function names are not flagged

## How to fix

1. Use a whitelist/dispatch table of allowed functions
2. Never call user-supplied function names directly

## Configuration

E0092 is enabled by default and has no configuration options.

## Related CVE / blog angle

RCE variant. Common in poorly designed plugins.
