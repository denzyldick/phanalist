# E0004: Uppercase constants

**In plain English:** Global constants defined with `define()` and class/interface/trait/enum constants should always be written in ALL_CAPS (uppercase letters separated by underscores).

**Why it matters:** Following consistent naming conventions makes code instantly recognizable. In PHP, constants do not change their value. By convention, uppercase names tell any developer reading the code: "This value is immutable and global/constant; it is not a regular variable."

## ❌ The Bad Example
```php
define('max_retries', 3);

class Config {
    public const timeoutSeconds = 30;
}
```

## ✅ The Good Example
```php
define('MAX_RETRIES', 3);

class Config {
    public const TIMEOUT_SECONDS = 30;
}
```

## What the rule checks
- Global constants defined via `define()`.
- Constants defined inside classes, interfaces, traits, and enums (`const FOO = ...`).
- Verifies that constant names match their uppercase equivalent (`name == name.to_uppercase()`).

## When it does not report
- When all constant names are fully capitalized (`MAX_RETRIES`, `TIMEOUT_SECONDS`, etc.).

## How to fix
- Rename the constant to use uppercase letters and underscores.
- Update all references to the constant across your codebase.

## Configuration
E0004 has no configuration options and is enabled by default.

### Junior Engineer's Rule of Thumb:
Variables start with lowercase or camelCase (`$userCount`). Constants are always `UPPER_CASE_WITH_UNDERSCORES`.
