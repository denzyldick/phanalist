# E0079: Dynamic method call

**In plain English:** Your code creates symbolic links using user-controlled target or path. An attacker can create symlinks to sensitive files outside your web directory.

**Why it matters:** Symlink attacks can:
- Expose files outside the web root (`/etc/passwd`, SSH keys)
- Escalate privileges on shared hosting
- Create TOCTOU (time-of-check-time-of-use) vulnerabilities

## Bad

```php
$target = $_GET['target'] ?? '';
$link = $_GET['link'] ?? '';
symlink($target, $link);
```

An attacker can symlink `/etc/passwd` to `/var/www/html/passwd` and read it via the web.

## Good

```php
$target = realpath($_GET['target'] ?? '');
$allowedDir = '/var/www/uploads/';
if (strpos($target, $allowedDir) !== 0) {
    http_response_code(400);
    exit;
}
symlink($target, $link);
```

## What the rule checks

- `symlink()`, `link()` with tainted target or link path arguments

## When it does not report

- `realpath()` validation is recognized as a check
- Whitelist path prefix validation is recognized

## How to fix

1. Validate symlink targets resolve to allowed directories
2. Use `realpath()` and prefix-check:
   ```php
   $target = realpath($_GET['target'] ?? '');
   if (strpos($target, '/var/www/uploads/') !== 0) {
       http_response_code(400);
       exit;
   }
   ```
3. Avoid symlinks from user input entirely

## Configuration

E0079 is enabled by default and has no configuration options.
