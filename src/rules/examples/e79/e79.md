# E0079: Dynamic method call

**In plain English:** A method is invoked on an object using a method name that comes from user input, allowing an attacker to call arbitrary methods on your objects.

**Why it matters:** Dynamic method invocation can:
- Reach unintended business logic or internal methods
- Bypass access controls on sensitive operations
- Execute dangerous methods with attacker-controlled arguments

## Bad

```php
$method = $_GET['method'] ?? '';
$obj->$method();
```

An attacker sends `?method=deleteAllData` and your code calls it.

## Good

```php
$method = $_GET['method'] ?? '';
$allowed = ['getData', 'save', 'view'];
if (!in_array($method, $allowed, true)) {
    http_response_code(400);
    exit;
}
$obj->$method();
```

## What the rule checks

- `$obj->$method()` where `$method` is a variable from user input
- `$obj->{$method}()` with a tainted method name
- `call_user_func([$obj, $method])` with tainted method name

## When it does not report

- Whitelist validation of the method name before invocation
- Static method calls are not flagged

## How to fix

1. Use a whitelist of allowed method names
2. Use a command/action pattern instead of dynamic dispatch
3. Never pass user input directly as a method name

## Configuration

E0079 is enabled by default and has no configuration options.
