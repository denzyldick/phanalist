# E0117: SQL injection via query string

**In plain English:** User input from the query string (`$_GET`) is concatenated directly into SQL queries, allowing attackers to inject arbitrary SQL.

**Why it matters:** SQL injection via query string is especially dangerous because:
- Query string parameters are easily crafted and shared in URLs
- Attackers can automate attacks with simple URL manipulation
- Search/filter endpoints are common targets

## Bad

```php
$id = $_GET['id'] ?? '';
$result = mysqli_query($conn, "SELECT * FROM users WHERE id = $id");
```

An attacker visits `?id=1 OR 1=1` and your query returns all users.

## Good

```php
$id = $_GET['id'] ?? '';
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);
$user = $stmt->fetch();
```

## What the rule checks

- `mysqli_query()`, `PDO::query()`, `pg_query()` with SQL strings containing `$_GET` variables
- SQL queries built by string concatenation with query string input

## When it does not report

- Prepared statements with `?` or `:name` placeholders
- Input cast to safe types (e.g., `(int)$_GET['id']`)
- Whitelist validation of query string parameters

## How to fix

1. Never concatenate `$_GET` variables into SQL strings
2. Use prepared statements with parameter binding
3. Cast query string input to expected types (e.g., `(int)` for IDs)

## Configuration

E0117 is enabled by default and has no configuration options.
