# E0117: `open_basedir` Not Set

**In plain English:** `open_basedir` restricts PHP file operations to specific directories. Without it, scripts can read/write anywhere the web server user has access.

**Why it matters:** Without `open_basedir`, a compromised script can read `/etc/passwd`, SSH keys, and other sensitive system files.

## Bad

```php
// php.ini: open_basedir not set (empty)
// or
ini_set('open_basedir', ''); // explicitly disabled
```

## Good

```php
// php.ini: open_basedir = /var/www/example.com:/tmp
// Limits file operations to the app directory and tmp
```

## What the rule checks

- `ini_set('open_basedir', '')` or `ini_set('open_basedir', null)` — explicitly disabling
- Cannot detect absence of `open_basedir` in php.ini (only inline code)

## When it does not report

- Cannot read php.ini — only catches code that explicitly disables it
- CLI scripts may intentionally not use `open_basedir`

## How to fix

1. Set `open_basedir` to your application directories in php.ini or per-virtualhost
2. Combine with `disable_functions` for defense in depth

## Configuration

E0117 is enabled by default and has no configuration options.

PHP hardening. Server configuration best practice.
