# E0132: LIKE Injection

**In plain English:** User input in SQL `LIKE` queries is not escaped for `%` and `_` wildcards. An attacker can broaden search results or bypass filters.

**Why it matters:** LIKE injection can expose more data than intended and bypass search restrictions.

## Bad

```php
$search = $_GET['q'] ?? '';
$result = $pdo->query("SELECT * FROM products WHERE name LIKE '%$search%'");
```

## Good

```php
$search = $_GET['q'] ?? '';
$search = addcslashes($search, '%_');
$result = $pdo->prepare("SELECT * FROM products WHERE name LIKE ?");
$result->execute(["%$search%"]);
```

## What the rule checks

- SQL `LIKE` clauses with tainted input not escaped via `addcslashes($input, '%_')`
- Prepared statements with `LIKE ?` and proper parameter binding are safe

## When it does not report

- `addcslashes($input, '%_')` is recognized as sanitization
- `str_replace(['%', '_'], ['\\%', '\\_'], $input)` is recognized

## How to fix

1. Escape `%` and `_` in LIKE patterns
2. Use prepared statements with bound parameters

## Configuration

E0132 is enabled by default and has no configuration options.

Subtle SQLi variant. Good for advanced injection blog posts.
