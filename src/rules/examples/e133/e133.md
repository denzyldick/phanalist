# E0133: `preg_replace()` with `/e` Modifier

**In plain English:** `preg_replace()` with the `/e` modifier evaluates the replacement as PHP code. This is `eval()` in disguise and has been removed.

**Why it matters:** `/e` modifier with user input is direct RCE.

## Bad

```php
$input = $_GET['input'] ?? '';
$result = preg_replace('/pattern/e', "strtoupper('$input')", $text);
```

## Good

```php
$input = $_GET['input'] ?? '';
$result = preg_replace_callback('/pattern/', function($m) use ($input) {
    return strtoupper($input);
}, $text);
```

## What the rule checks

- `preg_replace()` with `/e` modifier (any usage is flagged)
- `preg_replace_callback()` is safe and not flagged

## When it does not report

- `/e` modifier removed in PHP 7.0+, but present in legacy codebases
- Always flagged — no safe usage with untrusted input

## How to fix

1. Replace with `preg_replace_callback()`
2. Never use `/e` modifier

## Configuration

E0133 is enabled by default and has no configuration options.

## Related CVE / blog angle

Legacy RCE. Good for PHP version migration blog posts.
