# E0003: Method modifiers

**In plain English:** Methods inside classes should always have an explicit visibility modifier (`public`, `protected`, or `private`) rather than relying on legacy default visibility.

**Why it matters:** Leaving methods without explicit modifiers creates ambiguity about whether a method is intended to be part of the public API or internal helper logic. Explicit visibility enforces proper encapsulation and class design.

## ❌ The Bad Example
```php
class Calculator {
    // Missing visibility modifier
    function add(int $a, int $b): int {
        return $a + $b;
    }
}
```

## ✅ The Good Example
```php
class Calculator {
    public function add(int $a, int $b): int {
        return $a + $b;
    }
}
```

## What the rule checks
- Scans class methods for missing visibility modifiers (`public`, `protected`, `private`).

## When it does not report
- When every method has an explicit visibility modifier.

## How to fix
- Add `public`, `protected`, or `private` to every method definition.

## Configuration
E0003 has no configuration options and is enabled by default.

### Junior Engineer's Rule of Thumb:
Always explicitly declare `public`, `protected`, or `private` on every method you write.
