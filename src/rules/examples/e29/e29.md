# E0029: Class Fan-in and Fan-out

Reports classes whose fan-out or fan-in exceeds configured thresholds.

## Why it matters

- **High fan-out** means a class depends on many other classes, making it more fragile and harder to change.
- **High fan-in** means many classes depend on this class, so changes can have wide impact and require careful testing.

## What it checks

- **Fan-out**: number of distinct classes a class depends on.
- **Fan-in**: number of other classes that depend on this class.
- Dependencies are collected from type hints, `new` instantiations, `instanceof` checks, static method calls, and property/constant access.
- Reports `E0029:fan-out` when fan-out exceeds `max_fan_out`.
- Reports `E0029:fan-in` when fan-in exceeds `max_fan_in`.

## Bad example: high fan-out

This class depends on many concrete classes directly.

```php
class ReportService
{
    public function __construct(
        private Database $db,
        private Mailer $mail,
        private PdfGenerator $pdf,
        private ExcelWriter $excel,
        private S3Storage $storage,
        private Logger $log,
        private Cache $cache,
        private Queue $queue,
        private EventBus $events,
        private Config $config,
    ) {}

    public function run(): void
    {
        $data = $this->db->query();
        $report = $this->pdf->generate($data);
        $this->storage->upload($report);
        $this->mail->send(new Notification());
    }
}
```

## Good example: lower fan-out

Dependencies are grouped behind smaller, focused collaborators.

```php
class ReportService
{
    public function __construct(
        private ReportRepository $reports,
        private ReportRenderer $renderer,
    ) {}

    public function run(): void
    {
        $report = $this->renderer->render($this->reports->fetch());
        $this->reports->save($report);
    }
}
```

## How to fix

- **High fan-out**: reduce direct dependencies, introduce abstractions, or split responsibilities across smaller classes.
- **High fan-in**: stabilize the class interface, add tests around its contract, and consider splitting it if it has become a central dependency for unrelated concerns.

## Configuration

```yaml
rules:
  E0029:
    max_fan_out: 10
    max_fan_in: 20
```
