# E0123: Missing `Strict-Transport-Security`

**In plain English:** No `Strict-Transport-Security` (HSTS) header, allowing downgrade attacks to HTTP.

**Why it matters:** Without HSTS, attackers can strip SSL and force the browser to use HTTP, enabling MITM attacks and cookie theft.

## Bad

```php
header("Location: https://example.com");
// No HSTS header on HTTPS responses
```

## Good

```php
header("Strict-Transport-Security: max-age=31536000; includeSubDomains");
header("Location: https://example.com");
```

## What the rule checks

- PHP scripts sending HTTPS responses (redirects, HTML) without `Strict-Transport-Security` header
- Cannot detect HSTS set at web server level

## When it does not report

- Cannot determine if site is HTTPS-only from static analysis
- Cannot detect web server HSTS headers

## How to fix

1. Send `Strict-Transport-Security: max-age=31536000; includeSubDomains` on all HTTPS responses
2. Ensure site is HTTPS-only (redirect HTTP to HTTPS)

## Configuration

E0123 is enabled by default. Configuration options:

```yaml
rules:
  E0123:
    exclude_paths:
      - api/
```
