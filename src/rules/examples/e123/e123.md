# E0123: XSS via echo

**In plain English:** User input is output directly via `echo`, `print`, or similar without escaping, allowing an attacker to inject JavaScript that runs in other users' browsers.

**Why it matters:** Cross-Site Scripting (XSS) can:
- Steal session cookies and authentication tokens
- Perform actions on behalf of the victim
- Deface your website
- Redirect users to malicious sites

## Bad

```php
$name = $_GET['name'] ?? '';
echo "Hello, $name";
// ?name=<script>stealCookies()</script>
```

## Good

```php
$name = $_GET['name'] ?? '';
echo "Hello, " . htmlspecialchars($name, ENT_QUOTES, 'UTF-8');
```

## What the rule checks

- `echo`, `print`, `printf()`, `vprintf()` with tainted input
- `<?=$var ?>` short echo tags with unescaped variables

## When it does not report

- `htmlspecialchars()`, `htmlentities()` escaping is recognized
- Output in non-HTML contexts (JSON, CLI) may be flagged conservatively

## How to fix

1. Always escape output with `htmlspecialchars()` for HTML contexts
2. Use `ENT_QUOTES | ENT_SUBSTITUTE` flags
3. Use a templating engine with auto-escaping (Twig, Blade, etc.)
4. Never echo user input directly

## Configuration

E0123 is enabled by default and has no configuration options.
