# E0126: Path traversal via file_get_contents

**In plain English:** `file_get_contents()` reads a file from a path built with user-controlled input without sanitizing `../` sequences, allowing an attacker to read arbitrary files on your server.

**Why it matters:** Path traversal via `file_get_contents()` can:
- Read sensitive files (`/etc/passwd`, source code, credentials, config files)
- Expose environment variables and application secrets
- Help attackers plan further attacks

## Bad

```php
$file = $_GET['file'] ?? '';
echo file_get_contents(__DIR__ . '/uploads/' . $file);
// ?file=../../../etc/passwd
```

## Good

```php
$file = $_GET['file'] ?? '';
$allowed = ['avatar.jpg', 'profile.png'];
if (!in_array($file, $allowed, true)) {
    http_response_code(400);
    exit;
}
echo file_get_contents(__DIR__ . '/uploads/' . $file);
```

## What the rule checks

- `file_get_contents()`, `file()`, `readfile()`, `fopen()` with paths built from tainted input
- `../` or null byte (`%00`) sequences in user-controlled paths

## When it does not report

- Whitelist validation of filenames
- `realpath()` verification that the resolved path starts with the expected directory

## How to fix

1. Use a whitelist of allowed files
2. Use `realpath()` and verify the result starts with the expected directory prefix
3. Strip `../` and null bytes from user input

## Configuration

E0126 is enabled by default and has no configuration options.
