# E0126: Path traversal via file_get_contents

Reading files with `file_get_contents()` (or similar functions) using a path built from user input can allow path traversal if `../` sequences or other unsafe path components are not properly restricted.

## Why it matters

Path traversal vulnerabilities can:
- Expose sensitive files such as `/etc/passwd`, source code, credentials, or configuration files
- Reveal environment details and application secrets
- Help attackers gather information for further attacks

## Bad example

```php
$file = $_GET['file'] ?? '';
echo file_get_contents(__DIR__ . '/uploads/' . $file);
// ?file=../../../etc/passwd
```

## Good example

```php
$file = $_GET['file'] ?? '';
$allowed = ['avatar.jpg', 'profile.png'];
if (!in_array($file, $allowed, true)) {
    http_response_code(400);
    exit;
}
echo file_get_contents(__DIR__ . '/uploads/' . $file);
```

## What it checks

- `file_get_contents()`, `file()`, `readfile()`, `fopen()` with paths built from tainted input
- User-controlled paths that may include `../` or null byte (`%00`) sequences

## When it does not report

- Filenames are validated against a whitelist
- `realpath()` verification confirms the resolved path starts with the expected directory prefix

## How to fix

1. Use an allowlist of permitted files.
2. Use `realpath()` and verify the resolved path stays within the expected directory.
3. Reject or sanitize unsafe path components such as `../` and null bytes.

## Configuration

E0126 is enabled by default and has no configuration options.
