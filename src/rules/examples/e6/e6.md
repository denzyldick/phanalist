# E0006: Property Modifiers

**In plain English:** Properties inside classes must have explicit visibility modifiers (`public`, `protected`, or `private`) and should generally not be left unprotected.

**Why it matters:** Public properties allow any external code to mutate object state directly, bypassing validation and encapsulation. Explicit property modifiers protect internal state and enforce object-oriented design principles.

## ❌ The Bad Example
```php
class User {
    // Property without visibility modifier or left public
    string $name;
}
```

## ✅ The Good Example
```php
class User {
    private string $name;

    public function getName(): string {
        return $this->name;
    }
}
```

## What the rule checks
- Scans class properties for missing visibility modifiers.

## When it does not report
- When properties have explicit visibility modifiers (`private`, `protected`, `public`).

## How to fix
- Add `private` or `protected` to properties to encapsulate state, providing getters/setters where needed.

## Configuration
E0006 has no configuration options and is enabled by default.

### Junior Engineer's Rule of Thumb:
Make your class properties `private` or `protected` by default, and expose access only through well-defined methods!
