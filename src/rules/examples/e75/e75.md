# E0075: Unvalidated File Upload

**In plain English:** Your application lets users upload files but doesn't check what kind of file they're uploading. An attacker can upload a `.php` file and execute code on your server.

**Why it matters:** Unrestricted file upload leads to **remote code execution**. One of the most common PHP vulnerabilities:
- Upload a PHP shell script
- Access it via your web server
- Run any command on your server

## Bad

```php
move_uploaded_file($_FILES['file']['tmp_name'], '/uploads/' . $_FILES['file']['name']);
```

An attacker uploads `shell.php` and accesses it at `https://yoursite.com/uploads/shell.php`.

## Good

```php
$allowed = ['jpg', 'png', 'gif', 'pdf'];
$ext = strtolower(pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION));
if (!in_array($ext, $allowed, true)) {
    http_response_code(400);
    exit;
}
$finfo = new finfo(FILEINFO_MIME_TYPE);
$mime = $finfo->file($_FILES['file']['tmp_name']);
if (!in_array($mime, ['image/jpeg', 'image/png', 'image/gif', 'application/pdf'], true)) {
    http_response_code(400);
    exit;
}
$filename = bin2hex(random_bytes(16)) . '.' . $ext;
move_uploaded_file($_FILES['file']['tmp_name'], '/uploads/' . $filename);
```

## What the rule checks

- `move_uploaded_file()` without extension/MIME validation beforehand
- `file_put_contents()` with `$_FILES` data
- `$_FILES['name']` used directly in file paths

## When it does not report

- Cannot verify actual file content magic bytes without runtime analysis
- Whitelist validation after upload but before move may still be flagged conservatively

## How to fix

1. Validate file extension against an allowlist
2. Verify MIME type with `finfo_file()`
3. Rename uploaded files to random names
4. Store uploads outside the web root

## Configuration

E0075 is enabled by default. Configuration options:

```yaml
rules:
  E0075:
    allowed_extensions:
      - jpg
      - jpeg
      - png
      - gif
      - pdf
      - txt
    check_mime: true
    store_outside_webroot: true
```
