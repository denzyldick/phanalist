# E0075: Session security

**In plain English:** `session_start()` is called without secure cookie settings, leaving session IDs vulnerable to interception and theft.

**Why it matters:** Insecure session configuration allows attackers to:
- Steal session cookies over unencrypted HTTP
- Access session data via JavaScript (XSS)
- Fixate session IDs before authentication
- Hijack authenticated user sessions

## Bad

```php
session_set_cookie_params([
    'secure' => false,    // sent over HTTP
    'httponly' => false,  // accessible via JavaScript
]);
session_start();
```

## Good

```php
session_set_cookie_params([
    'lifetime' => 3600,
    'path' => '/',
    'secure' => true,      // HTTPS only
    'httponly' => true,    // not accessible via JavaScript
    'samesite' => 'Lax',   // prevent cross-site leakage
]);
ini_set('session.use_strict_mode', '1');
session_start();
```

## What the rule checks

- `session_start()` without prior `session_set_cookie_params()` setting `secure => true` and `httponly => true`
- `ini_set('session.cookie_secure', '0')` or `ini_set('session.cookie_httponly', '0')`
- `session.use_trans_sid = 1` (session ID in URL)

## When it does not report

- CLI scripts where session cookies don't apply
- Secure cookie params set via `.htaccess` or web server config (not detectable statically)

## How to fix

1. Set `session.cookie_secure = 1` (HTTPS only)
2. Set `session.cookie_httponly = 1` (not accessible via JavaScript)
3. Set `session.cookie_samesite = Lax` or `Strict`
4. Set `session.use_only_cookies = 1` (never put session ID in URLs)
5. Set `session.use_strict_mode = 1` (reject uninitialized session IDs)

## Configuration

E0075 is enabled by default and has no configuration options.
