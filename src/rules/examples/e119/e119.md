# E0119: Session cookie without Secure flag

Session cookies configured without the `Secure` flag can be sent over unencrypted HTTP connections, increasing the risk of interception.

## Why it matters

Without the `Secure` flag on session cookies:
- Session IDs can be exposed through network sniffing
- Attackers on the same network may be able to hijack sessions
- Authentication is more vulnerable to man-in-the-middle attacks

## Bad example

```php
session_set_cookie_params([
    'secure' => false,    // sent over HTTP
    'httponly' => true,
]);
session_start();
```

## Good example

```php
session_set_cookie_params([
    'secure' => true,     // HTTPS only
    'httponly' => true,   // not accessible via JavaScript
    'samesite' => 'Lax',
]);
session_start();
```

## What it checks

- `session_set_cookie_params()` with `secure => false`, or where `secure` is not set
- `ini_set('session.cookie_secure', '0')`, or cases where it is not set
- Session cookies created without the `Secure` attribute

## When it does not report

- Session cookies explicitly marked with `secure => true`
- The rule cannot detect server-level `session.cookie_secure` ini configuration

## How to fix

1. Set `session.cookie_secure = 1` in `php.ini`.
2. Call `session_set_cookie_params(['secure' => true, ...])` before `session_start()`.
3. Serve the application over HTTPS, ideally with HSTS enabled.

## Configuration

E0119 is enabled by default and has no configuration options.
