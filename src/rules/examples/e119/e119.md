# E0119: Session cookie without Secure flag

**In plain English:** The session cookie is set without the `Secure` flag, meaning it can be transmitted over unencrypted HTTP and intercepted by network attackers.

**Why it matters:** Without the `Secure` flag on session cookies:
- Session IDs can be stolen via network sniffing (packet capture)
- Attackers on the same network can hijack user sessions
- Authentication is vulnerable to man-in-the-middle attacks

## Bad

```php
session_set_cookie_params([
    'secure' => false,    // sent over HTTP
    'httponly' => true,
]);
session_start();
```

## Good

```php
session_set_cookie_params([
    'secure' => true,     // HTTPS only
    'httponly' => true,   // not accessible via JavaScript
    'samesite' => 'Lax',
]);
session_start();
```

## What the rule checks

- `session_set_cookie_params()` with `secure => false` or not setting `secure`
- `ini_set('session.cookie_secure', '0')` or not setting it at all
- Session cookies created without the Secure attribute

## When it does not report

- Session cookies explicitly marked `secure => true`
- Cannot detect server-level `session.cookie_secure` ini setting

## How to fix

1. Set `session.cookie_secure = 1` in php.ini
2. Call `session_set_cookie_params(['secure' => true, ...])` before `session_start()`
3. Serve your site over HTTPS only, with HSTS

## Configuration

E0119 is enabled by default and has no configuration options.
