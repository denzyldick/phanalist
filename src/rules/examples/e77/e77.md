# E0077: Path Traversal / LFI

**In plain English:** Your code takes input from a user and uses it to build a file path without sanitizing `../` sequences. An attacker can read files outside your web directory (Local File Inclusion) or include remote files (Remote File Inclusion).

**Why it matters:** LFI/RFI can:
- Read `/etc/passwd`, source code, and credentials
- Include and execute remote PHP code (RFI)
- Expose sensitive configuration files

## Bad

```php
$page = $_GET['page'] ?? '';
include __DIR__ . '/pages/' . $page . '.php';
```

If an attacker sends: `?page=../../../etc/passwd`, your server reads `/etc/passwd`.

## Good

```php
$page = $_GET['page'] ?? '';
$allowed = ['home', 'about', 'contact'];
if (!in_array($page, $allowed, true)) {
    $page = 'home';
}
include __DIR__ . '/pages/' . $page . '.php';
```

## What the rule checks

- `include`, `require`, `include_once`, `require_once` with paths built from tainted input
- `file_get_contents()`, `file()`, `readfile()`, `fopen()` with tainted paths
- `../` or null byte (`%00`) sequences in user-controlled paths

## When it does not report

- Whitelist validation is recognized

## How to fix

1. Use a whitelist of allowed pages/files:
   ```php
   $allowed = ['home', 'about', 'contact'];
   if (!in_array($page, $allowed, true)) {
       $page = 'home';
   }
   ```
2. Use `realpath()` and verify the result starts with the expected directory
3. Strip `../` and null bytes from user input

## Configuration

E0077 is enabled by default and has no configuration options.

LFI/RFI. Classic PHP vulnerability. Very common in CMS themes and plugins.
