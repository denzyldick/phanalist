# E0077: Display errors enabled

**In plain English:** `display_errors` is enabled via `ini_set()` or similar, causing PHP errors to be rendered in the browser and exposing stack traces, file paths, and variable values.

**Why it matters:** Error messages revealed to users can expose:
- File paths and directory structure
- Database structure and SQL queries
- Sensitive variable contents
- A roadmap for attackers

## Bad

```php
ini_set('display_errors', '1');
ini_set('error_reporting', 'E_ALL');
```

## Good

```php
ini_set('display_errors', '0');
ini_set('log_errors', '1');
ini_set('error_log', '/var/log/app_errors.log');
// In production: display_errors = Off, log_errors = On
```

## What the rule checks

- `ini_set('display_errors', '1')` / `ini_set('display_errors', 'true')`
- `error_reporting(E_ALL)` without `display_errors = Off`
- `.htaccess` / `.user.ini` directives enabling `display_errors`

## When it does not report

- Cannot read php.ini or .htaccess from static analysis (only inline `ini_set()`)
- `display_errors = 1` behind `if (getenv('APP_ENV') === 'development')` may still be flagged

## How to fix

1. `display_errors = Off` in production
2. `log_errors = On` with a secure error log path outside the web root
3. Check errors via log files, not browser output

## Configuration

E0077 is enabled by default and has no configuration options.
