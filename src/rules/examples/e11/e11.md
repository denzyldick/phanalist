# E0011: Error suppression operator `@`

The `@` error control operator suppresses PHP errors and warnings. This rule flags its use.

## Why it matters

Suppressing errors hides underlying problems, such as failed file reads, undefined indexes, or connection errors. This makes failures harder to detect and debug, especially when issues only appear in production.

## Bad example

```php
// Suppressing errors when reading a file or calling a risky function.
$content = @file_get_contents($filename);
@$this->connectDatabase();
```

## Good example

```php
// Handle errors explicitly using checks, exceptions, or try/catch.
if (file_exists($filename)) {
    $content = file_get_contents($filename);
} else {
    throw new FileNotFoundException("File not found: $filename");
}

try {
    $this->connectDatabase();
} catch (DatabaseException $e) {
    Log::error("Database connection failed: " . $e->getMessage());
}
```

## What it checks

- Expressions and return statements that use the error control operator (`@`).

## When it does not report

- When no `@` operator is used.

## How to fix

- Remove the `@` operator.
- Add explicit checks (for example, `file_exists()` or `isset()`) or use `try...catch` where appropriate.

## Configuration

E0011 has no configuration options and is enabled by default.
