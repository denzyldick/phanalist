# E0089: `switch()` with Loose Comparison

**In plain English:** PHP's `switch()` statement uses loose comparison (`==`) internally. `switch("0delete") { case 0: }` matches because `"0delete" == 0` is true. An attacker can craft string input that matches an unintended `case` branch through type coercion.

**Why it matters:** An attacker can craft string input that matches an unintended `case` branch through type coercion, executing code they shouldn't have access to.

## Bad

```php
switch ($_GET['action']) { // "0delete" == 0 is true
    case 0:
        deleteAllData();
        break;
    case 1:
        viewData();
        break;
}
```

If an attacker sends `?action=0delete`, PHP converts `"0delete"` to `0`, matching `case 0:`.

## Good

```php
$action = (string)($_GET['action'] ?? '');
switch ($action) {
    case 'delete':
        deleteAllData();
        break;
    case 'view':
        viewData();
        break;
}
```

## What the rule checks

- `switch()` statements where the discriminant is a tainted variable and `case` values are integers or numeric strings

## When it does not report

- `switch((string)$var)` is recognized as safe
- All-string cases (`case 'admin':`) are not flagged

## How to fix

1. Cast switch discriminant to string: `switch((string)$input)`
2. Use `match()` (PHP 8+) which uses strict comparison:
   ```php
   match($input) {
       'delete' => ...,
   }
   ```

## Configuration

E0089 is enabled by default and has no configuration options.
