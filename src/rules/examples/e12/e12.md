# E0012: Service compatibility with shared-memory runtimes

In long-running PHP runtimes such as RoadRunner, Swoole, or FrankenPHP, service instances can remain in memory across multiple requests. This rule checks for service state mutations that can leak data between requests.

## Why it matters

Traditional PHP-FPM typically discards request memory after each request. In long-running worker runtimes, the same service instance may handle many requests. If request-specific data is stored on `$this` or in static properties, that state can leak into later requests, causing data corruption or security issues.

## Bad example

```php
namespace App\Service;

class UserService {
    private string $currentUser;

    public function handleRequest(Request $request): void {
        // Mutating $this state in a long-running worker.
        $this->currentUser = $request->get('user');
        $this->process();
    }
}
```

## Good example

```php
namespace App\Service;

class UserService {
    // Pass request-specific state as method parameters instead of storing it on $this.
    public function handleRequest(Request $request): void {
        $user = $request->get('user');
        $this->process($user);
    }
}
```

## What it checks

- Classes in configured namespaces (by default `App\Service\` and `App\Controller\`).
- Assignments to `$this->property` or static properties such as `self::$prop` inside methods, excluding constructors.
- Classes that implement a configured reset interface (for example, `ResetInterface`) are allowed.

## When it does not report

- Classes outside the configured namespaces.
- Classes that implement a configured reset interface.
- Properties initialized in constructors that are not reassigned during request-handling methods.

## How to fix

- Keep services stateless where possible.
- Pass request-specific data as method parameters instead of storing it in object or static state.
- Make properties immutable or set them only in the constructor when appropriate.
- If state is required, implement a reset interface that clears state between requests.

## Configuration

```yaml
rules:
  E0012:
    include_namespaces:
      - "App\\Service\\"
      - "App\\Controller\\"
    exclude_namespaces: []
    reset_interfaces:
      - "ResetInterface"
```
