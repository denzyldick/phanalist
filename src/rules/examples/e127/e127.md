# E0127: Command execution via system

**In plain English:** User input is passed to `system()`, allowing an attacker to execute arbitrary shell commands on your server.

**Why it matters:** Command injection via `system()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Achieve full server compromise

## Bad

```php
$ip = $_GET['ip'] ?? '';
system("ping -c 4 $ip");
```

An attacker sends: `?ip=8.8.8.8; cat /etc/passwd` and your server executes both commands.

## Good

```php
$ip = $_GET['ip'] ?? '';
if (!filter_var($ip, FILTER_VALIDATE_IP)) {
    http_response_code(400);
    exit;
}
system('ping -c 4 ' . escapeshellarg($ip));
```

## What the rule checks

- `system()`, `exec()`, `shell_exec()`, `passthru()` calls with tainted input
- Backtick operator (`` `$cmd` ``) with tainted input (also covered by E0087)

## When it does not report

- Shell execution with literal commands or validated input
- `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Never pass user input to shell execution functions
2. Validate input strictly (e.g., `FILTER_VALIDATE_IP` for IP addresses)
3. Use `escapeshellarg()` for all user-controlled arguments
4. Prefer PHP-native functions over shell commands

## Configuration

E0127 is enabled by default and has no configuration options.
