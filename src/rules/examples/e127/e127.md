# E0127: CORS `Allow-Origin: *` with Credentials

**In plain English:** `Access-Control-Allow-Origin: *` combined with `Access-Control-Allow-Credentials: true` is invalid and dangerous — it allows any origin to make authenticated requests.

**Why it matters:** This combination bypasses same-origin policy for authenticated requests, allowing any website to make requests with the user's cookies.

## Bad

```php
header("Access-Control-Allow-Origin: *");
header("Access-Control-Allow-Credentials: true");
// Invalid per spec, but browsers may behave unpredictably
```

## Good

```php
$origin = $_SERVER['HTTP_ORIGIN'] ?? '';
$allowed = ['https://app.example.com', 'https://admin.example.com'];
if (in_array($origin, $allowed, true)) {
    header("Access-Control-Allow-Origin: $origin");
    header("Access-Control-Allow-Credentials: true");
}
```

## What the rule checks

- `header("Access-Control-Allow-Origin: *")` combined with `Access-Control-Allow-Credentials: true`
- `Access-Control-Allow-Origin: *` on endpoints handling authenticated requests (`$_SESSION`, `$_COOKIE`)

## When it does not report

- Cannot determine if endpoint uses credentials — flagged conservatively
- Dynamic origin validation (reflecting `Origin` header) is dangerous and may still be flagged

## How to fix

1. Never use `*` with `Allow-Credentials: true`
2. Validate `Origin` against an allowlist and echo it back
3. For public APIs, use `*` without credentials

## Configuration

E0127 is enabled by default and has no configuration options.
