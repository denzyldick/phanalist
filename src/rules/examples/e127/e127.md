# E0127: Command execution via system

Passing untrusted input to `system()` can allow an attacker to execute arbitrary shell commands on the server.

## Why it matters

Command injection through `system()` can:
- Run arbitrary system commands
- Read or modify files and databases
- Install malware or backdoors
- Lead to full server compromise

## Bad example

```php
$ip = $_GET['ip'] ?? '';
system("ping -c 4 $ip");
```

An attacker can send `?ip=8.8.8.8; cat /etc/passwd`, causing the server to execute both commands.

## Good example

```php
$ip = $_GET['ip'] ?? '';
if (!filter_var($ip, FILTER_VALIDATE_IP)) {
    http_response_code(400);
    exit;
}
system('ping -c 4 ' . escapeshellarg($ip));
```

## What it checks

- `system()`, `exec()`, `shell_exec()`, `passthru()` calls with tainted input
- Backtick operator (`` `$cmd` ``) with tainted input (also covered by E0087)

## When it does not report

- Shell execution with literal commands or validated input
- Cases where `escapeshellarg()` / `escapeshellcmd()` sanitization is recognized

## How to fix

1. Do not pass user input to shell execution functions.
2. Validate input strictly (for example, `FILTER_VALIDATE_IP` for IP addresses).
3. Use `escapeshellarg()` for all user-controlled arguments.
4. Prefer PHP-native functions over shell commands when possible.

## Configuration

E0127 is enabled by default and has no configuration options.
