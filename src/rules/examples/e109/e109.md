# E0109: Directory Listing Exposure

Using `opendir()`, `readdir()`, `scandir()`, or `glob()` on a user-controlled directory path can allow an attacker to list files in arbitrary directories on your server.

## Why it matters

Directory listing exposure can:

- Reveal file names and directory structure
- Expose backup files, configuration files, or source code
- Help attackers plan further attacks

## Bad example

```php
$dir = $_GET['dir'] ?? '';
$files = scandir($dir);
// ?dir=../../../etc/ or ?dir=../../../var/www/config/
```

## Good example

```php
$dir = $_GET['dir'] ?? '';
$allowedDirs = ['/var/www/uploads/', '/var/www/assets/'];
$realDir = realpath($dir);
if (!$realDir || !in_array($realDir, $allowedDirs, true)) {
    http_response_code(400);
    exit;
}
$files = scandir($realDir);
```

## What it checks

- `opendir()`, `readdir()`, `scandir()`, and `glob()` with user-controlled directory paths
- Directory traversal patterns (`../`) in directory arguments

## When it does not report

- Allowlist validation of directory paths is recognized
- `realpath()` verification that the resolved path is within allowed directories is recognized

## How to fix

1. Never list directories based on user input.
2. Use an allowlist of permitted directories.
3. Use `realpath()` and verify the resolved path is within the expected directory.
4. Disable directory listing in your web server configuration.

## Configuration

E0109 is enabled by default and has no configuration options.

## Taint engine

This rule is backed by the phanalist taint engine. Instead of guessing whether a variable contains user input, the engine tracks taint from sources to sinks.

- **`TaintMode::Only`** (default): Reports only when a proven taint flow from a source (for example `$_GET`, `$_POST`, superglobals, or request parameters) reaches the sink.
- **`TaintMode::Annotate`**: Reports all findings and adds the proven source origin.
- **`TaintMode::Off`**: Retains legacy heuristic behavior through `taint_support::looks_dynamic` for compatibility.

Every finding carries structured metadata (severity, category, confidence, effort, CWE/OWASP references, fingerprint) and a stable content-based fingerprint independent of line numbers.
