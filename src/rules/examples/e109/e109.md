# E0109: Directory listing exposure

**In plain English:** `opendir()`, `readdir()`, or `scandir()` is used on a user-controlled directory path, allowing an attacker to list files in arbitrary directories on your server.

**Why it matters:** Directory listing exposure can:
- Reveal file names and directory structure
- Expose backup files, configuration files, or source code
- Help attackers plan further attacks

## Bad

```php
$dir = $_GET['dir'] ?? '';
$files = scandir($dir);
// ?dir=../../../etc/ or ?dir=../../../var/www/config/
```

## Good

```php
$dir = $_GET['dir'] ?? '';
$allowedDirs = ['/var/www/uploads/', '/var/www/assets/'];
$realDir = realpath($dir);
if (!$realDir || !in_array($realDir, $allowedDirs, true)) {
    http_response_code(400);
    exit;
}
$files = scandir($realDir);
```

## What the rule checks

- `opendir()`, `readdir()`, `scandir()`, `glob()` with user-controlled directory paths
- Directory traversal patterns (`../`) in directory arguments

## When it does not report

- Whitelist validation of directory paths
- `realpath()` verification that the resolved path is within allowed directories

## How to fix

1. Never list directories based on user input
2. Use a whitelist of allowed directories
3. Use `realpath()` and verify the resolved path is within the expected directory
4. Disable directory listing in your web server configuration

## Configuration

E0109 is enabled by default and has no configuration options.
