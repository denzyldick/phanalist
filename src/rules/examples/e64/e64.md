# E0064: XPath Injection

**In plain English:** Your code takes input from a user and inserts it into an XPath query without escaping. XPath is used to query XML documents. An attacker can craft input that changes what the XPath query returns—bypassing authentication or extracting XML data.

**Why it matters:** XPath injection affects applications using XML data stores or SimpleXML/XPath for configuration. It can:
- Bypass XML-based authentication
- Extract data from XML files
- Read sensitive configuration data

## Bad

```php
$user = $_GET['user'] ?? '';
$query = "//user[login='$user']";
$result = $xpath->query($query);
```

If an attacker sends: `?user=' or '1'='1`, the XPath becomes:
```
//user[login='' or '1'='1']
```
This returns **all** user elements instead of just one.

## Good

```php
$user = $_GET['user'] ?? '';
$escaped = str_replace("'", "\\'", $user);
$query = "//user[login='$escaped']";
$result = $xpath->query($query);
```

Escaping single quotes prevents the attacker from breaking out of the string literal.

## What the rule checks

- `DOMXPath::query()`, `DOMXPath::evaluate()`, `SimpleXMLElement::xpath()` with tainted string concatenation in the XPath expression

## When it does not report

- XPath 2.0 parameter binding (using variables instead of string concatenation)
- Manual quote escaping (may still be flagged conservatively)

## How to fix

1. Escape single quotes in user input before interpolating into XPath: `str_replace("'", "\\'", $input)`
2. Use parameterized XPath queries where supported

## Configuration

E0064 is enabled by default and has no configuration options.

Niche but serious in XML-heavy PHP applications. Good for showing that injection isn't just about SQL—any query language can be attacked.
