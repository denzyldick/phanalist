# E0120: Eval with user-controlled string

**In plain English:** `eval()` is called with a string that contains user-controlled input, allowing an attacker to execute arbitrary PHP code on your server.

**Why it matters:** `eval()` with user input is one of the most dangerous PHP vulnerabilities:
- Attacker can execute arbitrary system commands
- Full server compromise is possible
- All data on the server can be read, modified, or deleted

## Bad

```php
$code = $_GET['code'] ?? '';
eval("return $code;");
```

An attacker sends: `?code=system('id');` and your server runs it.

## Good

```php
// Never eval user input. Use a whitelist-based dispatch instead.
$action = $_GET['action'] ?? '';
$allowed = ['list', 'view', 'search'];
if (!in_array($action, $allowed, true)) {
    http_response_code(400);
    exit;
}
// Handle each allowed action explicitly
switch ($action) {
    case 'list':
        listItems();
        break;
}
```

## What the rule checks

- `eval()` calls where the string argument contains tainted input
- String concatenation inside `eval()` with user-controlled variables

## When it does not report

- `eval()` on literal strings with no user input
- Cannot detect dynamic code construction that bypasses taint tracking

## How to fix

1. Never pass user input to `eval()`
2. Replace dynamic code execution with whitelist-based dispatch
3. Use a command/action pattern instead of evaluating strings

## Configuration

E0120 is enabled by default and has no configuration options.
