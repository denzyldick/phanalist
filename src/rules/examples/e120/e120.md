# E0120: Eval with user-controlled string

**In plain English:** `auto_prepend_file` and `auto_append_file` automatically include files on every request. If these point to attacker-writable locations, code execution is possible.

**Why it matters:** These directives can be abused to include malicious files on every PHP request.

## Bad

```php
// php.ini or .htaccess:
php_value auto_prepend_file /tmp/evil.php
php_value auto_append_file /tmp/evil.php
```

## Good

```php
// Leave unset, or point to trusted application files only
// php_value auto_prepend_file /var/www/app/bootstrap.php
```

## What the rule checks

- Cannot read php.ini/.htaccess directly — only documents the risk
- Cannot detect inline usage (these are INI_PERDIR/PHP_INI_SYSTEM settings)

## When it does not report

- Purely informational — cannot be detected via static analysis of PHP code
- Requires scanning server configuration files

## How to fix

1. Leave `auto_prepend_file` / `auto_append_file` unset unless needed
2. If needed, point to trusted, non-writable application files
3. Audit `.htaccess` and `.user.ini` files for these directives

## Configuration

E0120 is enabled by default and has no configuration options.

Server configuration. Requires .htaccess/php.ini auditing alongside code analysis.
